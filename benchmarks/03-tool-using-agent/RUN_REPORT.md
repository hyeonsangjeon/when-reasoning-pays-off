### Pre-existing benchmark-01 analyzer drift (not caused by Task 010)

Re-running the current `scripts/analyze_tokens.py` over benchmark-01's committed
fixture cohort does **not** reproduce the committed
`benchmarks/01-short-factual/analysis.json` byte-for-byte. This drift is
**pre-existing from `main` and is not introduced by Task 010**:

- **Root cause — Task 009, not Task 010.** Task 009's reasoning-token
  double-count fix changed `scripts/cost_calculator.py` (reasoning tokens are a
  labelled subset of `output_tokens` under Azure's Responses-API contract —
  `total_tokens == input_tokens + output_tokens` — and are billed at the output
  rate, never as a separate line) and `scripts/analyze_tokens.py`
  (`tokens_per_request = input + output`, no longer `+ reasoning`), and expanded
  `CANONICAL_EFFORT_ORDER` to include the production `none` tier. Task 009
  regenerated benchmark-02 with the corrected pipeline but **did not regenerate
  benchmark-01's committed `analysis.json`**, which still carries the
  pre-Task-009 provenance (`git_commits == ["FIXTURE-008-synth-1"]`).
- **Drift is confined to the Task-009-affected fields.** The only differing
  fields are `mean_usd_per_request`, `std_usd_per_request`, `tokens_per_request`,
  `throughput_gain_factor`, plus one added empty `gpt-5.2 / effort=none` cell
  row. **No Task-010-added field differs** — the `tool_efficiency_breakdown`
  block is correctly gated off (benchmark-01 judge JSONs carry no
  `tool_efficiency_score`). `main`'s `analyze_tokens.py` and this branch's
  `analyze_tokens.py` produce byte-identical output to each other over the same
  benchmark-01 input; both differ from the committed file only in those Task-009
  fields. That is the additive-and-gated proof.
- **Why a naive regeneration is wrong (and deferred).** Benchmark-01's
  `exp008_short-factual_fixture` cohort is non-canonical w.r.t. Azure's usage
  contract: `reasoning_tokens` is recorded **outside** `output_tokens` (e.g.
  `sf_01` high: `output_tokens=16`, `reasoning_tokens=151`,
  `total_tokens=236=input+output`). Re-running the corrected analyzer over that
  data drops the reasoning subset from the cost/throughput formulas and yields a
  **flat** ~$0.0006/req curve that understates reasoning spend — contradicting
  the benchmark's escalating-cost finding. A faithful refresh must first
  re-synthesize the exp008 fixtures canonically (`reasoning ⊆ output`,
  `total = input + output`) and then re-run the analyzer, plotter, and
  `analysis.md`. That is a dedicated benchmark-01 refresh, **out of Task 010's
  additive scope**, and is tracked as a follow-up. Benchmark-01's committed
  `analysis.json` / `analysis.md` / charts are therefore left untouched by this
  task and remain mutually consistent (the cross-benchmark synthesis cites them
  as the current source of truth).

## Reproduce locally

```bash
# 0. Set up env:
export AZURE_OPENAI_FOUNDRY_ENDPOINT=https://<your-foundry-resource>.services.ai.azure.com/api/projects/<your-project>
export AZURE_OPENAI_DEPLOYMENT_GPT_5_2=gpt-5.2
export AZURE_OPENAI_DEPLOYMENT_GPT_4O=gpt-4o
export AZURE_AUTH_MODE=entra
az login

# 1. Smoke (~$0.01 actual; $0.50 ceiling per YAML):
python -m scripts.run_benchmark --experiment experiments/exp_smoke_03_gpt4o.yaml
python -m scripts.run_benchmark --experiment experiments/exp_smoke_03.yaml

# 2. Full measurement (~$1.11 actual; $33 budget / $45 hard ceiling):
python -m scripts.run_benchmark --experiment experiments/exp003_benchmark03_gpt4o.yaml
python -m scripts.run_benchmark --experiment experiments/exp003_benchmark03_gpt5_2.yaml \
    --skip-existing   # idempotent resume on retry

# 3. Judge pass (~$0.40 actual; tool-aware prompt fires automatically):
python -m scripts.run_judge \
    --benchmark 03-tool-using-agent \
    --experiment-prefix exp003 --confirm --concurrency 5

# 4. Analyze + plot:
python -m scripts.analyze_tokens --benchmark 03-tool-using-agent --experiment-prefix exp003
python -m scripts.plot_results --benchmark 03-tool-using-agent
```
