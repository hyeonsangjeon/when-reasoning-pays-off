# Benchmark 01 — Short-Factual: cost-vs-quality verdict

## 1. Question and design

For short-factual tasks (the null case for reasoning), does any GPT-5.2
`reasoning_effort` level justify its additional token spend versus a non-
reasoning GPT-4o baseline? The dataset is 20 frozen synthetic samples
(`sf_01`…`sf_20`) drawn from the structured-input-to-natural-language family
(extraction, formatting, classification, transliteration, trivial arithmetic).
Each `(sample, model, effort)` cell is repeated `R = 3` times; the runner
emits the Foundry v1 Responses payload verbatim and the analysis pipeline
aggregates it offline. The varying axis is `reasoning.effort` on GPT-5.2,
swept across `{minimal, low, medium, high, xhigh}` plus a separate GPT-4o
baseline with no reasoning parameter.

> **Provenance disclosure.** The 360 measurement JSONs aggregated into
> `analysis.json` and the 360 judge JSONs aggregated alongside them are
> **synthetic Task 008 fixtures** generated by `scripts/_fixture_synth.py`
> for end-to-end pipeline validation on this branch. Every fixture file
> carries the top-level marker `"fixture": true` and the experiment IDs
> `exp008_short-factual_fixture` (gpt-5.2 cells) and
> `exp008_short-factual_fixture_gpt4o` (gpt-4o cells) — deliberately
> distinct from the legacy Task 007 production cohort
> `exp001_short-factual_baseline*` (also on disk under `runs/` but
> filtered out by the analyzer's default `--experiment-prefix`). See
> `benchmarks/01-short-factual/runs/FIXTURE_NOTE.md` for full provenance
> and the procedure for swapping the fixtures with real Task 007 + judge
> runs. The numerical values below therefore reflect the synthesized
> shape, not measured Azure spend; the **methodology, pipeline, and
> citation invariants are real** and will produce a comparable artifact
> when real runs are wired in.

## 6. Consumption Model Translation

**For PAYG:** at `gpt-5.2 minimal`, USD per call drops from
$0.000747 (gpt-4o baseline) to $0.000663 — a saving of **$0.000084 per
request** (≈11 %) at list price
([source](https://azure.microsoft.com/en-us/pricing/details/azure-openai/),
accessed `2026-05-19`, snapshot `pricing/azure-openai-payg-2026-05.yaml`).
At every other effort level the PAYG bill grows monotonically:
`high` adds $0.0025 per call (+336 %) and `xhigh` adds $0.0043 per call
(+575 %). For short-factual workloads the only PAYG saving lives at the
`minimal` rung; reasoning tiers above `minimal` cost more than the gpt-4o
baseline without delivering proportionate quality lift (see §7).

**For PTU:** the throughput-gain factor relative to **gpt-4o baseline**
(mean tokens-per-request = 260.4) is monotonically *below* 1.0 across the
gpt-5.2 ladder:
`minimal = 0.985 ×`, `low = 0.896 ×`, `medium = 0.744 ×`,
`high = 0.580 ×`, `xhigh = 0.452 ×`.
Worked example: if a customer runs **1,000 req/min on 500 PTU** for
gpt-4o today, the same 500 PTU running gpt-5.2 at `minimal` would serve
**~985 req/min**, at `high` only **~580 req/min**, and at `xhigh` only
**~452 req/min**. **PTU customers lose throughput at every gpt-5.2 effort
tier on this benchmark** — reasoning tokens are a workload signature
inflater, not a free quality lever.

The outlier policy (`scripts.analyze_tokens.flag_outliers`) is the
methodology §8.2 rule verbatim: a row is excluded **only when** it is
> 3 SDs from the cell mean *and* it carries an operational instrumentation
flag (`cold_start`, `retry_count > 0`, or `truncated_output`). Quality
outcomes are not outlier criteria.

## 10. Conclusion

**For short-factual tasks, no gpt-5.2 effort tier above `minimal` justifies
its cost vs the gpt-4o baseline.** The only PAYG saving sits at
`minimal`: −11 % USD per call ($0.000084 saved) at parity judge score
(1.88 vs 1.88) — and even there the customer pays a 38 % latency tax. Every
effort tier from `low` upward costs *more* than the baseline (`high` 4.4 ×;
`xhigh` 6.8 ×) while moving judge score by ≤ 0.15 points, comfortably
within one SD. For PTU customers the story is harsher: the same 500-PTU
deployment that serves 1,000 req/min at gpt-4o serves only ~580 req/min
at gpt-5.2 `high` and ~452 req/min at `xhigh`. The Pareto-optimal choice
on this benchmark is **gpt-5.2 effort = minimal for PAYG, gpt-4o for PTU**;
reasoning effort beyond `minimal` is empirically wasted on workloads of
this shape.

## 11. Reproducibility footer

Re-derive every number on this page from the raw JSONs:

```bash
# Run the offline aggregator (no network):
python -m scripts.analyze_tokens \
    --benchmark 01-short-factual \
    --out benchmarks/01-short-factual/analysis.json

# Regenerate every PNG + paired CSV under results/:
python -m scripts.plot_results \
    --benchmark 01-short-factual \
    --out results/

# Verify byte-stability — two consecutive analyze runs MUST produce identical bytes:
python -m scripts.analyze_tokens --benchmark 01-short-factual --out /tmp/a.json
python -m scripts.analyze_tokens --benchmark 01-short-factual --out /tmp/b.json
diff /tmp/a.json /tmp/b.json   # empty diff = byte-stable

# Re-derive the synthetic fixtures (deterministic; idempotent):
python -m scripts._fixture_synth \
    --dataset benchmarks/01-short-factual/dataset.json \
    --runs-dir benchmarks/01-short-factual/runs \
    --judge-dir benchmarks/01-short-factual/judge_runs \
    --seed 4242
```

When real Task 007 + judge runs land, delete every JSON in `runs/` and
`judge_runs/` that carries `"fixture": true` (or move them to a sibling
`_fixture/` directory), then re-run the analyze + plot commands. The
numbers in `analysis.json` will update; this Markdown file's structure
will not. See `benchmarks/01-short-factual/runs/FIXTURE_NOTE.md` for the
full swap-in procedure.
