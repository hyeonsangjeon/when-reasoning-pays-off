exp002 — Did reasoning effort pay off in multi-step reasoning?

By Hyeonsang Jeon · Global Black Belt, Cloud & AI Apps

This experiment was reasoning's turn to win. Twenty problems that answer only after at least two steps — the kind of place where every notch up in reasoning effort (reasoning_effort) feels like it should make the answer safer.

That is what we pre-registered. gpt-4o would miss more than half (30–60% pass), and gpt-5.2 would clear 80% only by raising effort. The measurement missed both predictions. gpt-5.2 already scored full marks at the lowest effort, and gpt-4o did far better than expected.

This note retraces that day as design → inputs → artifacts → prediction vs. measurement → outliers → decision. Not just the numbers, but the road they came from and how to read them — so the next person wanders less on the same road.

Design

It was reasoning's turn to win

One question. On multi-step reasoning — the ceiling case for reasoning — how far do you have to raise gpt-5.2's effort before reasoning is worth the bill? We look through two lenses at once: PAYG (dollars per correct answer) and PTU (correct answers per minute per fixed capacity).

Dataset. Twenty frozen synthetic samples (mr_01…mr_20). Arithmetic word problems, constraint satisfaction, date/time, causal chains, code tracing, boolean logic, counting — spanning seven types, and every sample has a verifiable answer and requires at least two steps of reasoning.

Exactly one axis moves — we sweep gpt-5.2's reasoning.effort across none · low · medium · high · xhigh, and set a gpt-4o baseline (which has no reasoning parameter) alongside it. Each (sample × model × effort) cell is repeated three times (R=3).

Pre-registered prediction

The multi-step shape overturns the short-answer benchmark's conclusion. gpt-4o passes only 30–60%, and gpt-5.2 passes 80% or more at sufficient effort, so reasoning pays.

This experiment's role

Paired with the short-answer benchmark's floor (a place that needs no reasoning), the anchor that fixes the ceiling of the cost surface where “reasoning is worth the bill.”

Prediction vs. measurement

The prediction missed twice

What we predicted

gpt-4o breaks down at 30–60%. gpt-5.2 clears 80% only by raising effort. In short: “higher effort buys quality and justifies the cost.”

What came out

gpt-4o was stronger than expected at 75% (45/60). gpt-5.2 was already 100% at the lowest none (60/60). By mean rating score, gpt-4o 1.50 vs. gpt-5.2 2.00.

Verdict: hypothesis refuted. The pre-registration that “in multi-step, higher effort pays” was refuted as stated. The real decider was not the effort dial but the gpt-4o → gpt-5.2 model swap, because gpt-5.2's default reasoning setting (none) was already enough.

First reversal

Swap the model and quality rose while cost fell

The dollars in the table below apply the methodology's PAYG formula to the price snapshot pricing/azure-openai-payg-2026-05.yaml (accessed 2026-05-19); they are re-cited from analysis.md §5.

Model     Effort   Per 1,000 req   Pass rate       Per 1,000 correct
gpt-4o    —        $0.80           75.0% (45/60)   $1.06   ← baseline
gpt-5.2   none     $0.62           100%  (60/60)   $0.62   ← Pareto-optimal
gpt-5.2   low      $0.86           96.7% (58/60)   $0.89
gpt-5.2   medium   $1.08           100%  (60/60)   $1.08
gpt-5.2   high     $1.25           100%  (60/60)   $1.25
gpt-5.2   xhigh    $2.18           100%  (60/60)   $2.18

This table is on the same scale (per 1,000) as the narrative essay. Swap the model and quality rose while cost actually fell — per 1,000 correct, none at $0.62 is 42% cheaper than gpt-4o ($1.06).

low costs 7.6% more per request, but its higher pass rate (96.7% vs. 75%) repays that premium, making it 16% cheaper than gpt-4o per 1,000 correct. The first optimization was not to raise effort but to treat model and effort as one combination and find the cheapest point that clears quality.

Second reversal

Higher effort bought the same quality more expensively

gpt-5.2's none and xhigh are both full marks (mean 2.00, 100% pass rate). Yet the cost per 1,000 correct rises from the none floor ($0.62) to 1.75× at medium, 2.02× at high, and 3.53× at xhigh ($2.18).

Latency tells the same story. none is about 1.6 seconds per call (1,589ms), xhigh about 3.3 seconds (3,265ms). Against gpt-4o (1,382ms), none's latency tax is only about 15%, but xhigh is 2.4×. Higher effort in this band did not buy a better answer — it bought the same answer more expensively and more slowly.

Break down the tokens and the reason is clear. The visible answer is about 5.8 tokens at none and about 7.7 at xhigh — barely two tokens more. Yet the hidden reasoning tokens swell from 0 to about 109.5, and at xhigh reasoning alone accounts for about 26% of the request size. Quality stays the same while only the billed tokens balloon.

This does not mean reasoning tokens are useless. Reasoning pays when there is structure to solve. It's just that this task band already touched the top of the rubric at the lowest combination, and when there is no room for quality to rise, raising effort makes the extra tokens closer to overspend than investment.

The PTU lens reaches the same conclusion. gpt-5.2 none is 0.994× gpt-4o's throughput × 100% pass, so on fixed PTU spend it delivers +32.5% correct answers per minute (gpt-4o is 75%). Raising effort only trims throughput with no quality reward.

Quality map

Where did gpt-4o break down

The single number 75% doesn't show “where.” Split by type, gpt-4o's failures cluster in particular places.

  • Where it missed most: arithmetic word problems (mean 1.20), date/time (1.00), code tracing (1.33), constraint satisfaction (1.33) — the types that need re-computation or backward tracing.
  • Where it got them all: counting, boolean logic, causal chains (2.00 each) — the types where a single forward pass suffices.
  • gpt-5.2 is full marks across every type (2.00). The only exception is the one mr_05 safety-filter refusal cell noted earlier.

In other words, for gpt-4o this dataset draws a map of “pass when the chain is short and forward, fail when it needs re-tracing.” gpt-5.2 flattened that map entirely.

Transparency

Even the smudges left on the numbers, as they are

No measurement is perfectly clean. We write down the marks this benchmark left without erasing them — because hidden away, they'd trip the next person at the same spot.

  • gpt-4o was easier than expected. 75% exceeded the pre-registered 30–60%. It means the dataset was less harsh on gpt-4o to begin with. So the size of the “savings vs. gpt-4o” came out smaller than it would have on a harder dataset (expected 1.7–3.3× gap → realized 1.7×). Rather than erasing where the prediction missed to fit the numbers, we leave the shrunken savings as they are. The direction of the conclusion (gpt-5.2 none Pareto-dominates) is unchanged.
  • One safety-filter refusal. On mr_05's first low repetition, the Azure content filter returned 0 input·output tokens and a structured refusal. This cell has no operational flag (cold start/retry/truncation), so it is not caught by the outlier rule, and per the append-only principle it is left in the aggregate without overwrite (the judge scored it exactly 0/fail). Other repetitions of the same problem answered correctly — a one-off, not a systematic trip, and this single cell is what widened the low row's variance.
  • Zero partial scores. Across all 360 cells, the judge's score == 1 never occurred once. With a verifiable-answer design, there is no middle ground between “produced 672” and “produced 576.” So the binarization choice doesn't shake the headline.

Limits

How far can you trust this

These results are small-sample aggregates from one multi-step task set, one price snapshot, and a particular model-and-rubric combination. It is safer to take the method than the numbers themselves.

  • Sample. N=20 · R=3. At this sample size we claim no confidence intervals or statistical significance — the directional conclusion is robust, but treat absolute magnitudes with small-sample caution.
  • Price. A single snapshot. If rates or the usage schema change, cost must be recomputed from the same raw data.
  • Grading. LLM-as-judge (gpt-4o). We record the judge prompt's SHA-256 in the grading JSON to watch for drift.
  • Fallout from exceeding pre-registration. Because gpt-4o's denominator (0.75) was larger than expected (0.30–0.60), the dollar savings shrank. So in this experiment the PTU throughput lens, which is insensitive to gpt-4o's pass rate, is the more robust view.

So what becomes the default

The default for multi-step reasoning is gpt-5.2 effort=none — in both PAYG and PTU. none is both the floor and the optimum, and any effort above it only adds cost and latency without quality. Higher effort is merely a candidate to promote in experiments “only when it actually buys additional quality,” not the default for this task shape.
