实验笔记 · exp002 · 多步推理(Ceiling case) · 叙事连载 ① 的证据页

exp002 — 多步推理中推理强度是否值得

作者 Hyeonsang Jeon · Global Black Belt, Cloud & AI Apps

这个实验本该轮到推理获胜。二十个问题都至少要走两步才有答案 — 这种场景里，推理强度(reasoning_effort)像一个旋钮。它决定模型回答前在心里多想多久。看起来每提高一档，答案就该更稳。

我们也这样预先登记了。gpt-4o 会错掉一半多(30–60% 通过)。gpt-5.2 要提高强度才会超过 80%。实测把两个预测都推翻了。gpt-5.2 在最低强度已经满分，gpt-4o 也远比预期更好。

本文按设计 → 输入 → 产物 → 预测对实测 → 异常值 → 决定回看那一天。这里不只放数字。也说明数字从哪里来、该怎么读。希望后来的人少在同一路上绕弯。

为什么值得读

难题就该让模型多想吗？

上一篇(01)里，推理强度旋钮空转了。但那是在最容易的任务上。问题如果要走好几步才能解出 — 要先拿住一个中间值，再往前走一步 — 故事好像就该不一样。到了这里，每提高一档，答案难道不会更稳吗？

这个期待很合理。所以这一次，我们挑了一个推理本该赢的位置，继续测试同一个旋钮。那些至少要两步才有答案的问题 — 带计算的文字题、同时守住多个条件、日期计算。我们就在这里钉住一句老话：“难的工作就要多想”，到底值不值账单。

如果你的服务处理的是一次答不完的问题 — 组合条件、串起中间值、跟着逻辑往下走 — 这就是你的场景。该不该调高旋钮，还是有更便宜、更快的路？我们的预测两次落空，正好替你回答这个问题。

设计

本该轮到推理获胜

为什么这次要测难的一端。 在 01 里，最容易的任务已经给过答案：让模型多想，答案并没有变好。于是疑问也来了：推理强度这个旋钮，难道只是永远更贵的装饰？不能这么下结论。很多问题确实不能一步答完，必须先拿住中间结果，再往前推一步。于是这次我们转到难的一端，也就是“什么时候该调高旋钮”真正要做决定的地方。

所以我们把可证伪的假设写清楚。 这句话是：在至少需要两步的问题上，提高推理强度会带来足够多的准确率提升，足以抵回它的成本。 同时，没有推理设置的基线模型会在这里撞上过不去的天花板。它也有清楚的破线：如果强度提高后准确率仍然不动，或者基线模型一路跟到最后，假设当场失效；反过来，如果准确率随强度明显上升，而基线模型卡在一堵墙前，假设就站得住。这个实验就是为了用实测来判定，而不是靠猜。

这篇在系列里负责钉住天花板。 01 已经用实测钉住了“底部”——推理不值回成本的位置；这篇笔记要钉住相反的一端，也就是推理最该值回成本的“天花板”。只有底部和天花板都站稳，后面的工具笔记 03 才能被放到两者之间看。所以在这个系列里，这一篇轮到推理赢一次。

要验证的问题收敛为一个。 这是至少要走两步才有答案的问题。在三个基准里，这里最像推理能值回票价的天花板案例。给 gpt-5.2 更多思考余地(推理强度)，答案会不会更好？账单值不值？要确认的只有两件事。强度提高时，(1) 质量会不会上升，(2) 成本会不会上升。 钱从两个角度读。按量付费的 PAYG 看‘每个正确答案多少钱’。整租容量的 PTU 看‘同样容量下每分钟答对几个’。

用什么来测 — 数据集。 冻结的合成样本 20 个(mr_01…mr_20)。它们均匀覆盖七类问题：算术应用题、约束满足(同时遵守多个条件)、日期/时间、因果链、代码追踪(读出程序的执行顺序)、布尔逻辑、计数。关键是一眼看不出答案。你要先拿到一个中间结果，再走一步。比如把先算出的值再代回条件。这样才到达答案。所以是‘至少两步’。所有样本都有可由机器验证的答案。

只改一件事。 我们把 gpt-5.2 的 reasoning.effort 依次设成 none · low · medium · high · xhigh。旁边放一个 gpt-4o 做基线。它没有推理强度设置。每个(样本 × 模型 × 强度)单元重复三次(R=3)。

预先登记预测

多步问题会推翻短事实基准的结论。gpt-4o 只会通过 30–60%。gpt-5.2 会在足够强度下通过 80% 以上。所以推理会值得。

本实验的作用

它和短事实基准的底部(不需要推理的位置)配成一组。它用来固定成本曲面的天花板，也就是“推理值回账单”的位置。

吃进什么，留下什么

测量表面为 360 个单元(gpt-4o 60 + gpt-5.2 300，五档强度)。作为异常值排除的单元为 0 个。评分由中立评审 gpt-4o 完成，每个单元评一次，360/360 成功(失败 0，重试 0)。评分规则很直接。失败给 0 分，部分通过给 1 分，完全通过给 2 分。所以平均 2.00 表示 60 个全部通过。gpt-4o 的 1.50 是 45 个通过与 15 个失败混合后的平均。所有 JSON 都是真实 Foundry v1 调用，没有一个 "fixture": true 标记(360 行中 159 行 reasoning_tokens > 0)。

预测对实测

预测错了两次

预测了什么

gpt-4o 会在 30–60% 崩掉。gpt-5.2 必须提高强度才会超过 80%。简单说，就是“高强度能买到质量，所以成本合理”。

结果是什么

gpt-4o 比预期更强，达到 75%(45/60)。gpt-5.2 在最低的 none 已经 100%(60/60)。按平均评价分数看，是 gpt-4o 1.50 对 gpt-5.2 2.00。

判定：预测落空了。 我们原以为“多步任务必须提高强度才值得”。这条预测错了两处。gpt-4o 比预期解得更好。gpt-5.2 在还没提高强度之前就已经满分。所以真正的分岔点不是强度旋钮，而是把 gpt-4o 换成 gpt-5.2。gpt-5.2 的默认设置(none，即关闭推理)已经足够。

第一次逆转

换了模型，质量上升，成本下降

下表中的美元数来自同一套算法。我们把方法论里的 PAYG 公式，套到价格快照 pricing/azure-openai-payg-2026-05.yaml(访问日 2026-05-19)上。数值从 analysis.md §5 重新引用。

模型      努力     每1,000次请求    通过率          每1,000个正确答案
gpt-4o    —        $0.80         75.0% (45/60)   $1.06   ← 基线
gpt-5.2   none     $0.62         100%  (60/60)   $0.62   ← 帕累托最优
gpt-5.2   low      $0.86         96.7% (58/60)   $0.89
gpt-5.2   medium   $1.08         100%  (60/60)   $1.08
gpt-5.2   high     $1.25         100%  (60/60)   $1.25
gpt-5.2   xhigh    $2.18         100%  (60/60)   $2.18

这张表和连载正文用的是同一刻度(每 1,000 次)。模型变了，质量提高了，成本反而下降了。 按每 1,000 个正确答案看，none 为 $0.62，比 gpt-4o($1.06)便宜 42%。

low 每请求单价高 7.6%。但通过率也更高(96.7% 对 75%)，足以抵掉这部分加价。按每 1,000 个正确答案看，它仍比 gpt-4o 便宜 16%。所以第一步优化不是提高强度。而是把模型与强度看成一个组合，找出通过质量门槛后最便宜的点。

第二次逆转

更高强度用更高价格买到相同质量

这里出现第二个事实。gpt-5.2 的 none 和 xhigh 质量完全相同 — 都是满分(平均 2.00，通过率 100%)。但每 1,000 个正确答案成本从 none($0.62)这个底点往上走。到 medium 是 1.75倍，到 high 是 2.02倍，到 xhigh 是 3.53倍($2.18)。这等于把同一个答案越买越贵。

等待时间也是同一个故事。 none 每次调用约 1.6 秒(1,589ms)，xhigh 约 3.3 秒(3,265ms)。相对 gpt-4o(1,382ms)，none 只慢约 15%，但 xhigh 是 2.4倍。在这个区间，高强度没有买到更好的答案。它只买到同一个答案，价格更高、速度更慢。

拆开 token 后原因更清楚。 同一道菜端上桌，如果厨房里备料更久，成本就更高。答案也是这样。屏幕上看到的答案相同，但模型在内部算得更多，账单就会变大。可见答案从 none 约 5.8 token 到 xhigh 约 7.7 token — 只多了两三个 token。但隐藏推理 token 从 0 膨胀到约 109.5。在 xhigh 时，仅推理就占请求大小约 26%。质量不变，只有被计费的 token 膨胀。

这个结果并不意味着推理 token 没用。只有在还有步骤要走时 — 比如做复杂规划或在工具间做选择 — 推理才值得。 只是这个任务集在最低设置就已经拿到评分标准的满分。没有可再涨的分数了。已经顶到天花板时，再提高强度所多烧的推理 token 就成了浪费，而非投资。一句话，强度旋钮是‘只在质量还有上升空间时’才拧的开关。

从 PTU 看，结论也相同。 gpt-5.2 none 是 gpt-4o 的 0.994倍吞吐，并且 100% 通过。所以在固定 PTU 支出下，每分钟正确答案多 +32.5%(gpt-4o 为 75%)。提高强度只会削低吞吐，质量不会变好。

质量地图

gpt-4o 在哪里倒下

gpt-4o 的 75% 这个总数，看不出它到底“在哪里”错。于是我们按任务类型把分数拆开。失败集中在一个地方：需要回头计算或反向追踪的类型。

  • 错得多的地方： 算术应用题(平均 1.20)、日期/时间(1.00)、代码追踪(1.33)、约束满足(1.33) — 都是需要回头计算或反向追踪的类型。
  • 全答对的地方： 计数、布尔逻辑、因果链(各 2.00) — 从前往后读一遍就够的类型。
  • gpt-5.2 除 low 外在所有强度的所有类型都满分(2.00)。只有 low 有两个 0 分单元 — mr_05(约束满足)是安全过滤拒绝，mr_15(代码追踪)是错误答案 “cba a”(正确为 “cbaa”)。所以在 low，这两个类型各为 1.78(±0.67)。

换句话说，这个数据集为 gpt-4o 画出了一张地图。链条短、只往前走就通过。需要回头检查就失败。gpt-5.2 把这张地图整个抹平了 — 哪里都答对。

透明度

连数字上的污点也原样留下

任何测量都不可能完全干净。这个基准留下的痕迹，我们不擦掉，而是原样写下。因为藏起来，后来的人会在同一个地方踩空。

  • gpt-4o 比预期更容易过。 75% 超过了预先登记的 30–60%。这说明数据集一开始就没有那么为难 gpt-4o。所以“相对 gpt-4o 的节省幅度”的大小比更难数据集时更小(预期 1.7–3.3倍差距 → 实现 1.7倍)。我们不把预测错掉的地方擦掉来配合数字。缩小的节省幅度也原样留下。结论的方向(gpt-5.2 none 在成本和质量上都更好)不变。
  • 安全过滤拒绝 1 个。 mr_05 的 low 第一次重复中，Azure 内容过滤器挡住了请求。输入·输出 token 都是 0，并返回了固定格式的拒绝。这个单元没有运营标记(冷启动/重试/截断)，所以不是该删掉的异常值。我们没有覆盖它，而是原样留在聚合中(评审准确评分为 0/失败)。同一问题其他重复都正常正确。它不是反复出现的问题，只发生了这一次。这个单元让 low 行的输入 token 方差变大。
  • 代码追踪错误 1 个。 mr_15 的 low 第三次重复(r2)把 g("abc") 的输出返回为 “cba a” — 正确答案是 “cbaa”(反转的 “cba” 加上首字符 “a”)。评审评分为 0/失败。这是纯推理错误，和安全过滤无关。这个单元和 mr_05 拒绝，是把 low 通过率变成 96.7%(58/60)的两次失败。
  • 部分分 0 个。 360 个单元里没有一个评审 score == 1。这些答案本来就是可验证的。“给出 672”和“给出 576”之间没有中间态。所以只按通过/失败来看，核心结论也不变。

限制

可以相信到哪里

这个结果来自一个多步任务集、一个价格快照、特定模型组合和评分设置。样本也不大。所以比起直接拿走数字，借鉴方法更稳妥。

  • 样本。 N=20 · R=3。这个样本量下，我们不主张置信区间或统计显著性。方向性结论稳健，但绝对幅度要按小样本谨慎看待。
  • 价格。 只用了一张价格快照。如果费率或计费方式改变，应从同一原始材料重新计算成本。
  • 评分。 评分由评审模型(gpt-4o)完成。评审提示的 SHA-256 记录在评分 JSON 中，以后能看出是否变过。
  • 超出预先登记的影响。 gpt-4o 通过率(0.75)比预期(0.30–0.60)更高，美元节省幅度因此缩小。所以在这个实验中，PTU 吞吐视角更稳。它较少受 gpt-4o 通过率影响。

所以默认值是什么

多步推理的默认值是 gpt-5.2 effort=none — PAYG 和 PTU 都一样。none 既最便宜，也最好。再往上的任何强度都只增加成本和等待时间，质量没有收益。更高强度只有在“确实能买到额外质量”时才值得试，不是这种任务形态的默认值。
