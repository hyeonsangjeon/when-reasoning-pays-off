exp002 — 多步推理中推理强度是否值得

作者 Hyeonsang Jeon · Global Black Belt, Cloud & AI Apps

这个实验本该轮到推理获胜。二十个至少要经过两步才能得到答案的问题 — 看起来每把推理强度(reasoning_effort)提高一档，答案就会更安全。

我们也这样预先登记了。gpt-4o 会错掉一半多(30–60% 通过)，gpt-5.2 必须提高强度才会超过 80%。测量把两个预测都打偏了。gpt-5.2 在最低强度已经满分，gpt-4o 也远比预期更好。

本文按设计 → 输入 → 产物 → 预测对实测 → 异常值 → 决定回看那一天。不只是数字，也包括数字产生的路径和读法 — 希望后来的人少在同一路上绕弯。

设计

本该轮到推理获胜

问题只有一个。 在多步推理 — 推理的天花板案例 — 中，gpt-5.2 的强度要提高到哪里，推理才值回账单？我们同时用 PAYG(每个正确答案多少美元)和 PTU(固定容量下每分钟正确答案)两个视角来看。

数据集。 冻结的合成样本 20 个(mr_01…mr_20)。覆盖算术应用题、约束满足、日期/时间、因果链、代码追踪、布尔逻辑、计数七类；所有样本都有可验证答案，并要求至少两步推理。

变化的轴只有一个 — 扫过 gpt-5.2 的 reasoning.effort：none · low · medium · high · xhigh。旁边放置没有推理参数的 gpt-4o 基线。每个(样本 × 模型 × 强度)单元重复三次(R=3)。

预先登记预测

多步形态会推翻短事实基准的结论。gpt-4o 只会通过 30–60%，gpt-5.2 会在足够强度下通过 80% 以上，从而让推理值得。

本实验的作用

与短事实基准的底部(不需要推理的位置)配对，固定“推理值回账单”的成本曲面天花板锚点。

输入与产物

吃进什么，留下什么

这个实验吃进和留下的都不是手写摘要，而是仓库里的真实文件。所以可以从输入到输出一行回看。

输入 (in)

实验定义： experiments/exp002_benchmark02_gpt5_2.yaml, …_gpt4o.yaml.
数据集： benchmarks/02-multi-step-reasoning/dataset.json (以 SHA-256 固定)。
提示： 系统/用户模板分别以 SHA-256 指纹化 — 保证所有单元使用字节完全相同的提示。

产物 (out)

原始调用： runs/*.json (Foundry v1 Responses 载荷原文)。
评分： judge_runs/*.json.
聚合： analysis.json.
图表/表： results/cost-curves/benchmark-02-*.png·.csv.

测量表面为 360 个单元(gpt-4o 60 + gpt-5.2 300，五档强度)。作为异常值排除的单元为 0 个。评分由中立裁判 gpt-4o 对每个单元一次完成，360/360 成功(失败 0，重试 0)。所有 JSON 都是真实 Foundry v1 调用，没有一个 "fixture": true 标记(360 行中 159 行 reasoning_tokens > 0)。

预测对实测

预测错了两次

预测了什么

gpt-4o 会在 30–60% 崩掉。gpt-5.2 必须提高强度才会超过 80%。概括就是“高强度买来质量，并证明成本合理”。

结果是什么

gpt-4o 以 75%(45/60)比预期更强。gpt-5.2 在最低的 none 已经 100%(60/60)。按平均评价分数看，是 gpt-4o 1.50 对 gpt-5.2 2.00。

判定：假设被反驳。 “多步任务中高强度值得”这条预先登记，按原句被反驳。真正的胜负点不是强度旋钮，而是 gpt-4o → gpt-5.2 的模型替换。因为 gpt-5.2 的默认推理设置(none)已经足够。

第一次逆转

换了模型，质量上升，成本下降

下表中的美元数，是把方法论的 PAYG 公式应用于价格快照 pricing/azure-openai-payg-2026-05.yaml(访问日 2026-05-19)后得到，并从 analysis.md §5 重新引用。

模型      努力     每1,000次请求    通过率          每1,000个正确答案
gpt-4o    —        $0.80         75.0% (45/60)   $1.06   ← 基线
gpt-5.2   none     $0.62         100%  (60/60)   $0.62   ← 帕累托最优
gpt-5.2   low      $0.86         96.7% (58/60)   $0.89
gpt-5.2   medium   $1.08         100%  (60/60)   $1.08
gpt-5.2   high     $1.25         100%  (60/60)   $1.25
gpt-5.2   xhigh    $2.18         100%  (60/60)   $2.18

这张表就是连载正文使用的同一刻度(每 1,000 次)。模型变了，质量提高了，成本反而下降了 — 每 1,000 个正确答案下，none 为 $0.62，比 gpt-4o($1.06)便宜 42%。

low 每请求单价高 7.6%，但较高通过率(96.7% 对 75%)抵回了这部分溢价；按每 1,000 个正确答案看，仍比 gpt-4o 便宜 16%。第一层优化不是提高强度，而是把模型与强度看成一个组合，找出通过质量门槛后最便宜的点。

第二次逆转

更高强度用更高价格买到相同质量

gpt-5.2 的 none 和 xhigh 都是满分(平均 2.00，通过率 100%)。但每 1,000 个正确答案成本以 none($0.62)为底，升到 medium 1.75倍、high 2.02倍、xhigh 3.53倍($2.18)。

延迟也是同一个故事。 none 每次调用约 1.6 秒(1,589ms)，xhigh 约 3.3 秒(3,265ms)。相对 gpt-4o(1,382ms)，none 的延迟税只有约 15%，但 xhigh 是 2.4倍。在这个区间，高强度买到的不是更好的答案，而是同一个答案，价格更高、速度更慢。

拆开 token 后原因更清楚。 可见答案从 none 约 5.8 token 到 xhigh 约 7.7 token — 只多了两三个 token。但隐藏推理 token 从 0 膨胀到约 109.5，在 xhigh 时仅推理就占请求大小约 26%。质量不变，只有被计费的 token 膨胀。

这个结果并不意味着推理 token 没用。推理在存在待解决结构时会有价值。只是这个任务区间在最低组合已经触到量规顶端；当质量没有上升空间时，只提高强度会让额外 token 更接近过度支出，而不是投资。

PTU 视角下结论也相同。 gpt-5.2 none 是 gpt-4o 的 0.994倍吞吐 × 100% 通过，所以固定 PTU 支出下每分钟正确答案为 +32.5%(gpt-4o 为 75%)。提高强度只削吞吐，没有质量补偿。

质量地图

gpt-4o 在哪里倒下

75% 这个单一数字看不出“在哪里”。按类型拆开，gpt-4o 的失败集中在特定位置。

  • 错得多的地方： 算术应用题(平均 1.20)、日期/时间(1.00)、代码追踪(1.33)、约束满足(1.33) — 需要回头计算或反向追踪的类型。
  • 全答对的地方： 计数、布尔逻辑、因果链(各 2.00) — 一次前向通过就足够的类型。
  • gpt-5.2 在所有类型满分(2.00)。只有前述 mr_05 安全过滤拒绝的一个单元例外。

换句话说，这个数据集为 gpt-4o 画出了一张地图：“链条短、前向推理就通过；需要回头检查就失败。” gpt-5.2 把这张地图整个抹平了。

透明度

连数字上的污点也原样留下

任何测量都不可能完全干净。这个基准留下的痕迹，我们不擦掉，而是原样写下 — 因为藏起来，后来的人会在同一个地方踩空。

  • gpt-4o 比预期容易。 75% 超过了预先登记的 30–60%。这意味着数据集本来对 gpt-4o 没那么严苛。因此“相对 gpt-4o 的节省幅度”的大小比更难数据集时更小(预期 1.7–3.3倍差距 → 实现 1.7倍)。预测错了的部分不按数字抹掉，而是原样留下缩小的节省幅度。结论的方向(gpt-5.2 none 帕累托支配)不变。
  • 安全过滤拒绝 1 个。 mr_05 的 low 第一次重复中，Azure 内容过滤器返回了输入·输出 token 0 与结构化拒绝。这个单元没有运营标记(冷启动/重试/截断)，因此不会命中异常值规则；按 append-only 原则，不覆盖，原样留在聚合中(裁判准确评分为 0/失败)。同一问题其他重复均正常正确 — 不是系统性触发，这一个单元是 low 行方差变大的原因。
  • 部分分 0 个。 360 个单元里没有一个裁判 score == 1。因为设计了可验证答案，“给出 672”和“给出 576”之间没有中间态。因此二值化选择不会摇动 headline。

限制

可以相信到哪里

这个结果来自一个多步任务集、一个价格快照、特定模型组合与量规下的小规模聚合。比起数字本身，带走方法更安全。

  • 样本。 N=20 · R=3。在这个样本量下，不主张置信区间或统计显著性 — 方向性结论稳健，但绝对幅度需按小样本谨慎看待。
  • 价格。 单一快照。如果费率或 usage schema 改变，应从同一原始材料重新计算成本。
  • 评分。 LLM-as-judge(gpt-4o)。裁判提示 SHA-256 记录在评分 JSON 中以监控漂移。
  • 超出预先登记的影响。 gpt-4o 分母(0.75)比预期(0.30–0.60)更大，美元节省幅度因此缩小。所以在这个实验中，对 gpt-4o 通过率不敏感的 PTU 吞吐视角更稳健。

所以默认值是什么

多步推理的默认值是 gpt-5.2 effort=none — 在 PAYG 和 PTU 两边都是。none 既是底部也是最优，其上任何强度都只增加成本和延迟，没有质量收益。更高强度只是在“确实能买到额外质量”时才值得提升的实验候选，而不是这种任务形态的默认值。
