exp002 — 多段階推論で推論強度は割に合ったのか

執筆: Hyeonsang Jeon · Global Black Belt, Cloud & AI Apps

この実験では、推論強度(reasoning_effort)を上げる効果が表れるはずでした。対象は、少なくとも二段階を経なければ答えに到達できない二十問です。回答前の内部推論を増やすほど、品質が高まると予測しました。

私たちは、gpt-4o の通過率は 30–60%、gpt-5.2 は強度を上げて初めて 80% を超えると事前登録した予測に記しました。しかし、実測では二つとも外れました。gpt-5.2 は最も低い強度ですでに満点で、gpt-4o も予想を上回りました。

本ノートでは、none と low を含む結果を設計 → 入力 → 成果物 → 予測と実測 → 外れ値 → 判断の順に振り返り、数値の出所と解釈を示します。

この記事で分かること

難しい問題には強度を上げるべきか

前の実験(01)では、最も易しいタスクで推論強度を上げても品質は改善しませんでした。しかし、複数の条件や中間値をつなぐ多段階タスクでは、結果が変わる可能性があります。

そこで今回は、計算を含む文章題、複数条件の制約充足、日付計算など、少なくとも二段階を要する問題を選びました。「難しい仕事には推論を増やすべきだ」という通念が、実際にコストに見合うかを検証します。

条件を組み合わせ、中間値を引き継ぎ、論理を追うサービスに近いケースです。強度を上げるべきか、より安く速い設定があるのかを、二つの予測が外れた実測結果から判断します。

設計

推論強度が効果を持つはずだったケース

なぜ難しい側を測定したのか。 直前の実験(01)では、最も易しいタスクで推論を増やしても品質は改善しませんでした。そこで、一度では答えに到達できず、中間結果を使って次の段階へ進む問題なら、強度が効果を持つかを確かめました。

反対方向の仮説を立てました。 複数の手順を要する問題では、推論強度を上げると正答率が上がり、そのコストに見合うという仮説です。推論設定を持たないベースラインは一定の上限を超えないと予測しました。強度を上げても正答率が横ばい、またはベースラインが同等なら、仮説は崩れます。 この判定を実測で下すために実験を設計しました。

上限ケースとしての役割。 01が推論の効果がない下限なら、本ノートは推論が最も効果を持ちそうな上限です。両端を測定することで、続くツールエージェント(03)の混合ケースを位置付けられます。

検証する問いは一つです。 少なくとも二段階を要する問題で、gpt-5.2 の推論強度を上げると品質が改善し、そのコストに見合うのでしょうか。PAYG では正答当たりのコスト、PTU では同じ容量での分当たり正答を評価します。

データセット。 凍結した合成サンプル 20個(mr_01…mr_20)を使用しました。算術文章題、制約充足、日付/時刻、因果の連鎖、コードトレース、ブール論理、数え上げの七種類です。いずれも中間結果を次の手順で使う、少なくとも二段階の問題で、機械的に検証できる正答があります。

変更する変数は一つです。 gpt-5.2 の reasoning.effort を none · low · medium · high · xhigh の五段階で比較し、推論強度の設定がない gpt-4o を基準としました。各 (サンプル × モデル × 強度) セルを三回ずつ(R=3)実行しています。

事前登録した予測

多段階では短い事実回答の結論が覆り、gpt-4o は30–60%、gpt-5.2 は十分な強度で80% 以上通過すると予測しました。

この実験の役割

短い事実回答の下限(推論が不要な範囲)と対になる、推論が最も効果を持ちそうな上限を測定します。

測定したのは 360セル(gpt-4o 60 + gpt-5.2 300、強度五段階)です。外れ値として除外したセルは0個でした。評価モデル gpt-4o がセルごとに一回採点し、360/360 成功(失敗 0、再試行 0)しました。0点は失敗、1点は部分通過、2点は完全通過です。平均 2.00 は 60個すべてが通過し、gpt-4o の 1.50 は 45個の通過と 15個の失敗を含むことを示します。すべて実際の Foundry v1 呼び出しで、"fixture": true マーカーはありません(360行中 159行が reasoning_tokens > 0)。

予測と実測

二つの予測が外れた

事前登録した予測

gpt-4o は 30–60% にとどまり、gpt-5.2 は強度を上げて初めて 80% を超えると予測しました。

実測結果

gpt-4o は 75%(45/60)で予想を上回りました。gpt-5.2 は最も低い none ですでに 100%(60/60)でした。平均評価スコアは gpt-4o 1.50、gpt-5.2 2.00です。

判定: 事前登録した予測と不一致。 gpt-4o は予想より多く正解し、gpt-5.2 は none で、強度を上げる前から満点でした。差を生んだのは推論強度ではなく、gpt-4o から gpt-5.2 へのモデル変更でした。

第一の反転

モデル変更で品質が上がり、コストが下がった

表のドル額は、価格スナップショット pricing/azure-openai-payg-2026-05.yaml(アクセス日 2026-05-19)に方法論の PAYG 式を適用した値で、analysis.md §5 から再引用しています。

モデル      推論強度  1,000リクエスト当たり 通過率          正答1,000件当たり
gpt-4o    —        $0.80         75.0% (45/60)   $1.06   ← ベースライン
gpt-5.2   none     $0.62         100%  (60/60)   $0.62   ← パレート最適
gpt-5.2   low      $0.86         96.7% (58/60)   $0.89
gpt-5.2   medium   $1.08         100%  (60/60)   $1.08
gpt-5.2   high     $1.25         100%  (60/60)   $1.25
gpt-5.2   xhigh    $2.18         100%  (60/60)   $2.18

モデルを変更すると、品質は上がり、コストは下がりました。 正答 1,000件当たりで none は $0.62、gpt-4o は $1.06 で、42% 安い結果です。

low はリクエスト当たり単価が 7.6% 高い一方、通過率は 96.7% 対 75% でした。そのため、正答 1,000件当たりでは gpt-4o より16% 安い結果です。正答 1,000件当たりの比較に基づく最適化ではモデルと強度を組み合わせ、合格線を満たす最安の設定を選ぶ必要があります。

第二の反転

高い強度では同じ品質のコストが増えた

gpt-5.2 の none と xhigh は同じ満点(平均 2.00、通過率 100%)でした。一方、正答 1,000件当たりのコストは none($0.62)に対し、medium で 1.75倍、high で 2.02倍、xhigh で 3.53倍($2.18)でした。同じ品質をより高いコストで得ています。

レイテンシも同じ傾向です。 none は約 1.6秒(1,589ms)、xhigh は約 3.3秒(3,265ms)でした。gpt-4o(1,382ms)と比べて none は約 15% 遅く、xhigh は 2.4倍遅い結果です。高い強度は品質を改善せず、コストと時間だけを増やしました。

トークン構成から理由を確認できます。 表示される出力は none で約 5.8トークン、xhigh で約 7.7トークンでした。一方、隠れた推論トークンは 0 から約 109.5 に増え、xhigh ではリクエストサイズの約 26% を占めました。品質は変わらず、課金対象トークンだけが増えています。

推論トークンが常に不要という意味ではありません。複雑な計画やツール選択など、解くべき段階が残っている場合には効果があり得ます。 しかし、この問題群は最も低い設定ですでに満点に達して頭打ちでした。その範囲では、追加の推論トークンは品質を改善しませんでした。

PTU でも結論は同じです。 gpt-5.2 none は gpt-4o の 0.994倍のスループットで通過率 100% となり、同じ PTU 支出での分当たり正答は +32.5% でした(gpt-4o は 75%)。強度を上げると品質は変わらず、スループットだけが低下しました。

品質の内訳

gpt-4o が失敗したタスク

gpt-4o の通過率 75% だけでは失敗箇所は分かりません。型別に分けると、戻って計算したり逆順に追跡したりするタスクに失敗が集中していました。

  • 失敗が多い型: 算術文章題(平均 1.20)、日付/時刻(1.00)、コードトレース(1.33)、制約充足(1.33) — 戻って計算するか、順序をさかのぼる必要があります。
  • すべて正解した型: 数え上げ、ブール論理、因果の連鎖(各 2.00) — 前から後ろへ一度たどれば解けるタスクです。
  • gpt-5.2 は low を除く全強度で全型満点(2.00)でした。low では 2セルが 0点です — mr_05(制約充足)の安全フィルター拒否と、mr_15(コードトレース)の誤答「cba a」(正答「cbaa」)です。そのため、low では、この 2型はそれぞれ 1.78(±0.67)でした。

gpt-4o は、前向きにたどるだけの問題には通過し、戻って追跡する問題で失敗しました。gpt-5.2 は low の 2セルを除き、gpt-5.2 はすべての型で満点でした。

透明性

測定上の例外も開示する

どの測定にも例外やノイズはあります。このベンチマークで生じた事象を、再検証できるように省略せず記録します。

  • gpt-4o は予想を上回りました。 75% は事前登録した予測の 30–60% を超えました。データセットが gpt-4o に対して想定ほど難しくなかったため、gpt-4o 比の削減幅は予想の 1.7–3.3倍から実測の 1.7倍になりました。ただし、gpt-5.2 none がコストと品質の両方で上回るという方向は変わりません。
  • 安全フィルター拒否 1件。 mr_05 の low 1回目で Azure コンテンツフィルターがリクエストを止め、入力·出力トークン 0 の定型拒否を返しました。運用上の問題マーカーはないため外れ値として除外せず、評価モデルの 0点を集計に含めました。同じ問題のほかの反復は正解しており、low で 1回限りの事象でした。
  • コードトレース誤答 1件。 mr_15 の low 3回目(r2)で、g("abc") の出力を「cba a」と回答しました。正答は「cbaa」(反転した「cba」に先頭文字「a」を連結)です。評価モデルは 0点としました。この 2件のうち、この誤答と mr_05 の拒否が、low の通過率 96.7%(58/60)につながりました。
  • 部分点 0件。 360セルで評価スコア 1、つまり score == 1 はありませんでした。正答が明確なため、たとえば “672 を出した” 場合と “576 を出した” 場合の間に部分点はなく、合格・不合格だけで評価しても結論は変わりません。

限界

どこまで信じられるか

この結果は、一つの多段階タスクセット、一つの価格スナップショット、特定のモデルと採点基準に基づく小規模な集計です。絶対値をそのまま一般化するより、方法を再利用するほうが安全です。

  • 標本。 N=20 · R=3 で、信頼区間や統計的有意性は主張しません。方向性は明確ですが、絶対値は小標本の結果として慎重に解釈します。
  • 価格。 価格表は一つだけを基準にしました。料金や課金方式が変われば、同じ原資料からコストを再計算する必要があります。
  • 採点。 評価モデル(gpt-4o)を使用し、評価プロンプトのデジタル指紋(SHA-256)を採点 JSON に記録しました。
  • 予想を上回った影響。 gpt-4o の通過率(0.75)が予想(0.30–0.60)より高く、ドル削減幅はその分小さくなりました。そのため、gpt-4o 通過率の影響を受けにくい PTU スループットも併せて確認します。

デフォルト

多段階推論のデフォルトは、PAYG と PTU のどちらでも gpt-5.2 effort=none です。none は最も安く、通過率も満点でした。それ以上の強度は品質を変えず、コストとレイテンシだけを増やしました。高い強度は、追加品質を実際に得られる場合にだけ試す候補であり、このタスク群のデフォルトではありません。
