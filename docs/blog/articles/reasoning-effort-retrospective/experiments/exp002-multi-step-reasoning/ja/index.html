exp002 — 多段階推論で推論努力度は割に合ったのか

文 Hyeonsang Jeon · Global Black Belt, Cloud & AI Apps

この実験は、推論が勝つ番だった。少なくとも二段階を経なければ答えが出ない二十問 — 推論努力度(reasoning_effort)を一段上げるほど答えがより安全になりそうな場所である。

私たちはそう事前登録した。gpt-4o は半分余りを間違え(30–60% 通過)、gpt-5.2 は努力度を上げてようやく 80% を超える、と。測定は二つの予測をどちらも外した。gpt-5.2 は最も低い努力度ですでに満点を取り、gpt-4o は予想よりずっとよくできた。

このノートはその一日を設計 → 入力 → 成果物 → 予測対実測 → 外れ値 → 判断として振り返る。数字だけでなく、その数字が出た道筋と読み方まで一緒に — 次の人が同じ道で迷いにくいように。

設計

推論が勝つ番だった

検証する問いは一つに絞った。 少なくとも二段階を踏まないと答えが出ない多段階推論 — 三つのベンチマークで推論が最も見合いそうな天井ケース — で、gpt-5.2 に考える余地(推論の努力度)を与えるほど答えは良くなり、それに見合うのか。だから確かめることも二つだけだ — 努力度を上げると(1) 品質は上がるか、(2) コストは上がるか。 お金は二つの角度で読む。使った分だけ払う PAYG では ‘正答一つ当たりいくら’ を、容量を丸ごと借りる PTU では ‘同じ容量で分当たり何個当てるか’ を見る。

何で測るか — データセット。 凍結した合成サンプル 20個(mr_01…mr_20)。算術文章題、制約充足、日付/時刻、因果の鎖、コードトレース、ブール論理、数え上げ — 七つの型に均等にわたる。肝心なのは一目では答えが出ない点だ。途中結果を手に持ったままもう一歩 — たとえば先に求めた値を条件にもう一度当てはめて — 進んで初めて正答に届く。だから ‘少なくとも二段階’ なのだ。すべてのサンプルは機械で検証可能な正答を持つ。

変わる軸は一つだけ — gpt-5.2 の reasoning.effort を none · low · medium · high · xhigh でスイープする。そこに推論パラメータのない gpt-4o ベースラインを横に置く。各 (サンプル × モデル × 努力度) セルは三回ずつ(R=3)繰り返す。

事前登録予測

多段階形状は短い事実回答ベンチマークの結論をひっくり返す。gpt-4o は30–60%しか通過せず、gpt-5.2 は十分な努力度で80% 以上通過し、推論は割に合うはずだ。

この実験の役割

短い事実回答ベンチマークの床(推論が不要な場所)と対になり、“推論が請求書に見合う”コスト曲面の天井を固定するアンカー。

予測対実測

予測は二度外れた

何を予測したか

gpt-4o は 30–60% で崩れる。gpt-5.2 は努力度を上げてようやく 80% を超える。要するに “高い努力度が品質を買い、コストを正当化する。”

何が出たか

gpt-4o は 75%(45/60)で予想より強かった。gpt-5.2 は最も低い none ですでに 100%(60/60)。平均評価スコアで見ると gpt-4o 1.50 対 gpt-5.2 2.00 である。

判定: 事前登録反証。 “多段階では努力度を上げてこそ見合う”という予測は二つの方向で外れた — gpt-4o は予想より解けたし、gpt-5.2 は努力度を上げる前からすでに満点だった。だから本当の勝負所は努力度ダイヤルではなく、gpt-4o を gpt-5.2 に入れ替えたことそのものだった。gpt-5.2 の基本設定(none、推論を切った状態)がすでに十分だったからだ。

第一の逆転

モデルを変えると品質は上がり、コストは下がった

下の表のドルは価格スナップショット pricing/azure-openai-payg-2026-05.yaml(アクセス日 2026-05-19)に方法論の PAYG 式を適用した値で、analysis.md §5 から再引用している。

モデル      努力度   1,000リクエスト当たり 通過率          正答1,000件当たり
gpt-4o    —        $0.80         75.0% (45/60)   $1.06   ← ベースライン
gpt-5.2   none     $0.62         100%  (60/60)   $0.62   ← パレート最適
gpt-5.2   low      $0.86         96.7% (58/60)   $0.89
gpt-5.2   medium   $1.08         100%  (60/60)   $1.08
gpt-5.2   high     $1.25         100%  (60/60)   $1.25
gpt-5.2   xhigh    $2.18         100%  (60/60)   $2.18

この表が、そのまま連載本文と同じ目盛り(1,000件当たり)である。モデルを変えたのに、品質は上がり、コストはむしろ下がった — 正答 1,000件当たりで none は $0.62、gpt-4o($1.06) より42% 安い。

low はリクエスト当たり単価が 7.6% 高いが、高い通過率(96.7% 対 75%)がそのプレミアムを返し、正答 1,000件当たりでは gpt-4o より16% 安い。最初の最適化は努力度を上げることではなく、モデルと努力度を一つの組み合わせとして見て、品質を通過した最も安い地点を探すことだった。

第二の逆転

より高い努力度は同じ品質をより高く買った

ここで二つ目の事実が見えてくる。gpt-5.2 の none と xhigh は品質が等しく満点(平均 2.00、通過率 100%)である。ところが正答 1,000件当たりのコストは none($0.62)を床に、medium 1.75倍、high 2.02倍、xhigh 3.53倍($2.18)へと跳ね上がる — 同じ答えをどんどん高く買っているわけだ。

遅延も同じ話だ。 none は呼び出し当たり約 1.6秒(1,589ms)、xhigh は約 3.3秒(3,265ms)。gpt-4o(1,382ms) に対する none の遅延税は約 15%にすぎないが、xhigh は 2.4倍だ。この区間の高い努力度は、より良い答えを買ったのではなく、同じ答えをより高く、より遅く買った。

トークンを分解すると理由ははっきりする。 目に見える答えは none で約 5.8トークン、xhigh で約 7.7トークン — 二トークン余り増えただけだ。ところが隠れた推論トークンは 0 から約 109.5 へ膨らみ、xhigh では推論だけでリクエストサイズの約 26% を占める。品質はそのままなのに、請求されるトークンだけが膨らんだのである。

この結果は、推論トークンが役に立たないという意味ではない。推論はまだ解くべき構造が残っているときにだけ割に合う。ただしこの作業区間は最も低い組み合わせですでにルーブリックの頂点に届いてしまった — これ以上取れる点がない。天井に頭がついた場所で努力度だけを上げれば、追加で燃やす推論トークンは投資ではなく過剰支出になる。要するに、努力度ダイヤルは ‘まだ上がる品質が残っているときにだけ’ 入れるスイッチだ。

PTU レンズでも結論は同じだ。 gpt-5.2 none は gpt-4o の 0.994倍スループット × 100% 通過で、固定 PTU 支出における分当たり正答が +32.5% だ(gpt-4o は 75%)。努力度を上げるとスループットだけが削られ、品質の補償はない。

品質マップ

gpt-4o はどこで崩れたか

gpt-4o の 75% という集計数字一つだけでは、“どこで”間違えたかが見えない。そこで作業の型別にスコアを割ってみた。すると失敗が特定の場所に — 戻って計算したり逆向きに追跡したりする必要のある型に — 集まっていることが分かった。

  • 多く間違えた場所: 算術文章題(平均 1.20)、日付/時刻(1.00)、コードトレース(1.33)、制約充足(1.33) — 戻って計算したり、逆向きに追跡したりする必要がある型。
  • すべて正解した場所: 数え上げ、ブール論理、因果の鎖(各 2.00) — 一度の前向きパスで足りる型。
  • gpt-5.2 は low を除く全努力度で全型満点(2.00)。low だけで 2セルが 0点 — mr_05(制約充足)の安全フィルター拒否と、mr_15(コードトレース)の誤答「cba a」(正答「cbaa」)。そのため low ではこの 2型が各 1.78(±0.67)。

言い換えると、このデータセットは gpt-4o に対して “チェーンが短く前向き推論なら通過、戻りが必要なら失敗” という地図を描いた。gpt-5.2 はその地図を丸ごと平坦化した。

透明性

数字に残った汚れまでそのまま

どんな測定も完全にきれいではない。このベンチマークが残した跡を消さず、そのまま書いておく — 隠すと次の人が同じ場所で踏み外すからだ。

  • gpt-4o には予想より易しかった。 75% は事前登録した 30–60% を超えた。データセットがそもそも gpt-4o にそれほど厳しくなかったということだ。だから “gpt-4o 比の削減幅” の大きさは、もっと難しいデータセットだった場合より小さくなった(期待 1.7–3.3倍の差 → 実現 1.7倍)。予測が外れた側を数字に合わせて消さず、小さくなった削減幅をそのまま残す。結論の方向(gpt-5.2 none がパレート支配)は変わらない。
  • 安全フィルター拒否 1件。 mr_05 の low 1回目の反復で、Azure コンテンツフィルターが入力·出力トークン 0 と定型拒否を返した。このセルには運用フラグ(コールドスタート/再試行/切断)がないため外れ値規則にはかからず、append-only 原則に従って上書きせず集計にそのまま残した(ジャッジは正確に 0/失敗と採点)。同じ問題の他の反復は正常な正答 — 系統的なトリップではなく一回限りで、この 1セルが low 行の入力トークン分散を大きくした原因である。
  • コードトレース誤答 1件。 mr_15 の low 3回目の反復(r2)で、g("abc") の出力を「cba a」と返した — 正答は「cbaa」(反転した「cba」に先頭文字「a」を連結)だ。ジャッジは 0/失敗と採点し、これは安全フィルターとは無関係の純粋な推論エラーだ。このセルと mr_05 の拒否が、low の通過率を 96.7%(58/60)にした 2件の失敗である。
  • 部分点 0件。 360セル全体でジャッジの score == 1 は一つもなかった。検証可能な正答設計なので、“672 を出した” と “576 を出した” の間に中間はない。だから二値化の選択はヘッドラインを揺らさない。

限界

どこまで信じられるか

この結果は、一つの多段階タスクセット、一つの価格スナップショット、特定のモデル組み合わせとルーブリックから出た小規模な集計値です。数字そのものより、方法を持ち帰るほうが安全です。

  • 標本。 N=20 · R=3。この標本サイズでは信頼区間や統計的有意性を主張しない — 方向性の結論は堅いが、絶対値の大きさは小標本として注意。
  • 価格。 単一スナップショット。料率や使用量スキーマが変われば、同じ原資料からコストを再計算する必要がある。
  • 採点。 LLM-as-judge(gpt-4o)。ジャッジプロンプト SHA-256 を採点 JSON に記録してドリフトを監視する。
  • 事前登録超過の余波。 gpt-4o の分母(0.75)が予想(0.30–0.60)より大きく、ドル削減幅が縮小した。だからこの実験では、gpt-4o 通過率に鈍感な PTU スループットレンズのほうがより堅い観点である。

だから何をデフォルトにするか

多段階推論のデフォルトは gpt-5.2 effort=none である — PAYG と PTU の両方で。none が床であると同時に最適であり、その上のどの努力度も品質なしにコストと遅延だけを足す。より高い努力度は “追加品質を実際に買うとき” にだけ昇格する実験候補であり、このタスク形状のデフォルトではない。
