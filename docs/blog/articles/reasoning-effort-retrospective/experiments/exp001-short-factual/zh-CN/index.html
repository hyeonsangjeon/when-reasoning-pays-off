实验笔记 · exp001 · 短事实任务(Null case) · 推理不值得的底部

exp001 — 短事实任务需要推理吗

作者 Hyeonsang Jeon · Global Black Belt, Cloud & AI Apps

我们先放下三项基准的底部。抽取·格式·分类·音译·算术 — 这些都是一次就能答出的短事实任务。在这里提高推理强度，很像为“1 加 1”开一场会。预测很简单。推理不值得。

这篇笔记和前两篇有一点不同。它不是合成 fixture，而是实测。我们真的用 Azure Foundry v1 调了 360 个单元。中立评审模型 gpt-4o 对每个单元评一次分，共 360/360。任何地方都没有 "fixture": true 标记。所以这个底部不是‘看起来合理的合成底部’，而是实际测出来的底部。

实测结果与预测一致。这是三项基准里唯一没有反转的地方。但实测也补了两个细节。第一，gpt-5.2 在完全不开推理的 none 下，已经在质量上超过 gpt-4o。第二，即使把强度提高到 xhigh，隐藏推理 token 也接近 0。也就是说，强度旋钮没有接到任何地方。本文按设计 → 输入 → 产物 → 预测对实测 → 失败藏身处 → 决定回看这个底部。希望后来的人少在同一路上绕弯。

为什么值得读

这个旋钮，调高真的划算吗？

接上新模型，设置里常会有一个叫推理强度的旋钮。它决定模型回答前，要在心里多想多久。调高后好像会更聪明，所以拿不准时，很容易先设高一点。但只要调高旋钮，不管答案有没有变好，钱和时间都会实打实多花。所以“试试也不亏”可能并不成立。

所以我们先从最容易的地方查起。短事实任务，一次就能答出 — 抽取数值、调整格式、分类、简单计算 — 也是许多服务最常处理的工作。如果旋钮在这里空转，“不确定，就先调高”的习惯，只会把每月账单推高。

本文从最容易的情况开始，用实测划清这个旋钮什么时候值回成本，什么时候只是浪费。如果你的工作就在这里，结论就可以当成默认值。如果不是，也不用急 — 后面多步任务(02)和工具任务(03)里的反转，只有拿这个底部来对照才有意义。

设计

从最简单的任务开始

为什么非要测这个。 有一个常见想法：“让模型多想一点，答案就会更好。” 这听起来很合理。所以很多团队拿不准时，就先把推理强度调高 — 觉得反正不会吃亏。可是强度一高，不管答案有没有变好，钱和时间都会实打实增加。所以“不会吃亏”可能并不成立。我们想用数据，而不是凭感觉，看看这个想法到底对不对。

于是把这个想法变成了“假设”。 这句话是：在最简单的任务里，更用力思考不会让答案更好，只会增加成本。 一个有用的假设，必须有一条线说明“如果发生这个，我就错了”。这里这条线很清楚。如果强度越高，正确率也明显上升，这个假设当场就破了。 如果强度提高后正确率仍然持平，假设就站得住。我们设计这个实验，就是想靠实测来判定，而不是靠猜。

为什么从最简单的任务开始。 因为要先钉住一个基准点，后面的结果才可信。要证明难题里“推理值得”，就得先用实测看清“推理不值得的位置”到底长什么样。有了这个底部，后面多步(02)和工具(03)笔记里的反转，才看得出是真的反转。所以这篇笔记就是本系列的出发点和基准点。

要验证的问题缩成一个。 这是一次就能答出的短事实任务。也是三项基准里最容易的情况。给 gpt-5.2 更多思考余地(推理强度)，答案会不会更好？这笔账值不值？要看的只有两点。提高强度后，(1) 质量会不会上升，(2) 成本会不会上升。 钱从两个角度读。按量付费的 PAYG 看“每个正确答案多少钱”。整块租用容量的 PTU 看“同样的容量每分钟能答对几个”。预期答案是“不”。这个实验的作用，就是用实测而不是猜测，把那个“不”的底部钉住。

用什么来测 — 数据集。 冻结的手写样本 20 个(sf_01…sf_20)，均匀混合了抽取·格式·分类·列举·音译·规范化·单位换算·简单算术·摘要。这类任务很难把“唯一正确答案”写进一张表。所以我们不用答案表，只固定 expected_output_shape(答案的形状)和 quality_rubric_notes(评分标准)。然后让中立评审模型 gpt-4o 读每份答案，并打 0·1·2 分。每次打分的理由也照原样留在原始材料中。

只改一件事。 我们把 gpt-5.2 的推理强度(reasoning.effort)从 none(关)一路提到 low · medium · high · xhigh，共五档。其余条件全部固定。旁边放一个没有推理旋钮的 gpt-4o 基准点。为了过滤偶然运气，每个(样本 × 模型 × 强度)单元各跑三次(R=3)。

预先登记预测

短事实任务不需要推理。质量在最低强度已经到顶。提高强度后，质量不变，只增加成本·延迟·token。也就是说，答案是“不要提高强度”。

本实验的作用

三项基准的底部锚点。在测量多步(02)的天花板和工具智能体(03)的混合形态之前，先用实测固定“确实不需要推理的位置”长什么样。后面实验里的反转，正是和这个底部对照后才有意义。

输入与产物

吃进什么，留下什么

这个实验吃进什么、留下什么，都不是手写摘要。它们是仓库里的真实文件。所以你可以从输入一路查到输出。

输入 (in)

实验定义： experiments/exp001_short-factual_baseline.yaml, …_gpt4o.yaml.
数据集： benchmarks/01-short-factual/dataset.json (以 SHA-256 固定)。
提示： 系统提示以 SHA-256 指纹化 — 保证 360 个单元全都使用同一个提示。评审提示 SHA-256 也记录在每个评分 JSON 中。

产物 (out)

原始调用： runs/*.json (Foundry v1 载荷 + usage/latency 原文)。
评分： judge_runs_real/*.json (实测 gpt-4o 评审，每单元 1 次)。
汇总： analysis.json (实测数据)。
图表/表： results/cost-curves/benchmark-01-*.png·.csv.

测量表面为 360 个单元(gpt-4o 60 + gpt-5.2 300，五档强度)。作为离群值排除的单元为 0 个。没有任何行因为运行问题标记（冷启动·重试·输出截断）而超过 3σ（明显超出正常范围的值）。评分由中立评审模型 gpt-4o 对每个单元评一次，360/360 成功。所有 JSON 都是真实 Azure Foundry v1 调用，没有一个 "fixture": true 标记。汇总用 --experiment-prefix exp001_short-factual_baseline 只选择实测数据重新生成。跑两次字节相同，也就是相同输入总是得到相同结果。

预测对实测

预测原样成立的唯一位置

预测了什么

短事实任务不需要推理。质量在底部已经到顶。提高强度后，质量仍不变，只增加成本。概括就是“不要提高强度”。

结果是什么

正好如此 — 没有反转。质量在 none 就已到顶(正确率 95%)。提高强度后，只在 60 个样本中 1–2 个的范围内晃动。额外细节是：none 在质量上也超过了 gpt-4o，而推理 token 即使在 xhigh 也接近 0。

判定：预测正好命中。 多步(02)和工具(03)打开后，故事都反转了(天花板里 none 是底部，混合里 low 是底部)。但只有这个底部按预测发生。所以这个实验是本系列的基准点。它用实测展示“推理不值得的位置”实际长什么样。

第一个信号

none 已经赢过 gpt-4o

下表中的美元数来自同一套算法。我们把方法论里的 PAYG 公式，套到价格快照 pricing/azure-openai-payg-2026-05.yaml(访问日 2026-05-19)上。数值从 analysis.md §5 重新引用，并按每 1,000 次归一化。正确率是评审分数 2(完全正确)的比例。

模型      努力     每1,000次请求    正确率           每1,000个正确答案
gpt-4o    —        $0.665        90.0% (54/60)    $0.739   ← 基线
gpt-5.2   none     $0.587        95.0% (57/60)    $0.618   ← 默认值
gpt-5.2   low      $0.589        96.7% (58/60)    $0.609
gpt-5.2   medium   $0.589        96.7% (58/60)    $0.609
gpt-5.2   high     $0.608        95.0% (57/60)    $0.640
gpt-5.2   xhigh    $0.598        95.0% (57/60)    $0.629

完全不开推理的 none 在两个方向上都领先 gpt-4o。 每 1,000 次请求 $0.587，比 gpt-4o($0.665)便宜 12%，正确率反而95% 对 90%更高。折算成每 1,000 个正确答案，是 $0.618 对 $0.739 — 便宜 16%。换句话说，这里真正起作用的不是“提高强度”，而是换了模型本身。强度旋钮到这里还什么都没做。

而且 none 以上几乎什么都没发生。low·medium 的正确率看起来高了一档，达到 96.7%。但那只是 60 个里多对了 1 个。样本这么小(N=20·R=3，无置信区间)，应当读作噪声。继续提到 high，成本反而按请求涨 +3.6%，正确率却退回 95%。最终，从 none 到 medium 基本持平。再往上只是增加成本，不换来质量。

失败藏身处

失败藏在哪里

只看 90% 对 95% 这两个汇总数字，看不出差距“出在哪里”。于是我们按任务类型把分数拆开。结果大多数类型在两个模型上都是满分(2.0)，差异只出现在三处 — 抽取·摘要·算术。这三类正是本实验的核心。

类型              gpt-4o   5.2/none   5.2/low   5.2/high   5.2/xhigh
抽取(extraction)  1.75     2.00       2.00      2.00       2.00
摘要(summ.)       1.33     1.78       2.00      1.78       1.89
算术(arith-triv)  2.00     1.83       1.67      1.67       1.67
  • 抽取 — gpt-5.2 在底部补上的地方。 gpt-4o 在 12 个抽取样本中得 1.75，漏了几项。gpt-5.2 从不开推理的 none 开始，已经是 2.00 满分。gpt-5.2 的 95% 领先 gpt-4o 的 90%，原因就在这里 — 不是推理，而是模型本身抽取得更稳。
  • 摘要 — low 到顶，之后回退。 这是 gpt-4o 最弱的标签(1.33)。gpt-5.2 从 none 1.78 → low 2.00 上升，又在 medium·high 回到 1.78–1.89。提高强度并不会让摘要更好。
  • 算术 — 唯一 gpt-4o 获胜的位置，也是强度的反作用。 在 6 个小算术样本上，gpt-4o 得 2.00 满分，而 gpt-5.2 从 none 1.83 下降到 low·high·xhigh 的 1.67。强度越高，越会把“1 加 1”反复咀嚼，反而踩空。推理不只是没有价值。在这里，它有负价值。

三个标签彼此抵消。gpt-5.2 在抽取·摘要上比 gpt-4o 赚回分数，在算术上略有损失。合起来看，none·low 最高。而且没有任何标签因为提高强度而得益。这就是这个基准被称为 “Null case” 的原因。

第二个信号

提高强度，推理仍停在 0

那么，为什么提高强度质量却不动？ 拆开 token 后，答案很直接。gpt-5.2 不摆到台面上使用的推理 token在 none·low·medium 平均为 0.00，在 high 为 1.35，在 xhigh 为 0.62。也就是说，即使把强度拉到最大，模型真正花在“思考”上的 token 也接近 0。短事实任务一次就能答完，根本没有可规划、可回看的余地。强度旋钮再怎么拧，也接不到任何地方。这与推理 token 确实随强度上升的多步任务(02)正好相反。

推理为 0，成本也跟着平。 每次请求输入固定在 224 token(提示逐字节相同)。可见输出也只在 10–16 token 间，几乎不增。所以各强度间的成本差，不过是从 none $0.587 到 high $0.608 — 每 1,000 次请求两美分多一点的轻微晃动。

响应耗时(延迟)也不跟随强度。 gpt-4o 为 1,494ms。gpt-5.2 无论强度如何，都像噪声一样散在 1,410–1,713ms 之间。medium 甚至比 none 更快。在一次答完的任务里，强度预测不了速度。

从 PTU 来看，结论没有反转，只是略微躺平。 gpt-5.2 none 每请求 token 比 gpt-4o 多约 1%，吞吐为 0.99倍(约 −1%)。按同一块固定容量每分钟答对的个数看，gpt-4o 略微领先。总结就是：按量付费的 PAYG 下 gpt-5.2 none 明确更便宜，租用的 PTU 下实质上是平手。不像前两个基准那样 PTU 拉开很大差距，这里两个模型几乎重叠。

透明度

连数字上的污点也原样留下

任何测量都不可能完全干净。这个基准留下的痕迹，我们不擦掉，而是原样写下。因为藏起来，后来的人会在同一个地方踩空。

  • 替换为实测。 这个底部一开始是以合成 fixture(exp008_short-factual_fixture)发布的。形状合理，但不是测量。随本文一起，我们把那个位置换成了实测数据。用 --experiment-prefix exp001_short-factual_baseline 重新生成 analysis.json·图·表。fixture 没有删除。它仍作为无需凭据的离线复现脚手架保留在仓库里，但从发布数字来源中移除。fixture 使用的 minimal 强度会被真实部署拒绝，因此实测数据的底部是 none。
  • 离群值 0 个。 360 个单元里没有任何行因为 3σ 或运行问题标记被排除(远低于方法论 10% 警戒线)。也就是说，没有从汇总中排除任何数据。
  • 没有固定答案表。 这个数据集没有用于规则对照的答案表，因此质量只能由评审分数判定。所以“正确率”只按通过·未通过来数，只统计评审分数 2(完全正确)的比例。部分正确(1)不算入通过率。明确这个选择，是为了说明这个标题数值是如何算出来的。
  • 算术的逆转。 gpt-5.2 输给 gpt-4o 的唯一标签(算术)没有隐藏，而是原样写在§失败藏身处。这样是为了说明，底部的结论不是“gpt-5.2 赢过一切”，而是“强度不值得”。

限制

可以相信到哪里

这个结果来自一个短事实任务集、一个价格快照、特定模型组合和评分标准。样本也不大。比起直接拿走数字，借鉴方法更稳妥。

  • 样本。 N=20 · R=3。在这个样本量下，不主张置信区间或统计显著性。none·low·medium 的正确率差异(60 个中 1 个)应读作噪声。方向性结论(“强度不值得”)稳健，但绝对幅度要按小样本谨慎看待。
  • 评分。 评分由评审模型(gpt-4o)完成。没有固定答案表，质量完全依赖评审。评审提示 SHA-256 记录在评分 JSON 中，以便以后核对是否发生变化。但评审自身的偏差仍然可能存在。
  • 价格。 只用了一张价格快照。如果费率或计费方式改变，应从同一原始材料重新计算成本。
  • PTU。 吞吐是基于 token 的估算，不是真实 PTU 负载测试。这个底部里两种模型吞吐在约 1% 内重叠，所以 PTU 结论要特别谨慎阅读。

所以默认值是什么

短事实任务的默认值是 gpt-5.2 effort=none。完全不开推理时，按请求比 gpt-4o 便宜 12%、按正确答案便宜 16%，正确率反而 95% 对 90% 更高。从 none 到 medium 基本持平，所以用 low·medium 也无妨。但额外收益在样本噪声内。high 以上推理 token 仍接近 0，却只增加成本，因此弃用。从 PTU 来看，gpt-4o 略微领先，实质上平手。起作用的是模型替换，不是强度。
