实验笔记 · exp001 · 短事实任务(Null case) · 推理不值得的底部

exp001 — 短事实任务需要推理吗

作者 Hyeonsang Jeon · Global Black Belt, Cloud & AI Apps

先放下三项基准的底部。抽取·格式·分类·音译·算术 — 一次就能答出的短事实任务。在这里提高推理强度，近似于为“1 加 1”召开一次评审会。预测很简单：推理不值得。

这篇笔记与前两篇有一个不同之处。它不是合成 fixture，而是实测。360 个单元全部通过 Azure Foundry v1 真实调用，并由中立裁判 gpt-4o 对每个单元评分一次，共 360/360。任何地方都没有 "fixture": true 标记。所以这个底部不是‘看起来合理的合成底部’，而是被测量出来的底部。

测量原样确认了预测 — 这是三项基准里唯一一个预先登记没有反转的位置。但实测也补上了两个细节。其一，gpt-5.2 在完全不开推理的 none 下，已经在质量上超过 gpt-4o。其二，即使把强度提高到 xhigh，隐藏推理 token 也贴近 0 — 强度旋钮没有接到任何地方。本文按设计 → 输入 → 产物 → 预测对实测 → 失败藏身处 → 决定回看这个底部 — 希望后来的人少在同一路上绕弯。

设计

从最简单的任务开始

问题只有一个。 对于一次就能答出的短事实任务 — 三项基准中最容易的案例 — 提高 gpt-5.2 的强度后，推理是否值回账单？我们同时用 PAYG(每个正确答案多少美元)和 PTU(固定容量下每分钟正确答案)两个视角来看。预期答案是“不”。这个实验的作用，是用实测钉住那个底部。

数据集。 冻结的手写样本 20 个(sf_01…sf_20)。混合了抽取·格式·分类·列举·音译·规范化·单位换算·简单算术·摘要。没有确定性答案表 — 只固定 expected_output_shape 与 quality_rubric_notes。因此质量不是规则对照，而只由中立裁判(gpt-4o)评分判定。这是为了把评分依据留在原始材料中。

变化的轴只有一个 — 扫过 gpt-5.2 的 reasoning.effort：none · low · medium · high · xhigh。旁边放置没有推理参数的 gpt-4o 基线。每个(样本 × 模型 × 强度)单元重复三次(R=3)。

预先登记预测

短事实任务不需要推理表面。质量在最低强度已经饱和；提高强度后，质量不变，只增加成本·延迟·token。也就是说，答案是“不要提高强度”。

本实验的作用

三项基准的底部锚点。在测量多步(02)的天花板和工具智能体(03)的混合形态之前，用实测固定“确实不需要推理的位置”长什么样。后续实验的反转，正是与这个底部对照后才有意义。

输入与产物

吃进什么，留下什么

这个实验吃进和留下的都不是手写摘要，而是仓库里的真实文件。所以从输入到输出，可以顺着一条线索回溯。

输入 (in)

实验定义： experiments/exp001_short-factual_baseline.yaml, …_gpt4o.yaml.
数据集： benchmarks/01-short-factual/dataset.json (以 SHA-256 固定)。
提示： 系统提示以 SHA-256 指纹化 — 保证 360 个单元全都使用同一个提示。裁判提示 SHA-256 也记录在每个评分 JSON 中。

产物 (out)

原始调用： runs/*.json (Foundry v1 载荷 + usage/latency 原文)。
评分： judge_runs_real/*.json (实测 gpt-4o 裁判，每单元 1 次)。
聚合： analysis.json (实测 cohort)。
图表/表： results/cost-curves/benchmark-01-*.png·.csv.

测量表面为 360 个单元(gpt-4o 60 + gpt-5.2 300，五档强度)。作为异常值排除的单元为 0 个 — 没有任何行因运营标记(冷启动·重试·输出截断)超过 3σ。评分由中立裁判 gpt-4o 对每个单元一次完成，360/360 成功。所有 JSON 都是真实 Azure Foundry v1 调用，没有一个 "fixture": true 标记。聚合用 --experiment-prefix exp001_short-factual_baseline 只选择实测 cohort 重新生成；跑两次字节相同(确定性聚合)。

预测对实测

预测原样成立的唯一位置

预测了什么

短事实任务不需要推理。质量在底部已经饱和；提高强度后质量仍不变，只增加成本。概括就是“不要提高强度”。

结果是什么

完全如此 — 没有反转。质量在 none 就已饱和(正确率 95%)，提高强度后只在 60 个样本中 1–2 个的范围内晃动。额外细节是：none 在质量上也超过了 gpt-4o，而推理 token 即使在 xhigh 也接近 0。

判定：预先登记得到确认。 多步(02)与工具(03)打开后故事都反转了(天花板里 none 是底部，混合里 low 是底部)，但只有这个底部按预测发生。因此这个实验充当本系列的对照组 — 用实测展示“推理不值得的位置”实际长什么样。

第一个信号

none 已经赢过 gpt-4o

下表中的美元数，是把方法论的 PAYG 公式应用于价格快照 pricing/azure-openai-payg-2026-05.yaml(访问日 2026-05-19)后得到，并从 analysis.md §5 重新引用，按每 1,000 次归一化。正确率是裁判分数 2(完全正确)的比例。

模型      努力     每1,000次请求    正确率           每1,000个正确答案
gpt-4o    —        $0.665        90.0% (54/60)    $0.739   ← 基线
gpt-5.2   none     $0.587        95.0% (57/60)    $0.618   ← 默认值
gpt-5.2   low      $0.589        96.7% (58/60)    $0.609
gpt-5.2   medium   $0.589        96.7% (58/60)    $0.609
gpt-5.2   high     $0.608        95.0% (57/60)    $0.640
gpt-5.2   xhigh    $0.598        95.0% (57/60)    $0.629

完全不开推理的 none 在两个轴上都领先 gpt-4o。 每 1,000 次请求 $0.587，比 gpt-4o($0.665)便宜 12%，正确率反而95% 对 90%更高。折算成每 1,000 个正确答案，是 $0.618 对 $0.739 — 便宜 16%。真正起作用的不是强度旋钮，而是模型替换本身。

none 以上几乎没有事情发生。low·medium 的正确率看起来是 96.7%(60 个中多 1 个)，但这是样本噪声范围(N=20·R=3，无置信区间)。high 按请求反而贵 +3.6%，正确率回到 95%。从 none 到 medium 基本上是同一个平面，再往上没有质量收益，只多成本。

失败藏身处

失败藏在哪里

90% 对 95% 这两个聚合数字看不出“在哪里”。按类型拆开，才会看到这个底部真正的纹理 — 大多数标签两边都是满分(2.0)，差异只出现在三个标签上。

类型              gpt-4o   5.2/none   5.2/low   5.2/high   5.2/xhigh
抽取(extraction)  1.75     2.00       2.00      2.00       2.00
摘要(summ.)       1.33     1.78       2.00      1.78       1.89
算术(arith-triv)  2.00     1.83       1.67      1.67       1.67
  • 抽取 — gpt-5.2 在底部补上的地方。 gpt-4o 在 12 个抽取样本中得 1.75，漏了几项；gpt-5.2 从不开推理的 none 开始已经是 2.00 满分。gpt-5.2 的 95% 领先 gpt-4o 的 90%，原因就在这里 — 不是推理，而是模型本身抽取得更稳。
  • 摘要 — low 达到顶点，之后回退。 gpt-4o 最弱的标签(1.33)。gpt-5.2 从 none 1.78 → low 2.00 上升，又在 medium·high 回到 1.78–1.89。提高强度并不会让摘要更好。
  • 算术 — 唯一 gpt-4o 获胜的位置，也是强度的反作用。 在 6 个细小算术样本上，gpt-4o 得 2.00 满分，而 gpt-5.2 从 none 1.83 下降到 low·high·xhigh 的 1.67。强度越高，越会把“1 加 1”反复咀嚼，反而踩空。推理不只是没有价值；在这里，它有负价值。

三个标签彼此抵消。gpt-5.2 在抽取·摘要上比 gpt-4o 赚回分数，在算术上略有损失，但净和在 none·low 最高。而且没有任何标签从提高强度中获益 — 这就是这个基准被称为 “Null case” 的原因。

第二个信号

提高强度，推理仍停在 0

为什么强度动不了质量？拆开 token 后答案很机械。gpt-5.2 的隐藏推理 token在 none·low·medium 平均为 0.00，在 high 为 1.35，在 xhigh 为 0.62。即使把强度拉到最大，模型实际使用的推理 token 也接近 0。短事实任务没有可规划的表面，强度旋钮没有接到任何地方。这与前面的单发基准(02)里推理 token 随强度上升正好相反。

所以成本也平坦。 每次请求输入固定为 224 token(提示字节相同)，可见输出只从 10–16 token 轻微增加。推理为 0，因此各强度间成本差只是从 none $0.587 到 high $0.608 — 每 1,000 次请求两美分多一点的晃动。

延迟也不跟随强度。 gpt-4o 为 1,494ms，gpt-5.2 无论强度如何都像噪声一样散在 1,410–1,713ms 之间(medium 比 none 更快)。在单发任务中，强度不是延迟的预测变量。

PTU 视角下结论没有反转，只是略微躺平。 gpt-5.2 none 的每请求 token 比 gpt-4o 多约 1%，吞吐为 0.99倍(约 −1%) — 按固定容量每分钟正确答案看，gpt-4o 略微领先。也就是说，PAYG 下 gpt-5.2 none 明确更便宜，PTU 下实质上是平手。不像前两个基准那样 PTU 拉开很大差距，这里两个模型几乎重叠。

透明度

连数字上的污点也原样留下

任何测量都不可能完全干净。这个基准留下的痕迹，我们不擦掉，而是原样写下 — 因为藏起来，后来的人会在同一个地方踩空。

  • 替换为实测。 这个底部一开始是以合成 fixture(exp008_short-factual_fixture)发布的。形状合理，但不是测量。随本文一起，我们把那个位置换成了实测 cohort — 用 --experiment-prefix exp001_short-factual_baseline 重新生成 analysis.json·图·表。fixture 没有删除，仍作为无需凭据的离线复现脚手架保留在仓库里，但从发布数字来源中移除。fixture 使用的 minimal 强度会被真实部署拒绝，因此实测 schema 的底部是 none。
  • 异常值 0 个。 360 个单元里没有任何行因 3σ·运营标记被排除(远低于方法论 10% 警戒线)。这是聚合掩码没有介入的干净表面。
  • 没有确定性答案表。 这个数据集没有用于规则对照的答案表，因此质量只能由裁判分数判定。所以“正确率”被二值化为裁判分数 2(完全正确)的比例，部分正确(1)从分母中剔除。明确这个选择，是为了说明这个核心数字是如何算出来的。
  • 算术的逆转。 gpt-5.2 输给 gpt-4o 的唯一标签(算术)没有隐藏，而是原样写在§失败藏身处 — 为了说明底部的结论不是“gpt-5.2 赢过一切”，而是“强度不值得”。

限制

可以相信到哪里

这个结果来自一个短事实任务集、一个价格快照、特定模型组合与量规下的小规模聚合。比起数字本身，借鉴方法更稳妥。

  • 样本。 N=20 · R=3。在这个样本量下，不主张置信区间或统计显著性 — none·low·medium 的正确率差异(60 个中 1 个)应读作噪声。方向性结论(“强度不值得”)稳健，但绝对幅度需按小样本谨慎看待。
  • 评分。 LLM-as-judge(gpt-4o)。没有确定性答案表，质量完全依赖裁判。裁判提示 SHA-256 记录在评分 JSON 中以监控漂移，但裁判自身偏差仍然可能存在。
  • 价格。 单一快照。如果费率或 usage schema 改变，应从同一原始材料重新计算成本。
  • PTU。 吞吐是基于 token 的估算，不是真实 PTU 负载测试。这个底部里两种模型吞吐在约 1% 内重叠，所以 PTU 结论尤其要谨慎阅读。

所以默认值是什么

短事实任务的默认值是 gpt-5.2 effort=none。完全不开推理时，按请求比 gpt-4o 便宜 12%、按正确答案便宜 16%，正确率反而 95% 对 90% 更高。从 none 到 medium 实质上是同一平面，使用 low·medium 也无妨，但额外收益在样本噪声内。high 以上推理 token 仍接近 0，却只增加成本，因此弃用。PTU 视角下 gpt-4o 略微领先，实质上平手 — 起作用的是模型替换，不是强度。
