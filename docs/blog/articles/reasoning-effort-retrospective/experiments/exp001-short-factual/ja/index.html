exp001 — 短い事実回答に推論は必要だったのか

文 Hyeonsang Jeon · Global Black Belt, Cloud & AI Apps

三つのベンチマークの床から置いた。抽出·整形·分類·音訳·算術 — 一度で答えが出る短い事実回答。ここで推論努力度を上げるのは、“1 足す 1”に会議を招集することに近い。予測は単純だった。推論は割に合わない。

このノートが前の二編と違う点が一つある。合成フィクスチャではなく実測である。360セルすべてを Azure Foundry v1 で実際に呼び出し、中立ジャッジ gpt-4o でセルごとに一回ずつ 360/360 採点した。"fixture": true マーカーはどこにもない。だからこの床は ‘それらしく合成された床’ ではなく、測定された床である。

測定は予測をそのまま確認した — 三つのベンチマークのうち、事前登録が反転なしに当たった唯一の場所だ。ただし実測が添えてくれた細部が二つあった。一つ、gpt-5.2 は推論を一切有効にしない none で、すでに gpt-4o を品質でも上回った。二つ、努力度を xhigh まで上げても隠れた推論トークンは0 近くに張り付いた — 努力度ダイヤルがどこにも配線されていない場所。このノートはその床を設計 → 入力 → 成果物 → 予測対実測 → 失敗が隠れた場所 → 判断として振り返る — 次の人が同じ道で迷いにくいように。

設計

最も単純なタスクから

検証すべき問いは一つに絞った。 一度で答えが出る短い事実回答タスク — 三つのベンチマークで最も易しいケース — で、gpt-5.2 に考える余地(推論の努力度)をより与えるほど答えは良くなり、その分の価値があるのか。だから見るべきものも二つだけだ — 努力度を上げると(1) 品質は上がるか、(2) コストは上がるか。 お金は二つの角度から読む。使った分だけ払う PAYG では “正答一つ当たりいくら” を、容量をまるごと借りる PTU では “同じ容量で毎分いくつ正解できるか” を見る。予想される答えは “いいえ” で、この実験の役割は、その “いいえ” の床を当て推量ではなく実測で固定することだ。

何で測るか — データセット。 凍結した著作サンプル 20個(sf_01…sf_20)で、抽出·整形·分類·列挙·音訳·正規化·単位換算·簡単な算術·要約がまんべんなく混ざっている。こうしたタスクは “唯一の正答” を表で固定しにくい。そこで正答表の代わりに expected_output_shape(答えの形)と quality_rubric_notes(採点基準)だけを固定し、品質は中立ジャッジのモデル gpt-4o が答案を読んで 0·1·2 で採点するようにした。採点の根拠まで原資料にそのまま残す。

変えるのは一つだけ — gpt-5.2 の推論の努力度(reasoning.effort)を none(オフ)から low · medium · high · xhigh まで五段階で上げていく。ほかの条件はすべて固定だ。横には推論ダイヤルがそもそもない gpt-4o をベースラインとして並べる。まぐれを取り除くため、各 (サンプル × モデル × 努力度) セルは三回ずつ(R=3)回す。

事前登録予測

短い事実回答タスクには推論表面が要らない。品質は最も低い努力度ですでに飽和し、努力度を上げると品質はそのまま、コスト·遅延·トークンだけが増える。つまり “努力度を上げるな” が答えだ。

この実験の役割

三つのベンチマークの床アンカー。多段階(02)の天井とツールエージェント(03)の混合を測る前に、“推論が本当に必要ない場所” がどんな形なのかを実測で固定する。後続実験の反転は、この床との対比で意味を持つ。

予測対実測

予測がそのまま当たった唯一の場所

何を予測したか

短い事実回答タスクに推論は要らない。品質は床ですでに飽和し、努力度を上げても品質はそのままでコストだけが増える。要するに “努力度を上げるな。”

何が出たか

まさにその通りだった — 反転はない。品質は none ですでに飽和(正答率 95%)し、努力度を上げても 60件中 1–2件の範囲でしか揺れなかった。添えられた細部: none が gpt-4o を品質でも上回り、推論トークンは xhigh でも 0 近くだった。

判定: 事前登録の確認。 多段階(02)とツール(03)は蓋を開けると物語がひっくり返ったが(天井は none が床、混合は low が床)、この床だけは予測どおりだった。だからこの実験はシリーズの対照群の役割を果たす — “推論が割に合わない場所” が実際にどんな形なのかを実測で示すアンカーである。

第一のシグナル

none がすでに gpt-4o に勝っていた

下の表のドルは価格スナップショット pricing/azure-openai-payg-2026-05.yaml(アクセス日 2026-05-19)に方法論の PAYG 式を適用した値で、analysis.md §5 から再引用し、1,000件当たりに正規化した。正答率はジャッジスコア 2(完全正答)の比率である。

モデル      努力度   1,000リクエスト当たり 正答率           正答1,000件当たり
gpt-4o    —        $0.665        90.0% (54/60)    $0.739   ← ベースライン
gpt-5.2   none     $0.587        95.0% (57/60)    $0.618   ← デフォルト
gpt-5.2   low      $0.589        96.7% (58/60)    $0.609
gpt-5.2   medium   $0.589        96.7% (58/60)    $0.609
gpt-5.2   high     $0.608        95.0% (57/60)    $0.640
gpt-5.2   xhigh    $0.598        95.0% (57/60)    $0.629

推論を一切有効にしていない none が、二つの軸のどちらでも gpt-4o を上回る。 リクエスト 1,000件当たり $0.587 で gpt-4o($0.665) より12% 安く、正答率はむしろ 95% 対 90% と高い。正答 1,000件当たりに換算すると $0.618 対 $0.739 — 16% 安い。言い換えれば、ここで割に合ったのは “努力度を上げたこと” ではなく、モデルを入れ替えたことそのものだ。努力度ダイヤルはまだ何もしていない。

そして none の上では何も起きない。low·medium は正答率が 96.7% と一段高く見えるが、60件中たった 1件の差だ — 標本が小さく(N=20·R=3、信頼区間なし)ノイズと見るべき大きさである。high まで上げるとコストはむしろリクエスト当たり +3.6% 跳ね、正答率は 95% に戻る。結局 none から medium までは実質一つの平面で、その上は品質なしにコストだけが乗る。

失敗が隠れた場所

失敗はどこに隠れたか

90% 対 95% という集計数字二つだけでは、“どこで”差がついたのか見えない。そこでタスクの型別にスコアを分けてみた。すると、ほとんどの型は両モデルとも満点(2.0)で、差はたった三か所 — 抽出·要約·算術 — だけに出ていた。この三つがこの実験の核心だ。

型                gpt-4o   5.2/none   5.2/low   5.2/high   5.2/xhigh
抽出(extraction)  1.75     2.00       2.00      2.00       2.00
要約(summ.)       1.33     1.78       2.00      1.78       1.89
算術(arith-triv)  2.00     1.83       1.67      1.67       1.67
  • 抽出 — gpt-5.2 が床で埋めた場所。 gpt-4o は抽出 12件で 1.75 といくつか落としたが、gpt-5.2 は推論を有効にしない none からすでに 2.00 満点だ。gpt-5.2 の 95% が gpt-4o の 90% を上回った理由はここにある — 推論ではなく、モデル自体が抽出をより安定して行う。
  • 要約 — low で頂点、その後後退。 gpt-4o が最も弱いタグ(1.33)。gpt-5.2 は none 1.78 → low 2.00 へ上がったあと、medium·high で 1.78–1.89 へ戻って下がる。努力度を上げても要約は良くならない。
  • 算術 — 唯一 gpt-4o が勝った場所、そして努力度の逆効果。 些細な算術 6件で gpt-4o は 2.00 満点だが、gpt-5.2 は none 1.83 から low·high·xhigh 1.67 へ下がる。努力度を上げるほど “1 足す 1” を過剰に考え込み、かえって踏み外すのだ。推論が割に合わないどころか、ここでは負の値を持つ。

三つのタグが互いを相殺する。gpt-5.2 は抽出·要約で gpt-4o より稼ぎ、算術で少し失うが、純合計は none·low で最高だ。そしてどのタグでも努力度を上げて得をした場所はない — このベンチマークが “Null case” である理由だ。

第二のシグナル

努力度を上げても推論は 0 にとどまる

では、なぜ努力度を上げても品質はびくともしないのか。 トークンを分解すると機械的な答えが出る。gpt-5.2 が表に出さずに使う推論トークンは none·low·medium で平均 0.00、high で 1.35、xhigh で 0.62 だ。つまり 努力度を最大まで上げても、モデルが実際に “考える” のに使うトークンは 0 近くである。短い事実回答タスクは一度で答えが出るので計画したり見直したりする余地がそもそもなく、努力度ダイヤルをいくら回してもつながる先がない。努力度に沿って推論トークンが実際に増えていった多段階タスク(02)とは正反対だ。

推論が 0 なので、コストもそれにつれて平らだ。 リクエスト当たり入力は 224トークンに固定され(プロンプトがバイトまで同一)、見える出力も 10–16トークンとほとんど増えない。だから努力度別のコスト差といっても none $0.587 から high $0.608 — リクエスト 1,000件当たり2セント余りの細かな揺れでしかない。

応答にかかる時間(遅延)も努力度に従わない。 gpt-4o 1,494ms、gpt-5.2 は努力度と無関係に 1,410–1,713ms の間でノイズのように散らばる — medium が none より速いほどだ。一度で答えるタスクでは、努力度から速度は予測できない。

容量をまるごと借りる PTU レンズでは、結論はひっくり返らないが少し寝る。 gpt-5.2 none はリクエスト当たりトークンを gpt-4o より約 1% 多く使うため、スループットは 0.99倍(約 −1%) だ — 同じ容量で毎分正解できる数では gpt-4o がわずかに先行する。まとめると 使った分だけ払う PAYG では gpt-5.2 none が明確に安く、容量を借りる PTU では実質引き分けである。前の二つのベンチマークのように PTU が大きく開く図ではなく、二つのモデルはほとんど重なる。

透明性

数字に残った汚れまでそのまま

どんな測定も完全にきれいではない。このベンチマークが残した跡を消さず、そのまま書いておく — 隠すと次の人が同じ場所で踏み外すからだ。

  • 実測への置き換え。 この床は当初、合成フィクスチャ(exp008_short-factual_fixture)として公開されていた。それらしい形ではあったが、測定ではなかった。このノートとともに、その場所を実測コホートに置き換えた — analysis.json·図表·表を --experiment-prefix exp001_short-factual_baseline で再生成した。フィクスチャは削除せず、資格情報なしのオフライン再現用の足場としてリポジトリに残すが、公開数値の出典からは外した。フィクスチャが使っていた minimal 努力度は実デプロイが拒否する値なので、実測スキーマでは none が床である。
  • 外れ値 0件。 360セルのどこでも 3σ·運用フラグで除外された行はない(方法論の警告線 10% を大きく下回る)。集計マスクが介入していない、きれいな表面である。
  • 決定的な正答表なし。 このデータセットにはルール照合用の正答表がないため、品質をジャッジスコアだけで判定する。だから “正答率” はジャッジスコア 2(完全正答)の比率として二値化し、部分正答(1)は分母から外した。この選択を明示し、ヘッドラインがどう計算されたかを示す。
  • 算術の逆転。 gpt-5.2 が gpt-4o に負けた唯一のタグ(算術)を隠さず、§失敗が隠れた場所にそのまま書いた — 床の結論が “gpt-5.2 がすべてに勝つ” ではなく、“努力度が割に合わない” であることを明確にするためだ。

限界

どこまで信じられるか

この結果は、一つの短い事実回答タスクセット、一つの価格スナップショット、特定のモデル組み合わせとルーブリックから出た小規模な集計値です。数字そのものより、方法を持ち帰るほうが安全です。

  • 標本。 N=20 · R=3。この標本サイズでは信頼区間や統計的有意性を主張しない — none·low·medium の正答率差(60件中 1件)はノイズとして読むべきだ。方向性の結論(“努力度は割に合わない”)は堅いが、絶対値の大きさは小標本として注意。
  • 採点。 LLM-as-judge(gpt-4o)。決定的な正答表がないため、品質は完全にジャッジに依存する。ジャッジプロンプト SHA-256 を採点 JSON に記録してドリフトを監視するが、ジャッジ自体の偏りの可能性は残る。
  • 価格。 単一スナップショット。料率や使用量スキーマが変われば、同じ原資料からコストを再計算する必要がある。
  • PTU。 スループットはトークンベースの推定であり、ライブ PTU 負荷テストではない。この床では二つのモデルのスループットが約 1% 内で重なるため、PTU の結論は特に慎重に読むべきだ。

だから何をデフォルトにするか

短い事実回答タスクのデフォルトは gpt-5.2 effort=none である。推論を一切有効にしないまま、リクエスト当たり gpt-4o より 12%·正答当たり 16% 安く、正答率はむしろ 95% 対 90% と高い。none から medium までは実質一つの平面なので low·medium を使っても構わないが、追加で得られるものは標本ノイズの中にある。high 以上は推論トークンがなお 0 近くなのにコストだけが上がるため捨てる。PTU レンズでは gpt-4o がわずかに先行し、実質引き分け — 割に合ったのは努力度ではなくモデルの入れ替えだった。
