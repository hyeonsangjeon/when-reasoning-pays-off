exp001 — 短い事実回答に推論は必要だったのか

執筆: Hyeonsang Jeon · Global Black Belt, Cloud & AI Apps

最初に、三つのベンチマークの下限を定めました。抽出·整形·分類·音訳·算術のいずれも、一度で答えが出る短い事実回答です。ここで推論強度を上げるのは、「1 足す 1」を解くために会議を開くようなものです。推論は割に合わないと予測しました。

このノートは、合成 fixture ではなく実測に基づいています。360セルすべてを Azure Foundry v1 で実際に呼び出し、評価モデル gpt-4o でセルごとに一回、360/360 採点しました。"fixture": true マーカーはありません。つまり、下限も実際の呼び出しから測定した値です。

実測結果は、強度を上げても品質は改善しないという事前登録した予測の中核部分と一致しました。三つのベンチマークで、この品質予測が覆らなかった唯一のケースです。さらに二点を確認しました。gpt-5.2 は推論を無効にした none ですでに gpt-4o を品質でも上回り、強度を xhigh まで上げても隠れた推論トークンは0 近くでした。この結果を、設計 → 入力 → 成果物 → 予測と実測 → 失敗箇所 → 判断の順に振り返ります。

この記事で分かること

推論強度を上げる価値はあるか

新しいモデルには、推論強度という設定があります。回答前にモデルが内部でどこまで推論するかを調整する値です。高いほど賢くなりそうに見えますが、回答が改善しなくても、強度を上げることでコストや時間が増える可能性があります。「念のため高くする」ことが安全とは限りません。

そこで、値の抽出、整形、分類、簡単な計算など、一度で答えが出る短い事実回答タスクから始めました。多くのサービスで頻繁に処理される仕事です。この範囲で強度が効果を持たないなら、理由なく強度を上げる運用は不要な内部計算や待ち時間を招く可能性があります。

本ノートでは、推論強度が費用に見合う場合と無駄になる場合を、最も単純なケースの実測から切り分けます。この種のタスクを扱うなら、結果をそのままデフォルトの候補にできます。また、多段階(02)とツールエージェント(03)の結果を比較する際の下限にもなります。

設計

最も単純なタスクから

なぜ測定したのか。 「モデルにもっと考えさせれば、回答も改善する」という考えは一般的です。そのため、判断に迷うと推論強度を高めに設定しがちです。しかし、回答が改善しなくても、強度を上げることでコストや時間が増える可能性があります。この考えが正しいか、推測ではなくデータで確かめました。

考えを仮説にしました。 最も易しいタスクでは、推論を増やしても回答は改善せず、追加コストが生じても正当化できないという仮説です。反証条件も明確です。強度を上げるほど正答率が明確に上がれば、仮説は崩れます。 一方、正答率が横ばいなら仮説は残ります。この判定を実測で下すために実験を設計しました。

最も易しいタスクから始めた理由。 ほかの結果と比較する基準が必要だったためです。難しい問題で推論が割に合うと示すには、まず割に合わない範囲の特性を実測で確定する必要があります。この下限が、多段階(02)とツールエージェント(03)の結果を判断する基準点になります。

検証する問いは一つです。 一度で答えが出る短い事実回答で、gpt-5.2 の推論強度を上げると品質が改善し、そのコストに見合うのでしょうか。確認するのは、(1) 品質が上がるか、(2) コストが上がるかの二点です。PAYG では「正答一つ当たりのコスト」を、PTU では「同じ容量での分当たり正答」を評価します。事前登録した予測は「いいえ」でした。この実験は、その下限を実測で確定します。

データセット。 凍結した著作サンプル 20個(sf_01…sf_20)を使用しました。抽出·整形·分類·列挙·音訳·正規化·単位換算·簡単な算術·要約を含みます。唯一の正答を表で固定しにくいため、expected_output_shape(回答の形式)と quality_rubric_notes(採点基準)を固定しました。品質は評価モデル gpt-4o が回答を 0·1·2 で採点し、その根拠も原資料に記録しています。

変更する変数は一つです。 gpt-5.2 の推論強度(reasoning.effort)を none(オフ)から low · medium · high · xhigh までの五段階で比較しました。ほかの条件は固定し、推論強度の設定がない gpt-4o を基準としました。各 (サンプル × モデル × 強度) セルを三回ずつ(R=3)実行しています。

事前登録した予測

短い事実回答には推論が不要で、品質は最も低い強度ですでに頭打ちになります。強度を上げても品質は変わらず、追加のコスト·レイテンシ（応答時間）·トークンが生じても正当化できないため、「強度を上げない」が判断です。

この実験の役割

三つのベンチマークの下限です。none を基準に、多段階(02)の上限とツールエージェント(03)の混合ケースを測る前に、推論が不要な範囲の特性を実測で確定し、後続実験の基準とします。

予測と実測

品質に関する事前予測と一致

事前登録した予測

短い事実回答に推論は不要です。品質は最も低い強度ですでに頭打ちとなり、強度を上げても品質は変わらず、追加支出を正当化できないと予測しました。

実測結果

品質に関する予測は一致し、反転はありませんでした。品質は none ですでに頭打ち(正答率 95%)となり、強度を上げても 60件中 1–2件の範囲でしか変動しませんでした。さらに、none が gpt-4o を品質でも上回り、推論トークンは xhigh でも 0 近くでした。コストとレイテンシは強度全体でほぼ横ばいでした。

判定: 品質に関する事前予測と一致。 多段階(02)とツールエージェント(03)では予測が覆りましたが、この none から low までの下限域では品質予測と一致し、正答率は 95% 対 90% でした。「推論が割に合わない範囲」の実測特性を示す、シリーズの基準点です。

第一のシグナル

none がすでに gpt-4o を上回った

表のドル額は、価格スナップショット pricing/azure-openai-payg-2026-05.yaml(アクセス日 2026-05-19)に方法論の PAYG 式を適用した値です。analysis.md §5 から再引用し、1,000件当たりに正規化しています。正答率は評価スコア 2(完全正答)の比率です。

モデル      推論強度  1,000リクエスト当たり 正答率           正答1,000件当たり
gpt-4o    —        $0.665        90.0% (54/60)    $0.739   ← ベースライン
gpt-5.2   none     $0.587        95.0% (57/60)    $0.618   ← デフォルト
gpt-5.2   low      $0.589        96.7% (58/60)    $0.609
gpt-5.2   medium   $0.589        96.7% (58/60)    $0.609
gpt-5.2   high     $0.608        95.0% (57/60)    $0.640
gpt-5.2   xhigh    $0.598        95.0% (57/60)    $0.629

推論を無効にした none が、コストと品質の両方で gpt-4o を上回りました。 リクエスト 1,000件当たり $0.587 で gpt-4o($0.665)より12% 安く、正答率は 95% 対 90% でした。正答 1,000件当たりでは $0.618 対 $0.739 で、16% 安い結果です。効果があったのは強度の引き上げではなく、モデルの変更でした。

none より上では明確な改善がありませんでした。low·medium の正答率は 96.7% ですが、差は 60件中 1件です。標本が小さく(N=20·R=3、信頼区間なし)、ノイズとして扱うべき大きさです。high ではリクエスト当たりのコストが +3.6% 上がり、正答率は 95% に戻りました。none から medium まではほぼ平坦で、それ以上では品質を改善せずコストだけが増えました。

失敗箇所

差が生じたタスク

90% 対 95% という集計値だけでは、差が生じた場所は分かりません。タスクの型別に分けると、ほとんどは両モデルとも満点(2.0)で、差は抽出·要約·算術の三か所に限られました。

型                gpt-4o   5.2/none   5.2/low   5.2/high   5.2/xhigh
抽出(extraction)  1.75     2.00       2.00      2.00       2.00
要約(summ.)       1.33     1.78       2.00      1.78       1.89
算術(arith-triv)  2.00     1.83       1.67      1.67       1.67
  • 抽出 — gpt-5.2 が下限で改善。 gpt-4o は抽出 12件で 1.75 でしたが、gpt-5.2 は推論を無効にした none ですでに 2.00 でした。gpt-5.2 の正答率が gpt-4o を上回った主因です。強度ではなく、モデル自体の差でした。
  • 要約 — low で最大、その後低下。 gpt-4o が最も弱いタグ(1.33)でした。gpt-5.2 は none 1.78 → low 2.00 と上がりましたが、medium·high では 1.78–1.89 に低下しました。強度を上げ続けても要約は改善しませんでした。
  • 算術 — 唯一 gpt-4o が優位。 簡単な算術 6件では gpt-4o が 2.00、gpt-5.2 は none 1.83 から low·high·xhigh 1.67 に低下しました。この型では、強度の引き上げが逆効果でした。

三つのタグの差は相殺されます。gpt-5.2 は抽出·要約で gpt-4o を上回り、算術では下回りました。合計では none·low が最良でしたが、どのタグでも高い強度による一貫した利得はありません。これが、推論に効果がない “Null case” と位置付ける理由です。

第二のシグナル

強度を上げても推論トークンはほぼ 0

品質が変わらない理由は、トークン構成から確認できます。 gpt-5.2 が内部で使う推論トークンは、none·low·medium で平均 0.00、high で 1.35、xhigh で 0.62 でした。強度を最大まで上げても実際の推論トークンは 0 近くです。短い事実回答には、計画や見直しを行う余地がほとんどありません。強度に応じて推論トークンが増えた多段階タスク(02)とは対照的でした。

コストもほぼ平らです。 リクエスト当たりの入力は 224トークンに固定され(プロンプトがバイト単位で同一)、表示される出力も 10–16トークンでした。強度別コストは none $0.587 から high $0.608 までで、リクエスト 1,000件当たり2セント余りの差です。

レイテンシ（応答時間）も強度に連動しませんでした。 gpt-4o は 1,494ms、gpt-5.2 は強度と関係なく 1,410–1,713ms の範囲でした。medium が none より速く、一度で答えるタスクでは強度から速度を予測できませんでした。

PTU では結論がやや弱まります。 gpt-5.2 none はリクエスト当たりのトークンが gpt-4o より約 1% 多く、スループットは 0.99倍(約 −1%)でした。同じ容量での分当たり正答では gpt-4o がわずかに先行します。したがって、PAYG では gpt-5.2 none が明確に安く、PTU では実質的に同等です。

透明性

測定上の例外も開示する

どの測定にも例外やノイズはあります。このベンチマークで生じた事象を、再検証できるように省略せず記録します。

  • 実測への置き換え。 この下限は当初、合成 fixture(exp008_short-factual_fixture)として公開されていましたが、測定値ではありませんでした。本ノートでは実測データに置き換え、analysis.json·図表·表を --experiment-prefix exp001_short-factual_baseline で再生成しました。fixture は資格情報なしでオフライン再現するために残していますが、公開数値の出典からは除外しました。fixture の minimal 強度は実デプロイが拒否するため、実測データの下限は none です。
  • 外れ値 0件。 360セルのうち、3σ または運用上の問題マーカー（コールドスタート・リトライ・出力打ち切り）により除外した行はありません(方法論の警告線 10% を大きく下回ります)。
  • 決定的な正答表なし。 ルールで照合できる正答表がないため、品質は評価スコアだけで判定しました。「正答率」は評価スコア 2(完全正答)の比率で、部分正答(1)は通過率に含めません。この定義を明示して、見出しの数値の算出方法を示しています。
  • 算術の逆転。 gpt-5.2 が gpt-4o を下回った唯一のタグ(算術)も開示しました。この結果により、結論は「gpt-5.2 がすべてに勝つ」ではなく、「推論強度が割に合わない」であることが分かります。

限界

どこまで信じられるか

この結果は、一つの短い事実回答タスクセット、一つの価格スナップショット、特定のモデルと採点基準に基づく小規模な集計です。絶対値をそのまま一般化するより、方法を再利用するほうが安全です。

  • 標本。 N=20 · R=3 で、信頼区間や統計的有意性は主張しません。none·low·medium の正答率差(60件中 1件)はノイズとして扱います。方向性の結論(「強度は割に合わない」)は明確ですが、絶対値は小標本の結果として慎重に解釈します。
  • 採点。 評価モデル(gpt-4o)を使用しました。決定的な正答表がないため、品質は評価モデルに依存します。評価プロンプトのデジタル指紋(SHA-256)を採点 JSON に記録しましたが、評価モデル自体の偏りは残り得ます。
  • 価格。 単一スナップショット。料率や課金方式が変われば、同じ原資料からコストを再計算する必要があります。
  • PTU。 スループットはトークンベースの推定であり、ライブ PTU 負荷テストの実測ではありません。両モデルの差が約 1% 以内のため、PTU の結論は特に慎重に解釈します。

デフォルト

短い事実回答のデフォルトは gpt-5.2 effort=none です。推論を無効にしたまま、gpt-4o よりリクエスト当たり 12%、正答当たり 16% 安く、正答率は 95% 対 90% でした。none から medium まではほぼ平坦で、low を含む差は標本ノイズの範囲です。high 以上では推論トークンがなお 0 近くでもコストが上がるため、採用しません。PTU のスループット比は 1 に近く、gpt-4o がわずかに先行するものの、実質的に同等です。割に合ったのは強度ではなく、モデルの変更でした。
