exp001 — Did short answers need reasoning?

By Hyeonsang Jeon · Global Black Belt, Cloud & AI Apps

We laid the floor of the three benchmarks first. Extraction, formatting, classification, transliteration, arithmetic — short factual tasks that answer in a single pass. Raising the reasoning effort here is close to convening a committee over “1 plus 1.” The prediction was simple. Reasoning does not pay.

There is one way this note differs from the previous two. It is measured, not a synthetic fixture. We made all 360 calls through the Azure OpenAI v1 API in Microsoft Foundry and graded 360/360, once per cell, with the neutral judge gpt-4o. Nowhere is there a "fixture": true marker. So this floor is not a ‘plausibly synthesized floor’ but a measured floor.

The measurement confirmed the prediction exactly — the only place across the three benchmarks where the prediction held without a reversal. Measurement did add two details. First, gpt-5.2 already beat gpt-4o on quality too at none, with no reasoning switched on. Second, even raising effort to xhigh, the hidden reasoning tokens stayed stuck near 0 — a place where the effort dial connects to nothing. This note retraces that floor as design → inputs → artifacts → prediction vs. measurement → where failure hid → decision — so the next person wanders less on the same road.

Why read this

That dial — is it worth turning up?

Wire up a new model and somewhere in the settings sits a dial called reasoning effort — how much the model mulls a question over before it answers. Turning it up feels like it should make the model smarter, so when in doubt it is easy to just leave it high. But turning the dial up costs real money and time whether or not the answer improves. So ‘no harm in trying’ may not hold.

So we started at the easiest place. Short factual tasks that answer in a single pass — pulling out a value, fixing a format, classifying, simple arithmetic — are also among the most common tasks services handle. If the dial spins for nothing here, the habit of ‘not sure, so crank it up’ just grows the monthly bill.

This note uses measurement, starting from the easiest case, to settle when that dial earns its cost and when it is wasted effort. If your work lives here, the conclusion becomes your default. And if it doesn’t, don’t worry — the reversals in the multi-step (02) and tool (03) notes only mean something measured against this floor.

Design

Start with the simplest task

Why measure this at all? There is a common belief: ‘make the model think more and the answer gets better.’ It sounds right, so when in doubt many teams just turn the reasoning dial up — figuring it can’t hurt. But turning it up costs more money and more time, whether or not the answer improves. So ‘it can’t hurt’ may not be true. We wanted to check that belief with data, not a hunch.

So we turned the belief into a hypothesis. It reads: on the easiest tasks, thinking harder doesn’t make the answer better — it only raises the cost. A useful hypothesis needs a line that says ‘if this happens, I was wrong.’ Here that line is clear. If accuracy climbs clearly as effort rises, the hypothesis breaks on the spot. If accuracy stays flat as effort rises, it holds. We built this experiment to settle that by measurement, not by guessing.

Why start with the easiest task? Because you have to plant a reference point before you can trust the rest. To show that ‘reasoning pays off’ on hard problems, you first have to pin down, by measurement, what ‘reasoning does not pay off’ actually looks like. With that floor in hand, the reversals in the multi-step (02) and tool (03) notes read as real reversals. That makes this note the series’ starting line and reference point.

We boiled the question down to one. On short factual tasks that answer in a single pass — the easiest case across the three benchmarks — does giving gpt-5.2 more room to think (reasoning effort) make the answers better, and if so, enough to justify the bill? So there are only two things to watch — as effort rises, does (1) quality go up, and (2) cost go up? We read the money through two lenses: pay-as-you-go pricing (PAYG) asks “dollars per correct answer,” while the provisioned throughput unit (PTU) model — renting a block of capacity outright — asks “how many correct answers per minute from that same capacity.” The expected answer was “no,” and this experiment's job is to nail that “no” floor down with measurement rather than a guess.

What we measure with — the dataset. Twenty frozen authored samples (sf_01…sf_20), evenly mixing extraction, formatting, classification, enumeration, transliteration, normalization, unit conversion, simple arithmetic, and summarization. For tasks like these you can't pin down “the one right answer” in a table. So instead of an answer key we fix only expected_output_shape (the shape of the answer) and quality_rubric_notes (the grading criteria), and let a neutral judge model, gpt-4o, read each answer and score it 0·1·2. Even the reasoning behind each score is kept in the raw data.

Only one thing changes — we raise gpt-5.2's reasoning effort (reasoning.effort) through five steps, from none (off) up to low · medium · high · xhigh. Everything else is held fixed. Beside it we stand a gpt-4o baseline, which has no reasoning dial at all. To filter out flukes, each (sample × model × effort) cell is run three times (R=3).

Pre-registered prediction

Short factual tasks need no reasoning. Quality is already saturated at the lowest effort, and raising effort only adds cost, latency, and tokens while quality stays flat. In short, the answer is “don't raise the effort.”

This experiment's role

The floor anchor of the three benchmarks. Before measuring the ceiling of multi-step (02) and the mix of the tool agent (03), we establish through measurement what “a place that truly needs no reasoning” looks like. The reversals in the later experiments earn their meaning against this floor.

Prediction vs. measurement

The only place the prediction held exactly

What we predicted

Short factual tasks need no reasoning. Quality saturates already at the floor, and raising effort only adds cost while quality stays flat. In short: “don't raise the effort.”

What came out

Exactly that — no reversal. Quality was already saturated at none (95% accuracy) and wobbled only within 1–2 of 60 as effort rose. The added detail: none beat gpt-4o on quality too, and reasoning tokens stayed near 0 even at xhigh.

Verdict: the prediction held exactly. Multi-step (02) and tools (03) flipped the story once opened (the ceiling's floor was none, the mix's floor was low), but this floor alone went as predicted. So this experiment serves as the series' reference point — an anchor that shows through measurement what “a place where reasoning doesn't pay” actually looks like.

First signal

none already beat gpt-4o

The dollars in the table below apply the methodology's PAYG formula to the price snapshot pricing/azure-openai-payg-2026-05.yaml (accessed 2026-05-19); they are re-cited from analysis.md §5 and normalized per 1,000. Accuracy is the share of judge score 2 (fully correct).

Model     Effort   Per 1,000 req   Accuracy         Per 1,000 correct
gpt-4o    —        $0.665          90.0% (54/60)    $0.739   ← baseline
gpt-5.2   none     $0.587          95.0% (57/60)    $0.618   ← default
gpt-5.2   low      $0.589          96.7% (58/60)    $0.609
gpt-5.2   medium   $0.589          96.7% (58/60)    $0.609
gpt-5.2   high     $0.608          95.0% (57/60)    $0.640
gpt-5.2   xhigh    $0.598          95.0% (57/60)    $0.629

none, with not a shred of reasoning switched on, leads gpt-4o on both axes. At $0.587 per 1,000 requests it is 12% cheaper than gpt-4o ($0.665), and its accuracy is actually higher, 95% vs. 90%. Converted to per 1,000 correct, $0.618 vs. $0.739 — 16% cheaper. In other words, what paid off here was not “raising the effort” but swapping the model itself. The effort dial has done nothing yet.

And above none, nothing happens. low·medium look a notch higher at 96.7% accuracy, but that's just one more out of 60 — with such a small sample (N=20·R=3, no confidence intervals) it should be read as noise. At high, however, cost climbs +3.6% per request while accuracy falls back to 95%. In the end, from none through medium is effectively flat, and above it you only stack cost without quality.

Where failure hid

Where did the failures hide

The two aggregate numbers, 90% vs. 95%, don't tell you “where” the gap opened. So we split the scores by task type. It turned out most types are full marks (2.0) on both models, and the difference shows in just three places — extraction, summarization, and arithmetic. These three are the heart of this experiment.

Type              gpt-4o   5.2/none   5.2/low   5.2/high   5.2/xhigh
extraction        1.75     2.00       2.00      2.00       2.00
summarization     1.33     1.78       2.00      1.78       1.89
arith-trivial     2.00     1.83       1.67      1.67       1.67
  • Extraction — where gpt-5.2 filled the floor. gpt-4o missed a few of the 12 extraction items at 1.75, whereas gpt-5.2 is already at a full 2.00 from none, with no reasoning on. This is exactly why gpt-5.2's 95% leads gpt-4o's 90% — it's the model itself, not reasoning, that does extraction more reliably.
  • Summarization — peaks at low, then retreats. gpt-4o's weakest tag (1.33). gpt-5.2 climbs from none 1.78 → low 2.00, then comes back down to 1.78–1.89 at medium·high. Raising effort does not make summaries better.
  • Arithmetic — the only place gpt-4o won, and effort's backfire. On the 6 trivial arithmetic items gpt-4o scores a full 2.00, while gpt-5.2 falls from none 1.83 to 1.67 at low·high·xhigh. The more you raise effort, the more it over-chews “1 plus 1” and trips. Here reasoning doesn't just fail to pay — the payoff is negative.

The three tags offset one another. gpt-5.2 gains over gpt-4o on extraction and summarization and loses a little on arithmetic, but the total across all three is highest at none·low. And in no tag did raising effort pay off — which is why this benchmark is the “Null case” (the case where reasoning earns nothing).

Second signal

Raise the effort, reasoning stays at zero

So why doesn't quality budge when you raise the effort? Break the tokens down and the answer is mechanical. The reasoning tokens gpt-5.2 spends out of sight average 0.00 at none·low·medium, 1.35 at high, and 0.62 at xhigh. In other words, even at maximum effort the tokens the model actually spends on “thinking” are near 0. A short factual task is answered in one pass, so there is nothing to plan or revisit, and no matter how far you turn the effort dial it connects to nothing — the opposite of the multi-step task (02), where reasoning tokens really did grow with effort.

With reasoning at 0, cost stays flat right along with it. Input per request is nailed at 224 tokens (the prompt is byte-for-byte identical), and even the visible output barely grows, 10–16 tokens. So the entire cost spread across efforts runs from none $0.587 to high $0.608 — a wobble of just over two cents per 1,000 requests.

Response time (latency) doesn't follow effort either. gpt-4o at 1,494ms; gpt-5.2 scatters like noise between 1,410–1,713ms regardless of effort — medium is even faster than none. On tasks answered in one pass, effort tells you nothing about speed.

Under PTU — renting capacity outright — the conclusion doesn't flip, but it softens a little. gpt-5.2 none carries about 1% more tokens per request than gpt-4o, so its throughput is 0.99× (about −1%) — on correct answers per minute from a fixed block of capacity, gpt-4o is marginally ahead. To sum up: in pay-as-you-go PAYG, gpt-5.2 none is clearly cheaper; in rented PTU, it's effectively a tie. Unlike the earlier two benchmarks where the PTU gap opened wide, here the two models nearly overlap.

Transparency

Even the smudges left on the numbers, as they are

No measurement is perfectly clean. We write down the marks this benchmark left without erasing them — because hiding them would trip up the next person at the same spot.

  • Measured swap. This floor was first published from a synthetic fixture (exp008_short-factual_fixture). It was a plausible shape, but it was not a measurement. With this note we replaced that spot with the measured data — regenerating analysis.json, charts, and tables via --experiment-prefix exp001_short-factual_baseline. The fixture is not deleted; it stays in the repo as a scaffold for reproducing the work offline without credentials, but it is removed as the source of the published numbers. The minimal effort the fixture used is a value real deployments reject, so in the measured data none is the floor.
  • Zero outliers. Nowhere in the 360 cells was a row excluded for landing far outside the normal range (3σ) or for an operational-problem marker (well under the methodology's 10% alert line). It is a clean surface where nothing was masked out of the totals.
  • No fixed answer key. This dataset has no rule-matching answer key, so quality is judged by judge score only. So “accuracy” counts only the share of judge score 2 (fully correct), and partial credit (1) does not count toward the pass rate. We state this choice to show how that top-line number was computed.
  • The arithmetic reversal. We didn't hide the only tag where gpt-5.2 lost to gpt-4o (arithmetic) — we wrote it plainly in §Where failure hid, to make clear that the floor's conclusion is not “gpt-5.2 wins everything” but “effort doesn't pay.”

Limits

How far can you trust this

These results are small-sample aggregates from one short-factual task set, one price snapshot, and a particular model-and-rubric combination. It is safer to take the method than the numbers themselves.

  • Sample. N=20 · R=3. At this sample size we claim no confidence intervals or statistical significance — the accuracy differences among none·low·medium (one out of 60) should be read as noise. The directional conclusion (“effort doesn't pay”) is robust, but treat absolute magnitudes with small-sample caution.
  • Grading. A judge model (gpt-4o). With no fixed answer key, quality depends entirely on the judge. We record the judge prompt's SHA-256 in the grading JSON to tell later if it changed, but the possibility of the judge's own bias remains.
  • Price. A single snapshot. If rates or the billing model change, cost must be recomputed from the same raw data.
  • PTU. Throughput is a token-based estimate, not a live PTU load test. On this floor the two models' throughput overlaps within about 1%, so the PTU conclusion should be read with particular care.

So what becomes the default

The default for short factual tasks is gpt-5.2 effort=none. With no reasoning switched on at all, it is 12% cheaper than gpt-4o per request and 16% per correct answer, and its accuracy is actually higher, 95% vs. 90%. From none through medium is effectively flat, so low·medium are fine to use, but any further gain is within sampling noise. high and above we discard: reasoning tokens are still near 0 while only cost rises. Under PTU gpt-4o is marginally ahead, effectively a tie — what paid off was not effort but the model swap.
