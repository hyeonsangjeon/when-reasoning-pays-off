实验笔记 · exp003 · 工具使用智能体(Mixed case) · 推理第一次值得的位置

exp003 — 工具智能体中推理强度是否值得

作者 Hyeonsang Jeon · Global Black Belt, Cloud & AI Apps

前两个基准的答案一直是“不要提高强度”。这一次不同。调用工具、接收结果、再做判断的混合任务 — 在三项基准中，这是推理第一次、而且只是很小幅度地值得的位置。

我们在预先登记中写下：中等强度(low–medium)会是帕累托膝点。gpt-4o 在无工具·单工具上可以，但会在多工具编排中倒下；gpt-5.2 none 因为没有可规划的推理表面，会在多工具上像 gpt-4o 一样弱；high·xhigh 会在质量饱和后，对小样本过度调用工具。

测量一半对了，一半令人意外。low 确实是底部 — 这一次不是 none。但 gpt-4o 真正倒下的地方不是多工具，而是在不需要工具的问题上调用计算器。本文按设计 → 输入 → 产物 → 预测对实测 → 工具滥用地图 → 决定回看那一天 — 希望后来的人少在同一路上绕弯。

设计

这次工具登场

问题只有一个。 在使用工具的智能体任务 — 最接近现实的混合案例 — 中，gpt-5.2 的强度要提高到哪里，推理才值回账单？我们同时用 PAYG(每个正确答案多少美元)和 PTU(固定容量下每分钟正确答案)两个视角来看。

数据集。 冻结的手写样本 20 个(tu_01…tu_20)。混合三类 — 无工具 6 个(只需知识/格式)、单工具 8 个(一个计算器或一次搜索)、多工具 6 个(搜索 → 计算器，连续 2–3 步的链)。所有样本都有可验证答案，也有应该调用哪些工具的 expected_tool_calls 答案表。

变化的轴只有一个 — 扫过 gpt-5.2 的 reasoning.effort：none · low · medium · high · xhigh。旁边放置没有推理参数的 gpt-4o 基线。每个(样本 × 模型 × 强度)单元重复三次(R=3)，工具循环最多重复 4 次(max_tool_iterations: 4)后截断。

预先登记预测

中等强度(low–medium)是混合任务的帕累托膝点。gpt-4o 可处理无工具·单工具，但会在多工具破裂；gpt-5.2 none 在多工具上同样弱；high·xhigh 会在质量饱和后只过度调用工具。

本实验的作用

短事实的底部(01)和多步的天花板(02)都以“不要提高强度”收尾后，检查是否存在实际需要推理表面的最小位置的混合锚点。

输入与产物

吃进什么，留下什么

这个实验吃进和留下的都不是手写摘要，而是仓库里的真实文件。所以从输入到输出，可以顺着一条线索回溯。

输入 (in)

实验定义： experiments/exp003_benchmark03_gpt5_2.yaml, …_gpt4o.yaml.
数据集： benchmarks/03-tool-using-agent/dataset.json (以 SHA-256 固定)。
提示·工具： 系统提示和工具设置分别以 SHA-256 指纹化 — 保证 360 个单元全都使用同一个系统提示和工具设置。

产物 (out)

原始调用： runs/*.json (Foundry v1 载荷 + 每轮 tool_calls 轨迹原文)。
评分： judge_runs/*.json (答案评分 + 单独工具效率分数)。
聚合： analysis.json.
图表/表： results/cost-curves/benchmark-03-*.png·.csv.

测量表面为 360 个单元(gpt-4o 60 + gpt-5.2 300，五档强度)。作为异常值排除的单元为 1 个(tu_18/low/r0)。评分由中立裁判 gpt-4o 对每个单元一次完成，360/360 成功。所有 JSON 都是真实 Azure Foundry v1 调用，没有一个 "fixture": true 标记。不过360 个单元中有 12 个(3.3%)触及工具循环 4 次上限，被强制在无工具下返回最终答案，并在各行留下 tool_loop_terminated="iteration_cap" 标记。

预测对实测

预测只对了一半

预测了什么

中等强度是膝点。gpt-4o 会在多工具上破裂。gpt-5.2 none 在多工具上弱。概括就是“混合任务需要少量推理”。

结果是什么

low 确实是帕累托膝点 — 这一次不是 none。但 gpt-4o 倒下的地方不只是多工具，还有无工具(83.3%)。明明不需要工具，它却调用了计算器。

判定：方向得到确认，失败模式反转。 “混合任务至少需要一点推理表面”这条预先登记得到支持 — low(不是 none)是按正确答案计的帕累托最优。但 gpt-4o 的弱点不只是多工具编排，还有在不该调用工具时调用工具的习惯。预测的一半对了，另一半被数据改写成更有意思的故事。

第一个信号

底部不是 none，而是 low

下表中的美元数，是把方法论的 PAYG 公式应用于价格快照 pricing/azure-openai-payg-2026-05.yaml(访问日 2026-05-19)后得到，并从 analysis.md §5 重新引用，按每 1,000 次归一化。

模型      努力     每1,000次请求    通过率          每1,000个正确答案
gpt-4o    —        $3.29         90.0% (54/60)   $3.65   ← 基线
gpt-5.2   none     $2.76         98.3% (59/60)   $2.81
gpt-5.2   low      $2.77         100%  (60/60)   $2.77   ← 帕累托最优
gpt-5.2   medium   $2.89         98.3% (59/60)   $2.94
gpt-5.2   high     $3.18         98.3% (59/60)   $3.23
gpt-5.2   xhigh    $3.50         100%  (60/60)   $3.50

每 1,000 个正确答案下，low 是 $2.77 — 比 gpt-4o($3.65)便宜 24%。它也是唯一在 gpt-4o 单价以下达到 100% 通过的单元。none 按请求已经比 gpt-4o 便宜约 16%(输入单价 $1.75/1M 对 $2.50/1M；在工具循环里输入主导账单)，但在多工具中漏掉一道，停在 98.3%。low 只增加了平均4 个 token 的推理表面，却把通过率拉到 100%(每 1,000 次请求 +$0.011)。

前两个基准里，none 既是底部也是最优。这里第一次把底部上移了一格。混合实际任务存在正的最小强度底部 — 推理终于，哪怕只是很小幅度地，值得了。

工具滥用地图

gpt-4o 过于频繁地调用工具

90% 这个单一聚合数字看不出“在哪里”。按类型拆开，才会露出这个基准的核心证据。

模型      努力     无工具(18)   1工具(24)   多工具(18)
gpt-4o    —        83.3%      100%      83.3%
gpt-5.2   none     100%       100%      94.4%
gpt-5.2   low      100%       100%      100%    ← 帕累托最优
  • 无工具 — gpt-4o 踩空的地方。 gpt-4o 明明不需要工具，却调用计算器，只有 83.3%。裁判把三次判为失败，理由是“量规要求工具调用 0 次，但模型调用了工具” — 即使是“1+1”这样的提示，也滥用了计算器。gpt-5.2 全强度 100%。
  • 单工具 — 完全饱和。 所有(模型×强度)单元都是 100%。单个工具分发对两个系列来说都是已经解决的问题。
  • 多工具 — 推理帮上忙的位置。 gpt-4o 83.3%，gpt-5.2 none 94.4%，low 100%。在连续 2–3 步的链条中，一个很小的推理表面让“计划并执行”更稳定。gpt-4o → gpt-5.2 low 的 16.7%p 提升，正是这个基准试图捕捉的实际任务信号。

工具效率分数(与答案评分分开，把轨迹评为 0–1)也指向同一方向。gpt-4o 以 0.950 最低，因为它在无工具任务中过度使用计算器，即使答对也被扣分。gpt-5.2 在 low 达到 0.988 顶点 — 正是通过率 100% 的那个单元。

第二个信号

超过 low，就用更高价格买相同质量

low 以上又重复前面基准的故事。medium 每 1,000 次请求多花约 $0.13，通过率却反而下降到 98.3%，相对 low 处于帕累托劣势。high 相比 low 每请求 +14%，xhigh +26%，但通过率不变(xhigh 虽为 100%，按正确答案却比 low 贵 26%)。

延迟也是同一个故事。 none 反而比 gpt-4o 快 5%(2,902ms 对 3,044ms)，low 为 +0.7%，基本平坦。但 high 拉到 +20.0%，xhigh 拉到 +23.9%。如果工作负载对延迟敏感，medium 是现实上限。

拆开 token 后，会看到这个基准自己的结构。 每请求输入约 1,200–1,300 token，主导账单 — 因为系统提示和工具定义在循环每轮都会重新带上。隐藏推理 token 从 0(none)增加到约 52(xhigh)，但相对输入而言很小。这与多步基准(02)中推理 token 主导 xhigh 成本的结构相反 — 反而与短事实基准(01)一样，是输入主导账单。

PTU 视角下，结论也汇聚到 low。 low 的吞吐是 gpt-4o 的 0.939倍，但 100% 通过率将其反转为每分钟正确答案 +4.3%(gpt-4o 为 90%)。吞吐损失(−6.1% req/min)小于通过率提升(+10.0%p)。相反，继续提高强度只会削减吞吐(medium −8.5%，xhigh −10.8%)。这是 PAYG(每正确答案最低)与 PTU(每分钟正确答案最高)两个视角都指向同一个 low 的收敛。

透明度

连数字上的污点也原样留下

任何测量都不可能完全干净。这个基准留下的痕迹，我们不擦掉，而是原样写下 — 因为藏起来，后来的人会在同一个地方踩空。

  • 异常值 1 个。 tu_18 的 low 第一次重复在 token 上超过 3σ，并同时带有运营标记，因此从聚合中排除(360 个单元中 1 个 = 0.3%，远低于方法论 10% 警戒线)。它仍原样保留在原始 JSON 树中 — 异常值排除只是聚合掩码，不是删除。
  • 循环上限 12 个。 360 个单元中有 12 个(3.3%)触及工具循环 4 次上限，被强制不再使用工具而返回答案。每行都留下 iteration_cap 标记，可以追踪哪些单元被上限压住。
  • 部分分不计入正确。 裁判分数 1(部分正确)在 §7 单独报告，但从每正确答案成本的分母中排除 — 因为在生产规模下，工具任务的部分正确不是正确。明确这个二值化选择，是为了说明这个核心数字是如何算出来的。

限制

可以相信到哪里

这个结果来自一个混合工具任务集、一个价格快照、特定模型组合与量规下的小规模聚合。比起数字本身，借鉴方法更稳妥。

  • 搜索是模拟的。 这个基准的 web_search 不是真实网页搜索，而是固定知识库查询。实时搜索会引入不可控方差，因此放在范围之外。核心结论(小推理表面提高多工具可靠性，超过 low 是 token 浪费)对这个简化是稳健的。这不是完美复现，而是只控制可以控制的部分 — 我们不隐藏这个边界。
  • 样本。 N=20 · R=3。在这个样本量下，不主张置信区间或统计显著性 — 方向性结论稳健，但绝对幅度需按小样本谨慎看待。
  • 价格。 单一快照。如果费率或 usage schema 改变，应从同一原始材料重新计算成本。
  • 评分。 LLM-as-judge(gpt-4o)。裁判提示 SHA-256 记录在评分 JSON 中以监控漂移。
  • PTU。 吞吐是基于 token 的估算，不是真实 PTU 负载测试。

所以默认值是什么

工具使用智能体的默认值是 gpt-5.2 effort=low — 在 PAYG 和 PTU 两边都是。按正确答案比 gpt-4o 便宜 24%，每分钟正确答案 +4.3%，还把多工具通过率从 83.3% 提到 100%。只有这一次，底部不是 none，而是 low。但超过 low 后，又只会增加成本·延迟，没有质量收益。
