Overview essay · reasoning effort, quality, and spend

When reasoning pays off: same token price, different bill

A reasoning model can have the same per-token price card and still create a different bill. The missing piece is the reasoning-token budget: tokens generated inside the model, billed like usage, and never shown in the response.

Question

When does extra reasoning effort buy measurable quality, and when does it only buy hidden compute?

Evidence

Public chart-data slices compare cost, judge score, token composition, latency, and modeled reserved-capacity crossover.

Decision

Raise effort only where the evaluator moves; keep the evidence dashboard as the audit trail behind the prose.

Reading convention · bars, axes, and tables

How to read the charts in this essay

The small bar figures in this essay are guideposts for the full source charts. They are not frequency histograms. Each bar is an aggregate measurement for one effort cell: baseline, minimal, low, medium, high, or extra-high.

X-axis

The X-axis is the operator's effort ladder. Moving left to right means allowing the model to spend more internal reasoning work.

Y-axis

The Y-axis changes by chart: USD per request for cost, judge score for quality, milliseconds for latency, token count for composition, and modeled requests per minute for crossover planning.

Bars

Taller is not always better. A taller quality bar can be good; a taller cost, latency, or reasoning-token bar is a tradeoff that needs a matching quality gain.

Source table

Use the dashboard table for exact values, standard deviations, and sample counts. The prose pulls out only the decision-relevant shape.

Topic · short factual answers

Short factual work often does not pay

Reading this bar chart

The X-axis is reasoning effort. The cost chart's Y-axis is mean USD per request; the paired quality chart's Y-axis is mean judge score. The bar shape therefore asks a simple question: did the higher spend buy a higher score, or did it only make the bill taller?

Why this chart exists

It tests the simplest migration trap: a team raises reasoning effort globally, then asks why the bill moved even though the task mostly needed short factual answers.

What it means

In the short-factual slice, minimal effort averaged $0.000663 per request. Xhigh effort averaged $0.005043 per request, a 7.6x bill, while the mean judge score moved from 1.87931 to 1.779661.

Operator lesson

Effort can buy more hidden computation without buying a better answer. For short factual work, start at the lowest effort level and raise it only after a quality gate shows a real gain.

Topic · invisible billing surface

Reasoning tokens explain the bill gap

Why this chart exists

A visible response can look almost unchanged while the model has spent many internal reasoning tokens to produce it. A plain output length chart would miss the billable work.

What it means

In the short-factual slice, minimal effort averaged 3.655172 reasoning tokens per request. Xhigh effort averaged 311.474576 reasoning tokens per request.

Operator lesson

The answer text does not reveal that difference. A production budget needs the usage breakdown: input, cached input, output, and reasoning tokens.

Topic · multi-step reasoning

Multi-step work can pay

Why this chart exists

It is the contrast case: a workload where intermediate reasoning is load-bearing and a higher-effort cell deserves a trial.

What it means

In the multi-step slice, the non-reasoning baseline scored 1.5. High effort scored 2.0 at $0.00125 per request.

Operator lesson

Reasoning earns its keep only when the evaluator moves enough to matter. Read quality before cost, then decide whether the marginal spend is justified.

Topic · tool-using agents

Tool-agent work needs ceiling checks

Why this chart exists

Tool agents can look like they need more thinking, but sometimes the tool call already carries the hard part of the work.

What it means

When the chart already shows a ceiling effect, raising effort may mostly add internal tokens and latency rather than better answers.

Operator lesson

Treat effort as a controlled experiment, not a default. For agentic workloads, check whether the limiting factor is reasoning quality, tool choice, tool latency, or orchestration.

Topic · capacity planning

PTU/PAYG crossover is a planning model

Why this chart exists

PAYG and reserved-capacity decisions answer different questions. The chart translates reasoning-inclusive token shape into a planning threshold.

What it means

For the short-factual xhigh row, the PTU/PAYG crossover is a modeled hypothesis at 149 rpm with a 50 PTU floor. It is not measured PTU throughput.

Operator lesson

Read that number as a planning threshold, not as capacity evidence. On PAYG, cutting reasoning tokens cuts variable spend. On PTU, the same cut may show up as room for more requests inside a fixed reservation.

The practical rule

Use low effort as the default for short factual work. Raise effort for multi-step work only when the evaluator moves enough to justify the cost. For tool-agent work, check for ceiling effects before spending more.
