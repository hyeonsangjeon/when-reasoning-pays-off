工具代理任务：质量触顶之后，延迟开始说话

工具代理任务很容易被浪漫化——它们涉及工具、分支，还带着一种“模型在真干活”的感觉。benchmark-03 用质量与延迟的成对视图，给这份浪漫降了温。结论比“effort 越多越好”要微妙得多。

问题

当工具代理的质量已经逼近上限时，再加 effort 还能买到什么？

天花板效应才是重点

benchmark-03 并没有给出一个简单的单调上升的故事。GPT-4o 平均评审分是 1.85；GPT-5.2 none 平均 1.966667，low 达到 2.0，medium 平均 1.983333，high 平均 1.966667，extra-high 达到 2.0。这相对基线确有提升，但同时也是一道天花板。

一旦好几个格都挤在顶端附近，再加 effort 就不再自动有意义了。下一份证据来自延迟、token 形态，以及藏在聚合分数背后的那些失败模式。

这张图该怎么读

这张图把延迟当作柱高，因为质量已经压缩在顶端附近。横轴是“模型／effort”格，纵轴是平均延迟（毫秒），每根柱子下方的标签给出成对的平均评审分。

这张图刻意不做成直方图。它比较的是被汇总过的实验格：如果两个格质量相近，更矮的那根柱就在追问——更长的等待，是不是还买到了什么看得见的东西。

为什么工具会改变读法

工具代理任务包含工具选择、中间状态和答案综合，这让它比短问答更吃力。这也意味着聚合质量分可能掩盖不同类型的行为：某个格通过，也许是工具干了大部分活儿；而某个格失败，也许是模型选对了工具，却总结得很糟。

这些图并不能免去人工检查的必要，但它们告诉我们该往哪儿检查。在这次运行里，low effort 是最有吸引力的区间——它既摸到了质量天花板，又把延迟保持在贴近基线的水平。

值得记住的那句话

工具代理基准需要读两遍。先问推理有没有提升正确性；如果质量已挤在顶端附近，再问哪个格能把延迟和 token 压力控制住。第二遍不是补充动作，而是让结果在基准之外真正可用的关键。

证据允许我们说什么

对工具代理任务，有用的那句话不是“加 effort”，而是“找到能保住你真正需要的代理行为的最低 effort”。
