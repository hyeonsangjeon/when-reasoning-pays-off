ツールエージェント：品質が天井に達したあと、真に問われるのはレイテンシ

チームがツールを使うエージェントを作り、それが間違いを出し始めると、最初の本能はたいてい同じだ。もっと考えさせよう、というものである。その本能は理にかなっている——ツールの作業には計画、ツールの選択、中間状態、回答の統合が絡むので、より多くの推論は効きそうに聞こえる。だが、もう一つの可能性がある。ツールの経路が十分に良く、ルーブリックがすでに頂点近くにあるとき、追加の推論はスコアが頭打ちのままレイテンシとコストだけを足すのかもしれない。benchmark-03 は、ツールエージェントの測定した区間でどちらの解釈が成り立つかを検証する。

なぜこれを検証したか

状況はよくあるものだ。チームはツールを使うエージェントを出荷し、いくつかの ケースで外すのを見て、まず推論強度（reasoning effort）を上げようとする。その理屈は筋が 通っている。エージェントの作業は純粋な想起ではない——計画を立て、正しい ツールを選び、中間状態を運び、そのうえで回答を統合しなければならない。 それだけの構造を持つタスクでは、「もっと考えさせる」は真っ先に思いつく一手のように見える。

だが、そこには確かめるべき二通りの解釈がある。追加の推論が本当に ツールの計画を改善し、回答を押し上げるのかもしれない。あるいは、ツールの 経路とルーブリックが一緒になって天井をつくり、エージェントが回答への 十分に良い経路を見つけてしまえば、より多くの推論はスコアが頂点近くに 張り付いたままレイテンシとコストだけを足すのかもしれない。benchmark-03 は、 どちらの解釈が抽象論ではなく実際の測定で成り立つかを検証する。

そこで検証した。benchmark-03 はツールエージェントの測定した区間を固定し、同じ モデルの強度の各段階——GPT-4o ベースライン、続いて GPT-5.2 の なし・ 低・中・高・最高——を順にたどり、各強度設定でレイテンシ・コスト・ トークンの形の隣に平均評価スコアを読む。結果は率直に述べる価値がある。 GPT-5.2 は GPT-4o ベースラインを超えて品質を押し上げたが、GPT-5.2 の内部 では品質の結果が天井（約 1.97〜2.00）に集まり、一方でコスト・ レイテンシ・推論トークンは上がり続けた。下の1枚要約はそれを一つの枠で 言い切り、続く各節が計測された詳細を示す。

問い

ツールエージェントの品質がすでに頂点近くにあるとき、推論強度を上げてもまだ何が改善されるのか。

根拠

benchmark-03 の品質・コスト・レイテンシ・トークン構成のチャート。

わかったこと

GPT-5.2 の品質は推論強度の全段階で 1.97〜2.00 の天井にとどまり、一方でコストはリクエストあたり $0.002762 から $0.003499 へ、レイテンシは 2.9s から 3.8s へ上った。

判断

ツールエージェントの作業は品質の天井に届く最も低い推論強度へ振り向け、それより高い推論強度は既定の選択ではなく、正当化すべきコストとレイテンシとして扱う。

対応する元チャートを開く： benchmark-03 レイテンシチャート。

天井効果こそが要点

benchmark-03 は単純な単調増加の物語を生まなかった。GPT-4o は評価スコア平均 1.85。GPT-5.2 はなしで平均 1.97、低で 2.0、中で平均 1.98、高で平均 1.97、最高で 2.0 に達した。ベースラインに対する品質の改善ではあるが、同時にこれは天井でもある。

いったん複数の組み合わせが頂点近くに集まってしまえば、推論強度を上げることに自動的な意味はなくなる。次の根拠は、レイテンシ、トークン形状、そして集計スコアの内側に隠れた失敗モードから来る。

チャートの読み方

このチャートは、品質がすでに頂点近くに集まっているため、棒の高さにレイテンシを使っている。X 軸はモデルと強度の組み合わせ、Y 軸は平均レイテンシ（ミリ秒）。各棒の下のラベルは、対になる平均評価スコアを示す。

このチャートは意図的にヒストグラムではない。要約された組み合わせ同士の比較だ。二つの組み合わせの品質が近いなら、短いほうの棒が「長く待つことでなお目に見える改善が得られているのか」を問いかける。

ツールが解釈を変える理由

ツールエージェントの作業には、ツールの選択、中間状態、回答の統合が含まれる。それが短い事実タスクよりも要求度を高くしている。同時に、集計の品質スコアが異なる種類の振る舞いを覆い隠しうる、ということでもある。ある組み合わせは、ツールが大半を片づけたから通ったのかもしれないし、正しいツールを使いながら要約が下手で落ちたのかもしれない。

チャートは検査の必要をなくしはしない。どこを検査すべきかを教えてくれるのだ。今回の測定で望ましい組み合わせは、基準をどこに置くかで決まる。厳密な 2.00 を求めるなら、最初にそこへ届く強度設定は低だ。天井近くのスコアですでにルーブリックを満たすなら、ベースラインに近いレイテンシで満たすのはなしだ。どちらにせよ方針は同じ——基準を満たす最も低い強度設定を見つけ、より高い推論強度へ上げる前にコストとレイテンシを確認する。

押さえておきたい要点

ツールエージェントのベンチマークは二通りの問いで読む必要がある。まず、推論が正しさを改善したかを問う。次に、品質が頂点近くに集まっているなら、どの強度設定がレイテンシとトークンを抑えているかを問う。二つ目の問いは後付けではない。結果をベンチマークの外で実際に使えるものにするのは、まさにこの問いだ。

この測定した区間が何を示し、何を示さないか：このツールエージェントの測定区間では、推論強度を上げると品質が天井に達し——GPT-5.2 のスコアは 1.97〜2.00 の帯を出なかった——一方でコストは強度の段階を通じて上がり続けたことを示す。同じ天井が短い事実回答、多段推論、統合の作業でも同じ強度水準で現れることは示さない。各トピックはそれぞれの測定を持つ。

この根拠から言えること

ツールエージェントの作業で役に立つ一文は「推論強度を上げよ」ではない。「本当に必要なエージェントの振る舞いを保つ、最も低い推論強度を見つけよ」だ。

概要記事に戻る

実務上のルール

  1. 品質チャートは、品質の棒だけでなく、同じ benchmark-03 強度設定のコストチャートとレイテンシチャートと対にして読んでください。
  2. 品質の基準——厳密な 2.00 でも、許容できる天井近くのスコアでも——を満たす最も低い強度設定を見つけ、それを既定にしてください。
  3. それより高い推論強度は、目に見えるスコアの変化で正当化すべきコストとレイテンシとして扱ってください。
  4. 信頼する前に集計を確認してください。合格した組み合わせが、推論ではなくツールに頼っている可能性がある。
  5. ワークロードの性質が変わったら測定し直してください。この天井はツールエージェントの作業に限られる。

実務上のルール：このツールエージェントの測定区間では、品質が天井に達したら推論強度を上げるのをやめてください。推論強度を上げることで増えたのは、より高いスコアではなく、コストとレイテンシだけである。
