ツールエージェント：品質が上限に達したあとに問うべきレイテンシ

ツールを使うエージェントで誤りが発生すると、まず「もっと考えさせよう」と考えがちです。ツールを使う処理には、計画、ツールの選択、中間状態の管理、回答の統合が含まれるため、推論を増やせば改善しそうに見えます。しかし、ツールの経路が十分に整い、評価スコアがすでにルーブリックの上限近くにある場合、推論を増やしてもスコアはほとんど変わらず、レイテンシとコストだけが増える可能性があります。benchmark-03 では、このツールエージェントの実測区間でどちらの解釈が成り立つかを確認します。

なぜこれを検証したか

よくある状況です。ツールを使うエージェントをリリースし、いくつかのケースで 失敗するのを見ると、まず推論強度の設定を上げようとします。この判断には 理由があります。エージェントの作業は単なる想起ではありません。計画を立て、適切な ツールを選び、中間状態を保持し、最後に回答を統合する必要があります。このように 構造のあるタスクでは、「もっと考えさせる」ことが最初の改善策に見えます。

ただし、二つの可能性を検証する必要があります。追加の推論によってツールの 利用計画が改善し、回答の品質が上がる可能性があります。一方、ツールの経路と ルーブリックによって上限が決まり、エージェントが十分に良い回答経路を見つけたあとは、 推論を増やしてもスコアが上限近くにとどまり、レイテンシとコストだけが増える可能性も あります。benchmark-03 では、どちらが実測で確認できるかを検証します。

benchmark-03 ではツールエージェントの測定区間を固定し、異なるモデルと 推論強度の組み合わせ——GPT-4o ベースライン、続いて GPT-5.2 の none・ low・medium・high・xhigh——を順に見ていき、各強度設定で平均評価スコアをレイテンシ・コスト・ トークン構成とあわせて読みました。結果は明確です。GPT-5.2 は GPT-4o ベースラインより品質を高めましたが、GPT-5.2 内の品質は上限（約 1.97〜2.00）に 集まりました。一方、コスト・レイテンシ・推論トークンは上がり続けました。 以下の1枚要約で結論を示し、続く各節で実測の詳細を説明します。

問い

ツールエージェントの品質がすでに上限近くにあるとき、推論強度を上げると何が改善するのでしょうか。

根拠

benchmark-03 の品質・コスト・レイテンシ・トークン構成のチャートです。

わかったこと

GPT-5.2 の品質は、推論強度の全段階で 1.97〜2.00 の上限近くにとどまりました。一方、コストはリクエストあたり $0.002762 から $0.003499 へ、レイテンシは 2.9s から 3.8s へ増加しました。

判断

ツールエージェントには、品質基準を満たす最も低い推論強度を選びます。それより高い強度は既定値にせず、増加するコストとレイテンシを正当化できる場合にだけ採用します。

対応する元チャートを開く： benchmark-03 レイテンシチャート。

上限効果が示すこと

benchmark-03 では、強度を上げるほどスコアも上がるという結果にはなりませんでした。GPT-4o の平均評価スコアは 1.85 でした。GPT-5.2 は none で平均 1.97、low で 2.0、medium で平均 1.98、high で平均 1.97、xhigh で 2.0 でした。ベースラインより品質は向上しましたが、GPT-5.2 内ではすでに上限に達しています。

複数の組み合わせが上限近くに集まると、推論強度を上げること自体に意味はありません。次に確認すべき根拠は、レイテンシ、トークン構成、集計スコアの背後にある失敗モードです。

チャートの読み方

このチャートでは、品質がすでに上限近くに集まり、差が小さいため、棒の高さでレイテンシを示しています。X 軸はモデルと強度の組み合わせ、Y 軸は平均レイテンシ（ミリ秒）です。各棒の下のラベルは、対応する平均評価スコアを示します。

これは度数分布を示すヒストグラムではなく、集計した組み合わせを横に並べた比較です。二つの組み合わせの品質が近い場合、短いほうの棒を選ぶことで、目に見える改善がないまま待ち時間だけが延びるのを避けられます。

ツールが解釈を変える理由

ツールエージェントの作業には、ツールの選択、中間状態の管理、回答の統合が含まれるため、短い事実回答より複雑です。同時に、集計された評価スコアは、性質の異なる振る舞いを覆い隠すことがあります。ツールが処理の大半を担ったため合格した組み合わせもあれば、正しいツールを使いながら、要約に失敗した組み合わせもありえます。

したがって、チャートだけで個別結果の確認が不要になるわけではありません。今回の実測でどの組み合わせを選ぶかは、品質基準によって決まります。厳密な 2.00 を求めるなら、最初に達する設定は low です。上限近くのスコアで十分なら、none がベースラインに近いレイテンシで基準を満たします。いずれの場合も、基準を満たす最も低い強度を選び、さらに強度を上げる前にコストとレイテンシを確認します。

押さえておきたい要点

ツールエージェントのベンチマークでは、二つの問いを確認します。まず、推論によって正しさが改善したかを見ます。次に、品質が上限近くに集まっている場合は、レイテンシとトークンを最も抑えられる強度を確認します。この二つ目の問いによって、実測結果を本番でも使える判断へつなげられます。

  • [1] Tier 1 — 方法論の契約： 本リポジトリ、docs/05-methodology.md（v1.0）。強度設定あたり N = 20 のサンプル、R = 3 回の反復で、公開集計の測定区間のみを対象にしています。本文のチャート読解はこの固定前提に立っており、誤差バーは信頼区間ではなく標準偏差です。N = 20 なので p 値は主張しません。

  • [3] Tier 2 — benchmark-03 区間の実測： 本リポジトリ、benchmarks/03-tool-using-agent/analysis.json。上限効果を示す評価スコア——1.85 の GPT-4o ベースラインと、1.97（none）、2.00（low）、1.98（medium）、1.97（high）、2.00（xhigh）の GPT-5.2——および、レイテンシが 2.9s から 3.8s へ延びるなかで、リクエストあたり $0.002762（none）から $0.003499（xhigh）へ単調に増加したコストの出典です。
  • [4] Tier 2 — レンダリング済みチャートデータ： 本リポジトリ、docs/blog/data/chart-data/cost-curves-effort/benchmark-03/cost-per-request.json、quality.json、latency.json。docs/blog/data/chart-data/token-composition/benchmark-03/tokens.json とあわせて読むと、推論トークンがリクエストあたり 0 から 52.15 へ増えても、品質は上限近くから動かなかったことを確認できます。
  • [5] 根拠ダッシュボード： レンダリングされた benchmark-03 の品質とコストの対チャートで、同じ成果物を検証できます。

この実測区間では、GPT-5.2 の評価スコアは 1.97〜2.00 の範囲で上限近くにとどまり、その一方で、コストは強度を上げるにつれて増加しました。ただし、短い事実回答、多段推論、統合作業でも同じ強度で同じ上限が現れることまでは示していません。各トピックで個別に測定する必要があります。

この根拠から言えること

ツールエージェントでは、単に推論強度を上げるのではなく、必要な振る舞いを保てる最も低い推論強度を見つけることが重要です。

実務上のルール

  1. 品質チャートを、同じ benchmark-03 の強度設定に対応するコストチャートとレイテンシチャートとあわせて読んでください。
  2. 品質基準——厳密な 2.00 でも、許容できる上限近くのスコアでも——を満たす最も低い強度を既定値にしてください。
  3. それより高い推論強度は、評価スコアの改善によって正当化できる場合にだけ採用してください。
  4. 集計値だけで判断せず、内容も確認してください。合格した組み合わせが、推論ではなくツールに依存している可能性があります。
  5. ワークロードの性質が変わったら、測定し直してください。この上限はツールエージェントの実測区間に限られます。

実務上のルール：このツールエージェントの実測区間では、品質が上限に達したら推論強度を上げるのをやめます。推論強度を上げても、評価スコアは高くならず、コストとレイテンシだけが増えました。
