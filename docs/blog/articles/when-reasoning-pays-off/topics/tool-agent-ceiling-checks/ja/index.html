トピック記事・benchmark-03 ツールエージェント

ツールエージェント：品質が天井に達したあと、真に問われるのはレイテンシ

チームがツールを使うエージェントを作り、そこに誤りが出始めると、最初に浮かぶ対応はたいてい同じだ。もっと考えさせよう、という発想だ。その直感にはもっともな理由がある。ツールの作業には計画、ツールの選択、中間状態の扱い、回答の統合が絡むので、推論を増やせば効きそうに見えるからだ。ただし、別の可能性もある。ツールの経路が十分に整い、ルーブリックがすでに頂点近くにあるなら、追加の推論はスコアをほとんど動かさないまま、レイテンシとコストだけを増やす可能性がある。benchmark-03 は、ツールエージェントのこの測定区間でどちらの解釈が成り立つかを確かめる。

なぜこれを検証したか

状況はよくある。チームはツールを使うエージェントを出荷し、いくつかの ケースで外すのを見て、まず推論強度（reasoning effort）を上げようとする。その理屈には筋が 通っている。エージェントの作業は単なる想起ではない——計画を立て、正しい ツールを選び、中間状態を保ちながら、そのうえで回答を統合しなければならない。 それだけ構造のあるタスクでは、「もっと考えさせる」が最初に浮かぶ一手に見える。

だが、ここには確かめるべき二通りの解釈がある。追加の推論が実際に ツールの計画を改善し、回答を押し上げる可能性がある。あるいは、ツールの 経路とルーブリックが一緒に天井をつくっていて、エージェントが回答への 十分に良い経路を見つけたあとは、推論を増やしてもスコアが頂点近くに 張り付いたまま、レイテンシとコストだけが増える可能性がある。benchmark-03 は、 どちらの解釈が抽象論ではなく実測で成り立つのかを確かめる。

そこで実測した。benchmark-03 ではツールエージェントの測定区間を固定し、同じ モデルの強度段階——GPT-4o ベースライン、続いて GPT-5.2 の none・ low・medium・high・xhigh——を順に見ていき、各強度設定で平均評価スコアをレイテンシ・コスト・ トークン構成と並べて読む。結果ははっきりしている。 GPT-5.2 は GPT-4o ベースラインより品質を押し上げたが、GPT-5.2 の内部 では品質が天井（約 1.97〜2.00）に集まり、一方でコスト・ レイテンシ・推論トークンは上がり続けた。下の1枚要約がその結論を一つの枠に 収め、続く各節で計測された詳細を示す。

問い

ツールエージェントの品質がすでに頂点近くにあるとき、推論強度を上げると何が改善されるのだろうか。

根拠

benchmark-03 の品質・コスト・レイテンシ・トークン構成のチャートだ。

わかったこと

GPT-5.2 の品質は推論強度の全段階で 1.97〜2.00 の天井にとどまり、一方でコストはリクエストあたり $0.002762 から $0.003499 へ、レイテンシは 2.9s から 3.8s へ上がった。

判断

ツールエージェントの作業は、品質の天井に届く最も低い推論強度に合わせ、それより高い推論強度は既定値ではなく、正当化が必要なコストとレイテンシとして扱う。

対応する元チャートを開く： benchmark-03 レイテンシチャート。

天井効果こそが要点

benchmark-03 の結果は、強度を上げるほど点数も上がるという単純な話にはならなかった。GPT-4o は評価スコア平均 1.85 だった。GPT-5.2 は none で平均 1.97、low で 2.0、medium で平均 1.98、high で平均 1.97、xhigh で 2.0 に達した。ベースラインに比べれば品質は改善しているが、同時にここが天井でもある。

いったん複数の組み合わせが頂点近くに集まると、推論強度を上げること自体には自動的な意味がなくなる。次に見るべき根拠は、レイテンシ、トークン構成、そして集計スコアの裏に隠れた失敗モードだ。

チャートの読み方

このチャートでは、品質がすでに頂点近くに集まっていて差が小さいため、棒の高さにレイテンシを使っている。X 軸はモデルと強度の組み合わせ、Y 軸は平均レイテンシ（ミリ秒）だ。各棒の下のラベルは、対応する平均評価スコアを示す。

このチャートは意図的にヒストグラムにはしていない。要約した組み合わせを横に並べて比較するためだ。二つの組み合わせの品質が近いなら、短いほうの棒は「長く待つだけの目に見える改善があるか」を問いかける。

ツールが解釈を変える理由

ツールエージェントの作業には、ツールの選択、中間状態の扱い、回答の統合が含まれる。そのため、短い事実タスクよりも要求が高くなる。同時に、集計された品質スコアは、性質の異なる振る舞いを覆い隠すことがある。ある組み合わせは、ツールが大半を片づけたことで通った可能性があるし、正しいツールを使っていても要約がうまくできずに落ちた可能性がある。

チャートが検査そのものを不要にするわけではない。どこを見ればよいかを教えてくれるだけだ。今回の測定でどの組み合わせを選ぶかは、基準をどこに置くかで決まる。厳密な 2.00 を求めるなら、最初にそこへ届く強度設定は low だ。天井近くのスコアでルーブリックを満たせるなら、ベースラインに近いレイテンシで満たすのは none だ。どちらにしても方針は同じだ——基準を満たす最も低い強度設定を見つけ、より高い推論強度に上げる前にコストとレイテンシを確認する。

押さえておきたい要点

ツールエージェントのベンチマークは、二つの問いで読む必要がある。まず、推論が正しさを改善したかを確認する。次に、品質が頂点近くに集まっているなら、どの強度設定がレイテンシとトークンを最も抑えられているかを見る。この二つ目の問いは後付けではない。測定結果をベンチマークの外でも実際に使える判断へつなぐのは、まさにこの問いだ。

この測定区間が示すことと、示さないことがある。このツールエージェントの測定区間では、推論強度を上げると品質が天井に達し——GPT-5.2 のスコアは 1.97〜2.00 の帯を出なかった——その一方で、コストは強度の段階を通じて上がり続けた。ただし、同じ天井が短い事実回答、多段推論、統合作業でも同じ強度水準で現れることまでは示していない。各トピックはそれぞれに測定が必要だ。

この根拠から言えること

ツールエージェントの作業で役に立つ一文は、「推論強度を上げる」ではない。「本当に必要なエージェントの振る舞いを保てる、最も低い推論強度を見つけること」だ。

概要記事に戻る

実務上のルール

  1. 品質チャートは、品質の棒だけでなく、同じ benchmark-03 の強度設定に対応するコストチャートとレイテンシチャートを対にして読む。
  2. 品質の基準——厳密な 2.00 でも、許容できる天井近くのスコアでも——を満たす最も低い強度設定を見つけ、それを既定にする。
  3. それより高い推論強度は、目に見えるスコアの変化で正当化される場合だけ受け入れるコストとレイテンシとして扱う。
  4. 集計をそのまま信じる前に、内容を確認する。合格した組み合わせが、推論ではなくツールに頼っている可能性がある。
  5. ワークロードの性質が変わったら、測定し直す。この天井はツールエージェントの作業に限られる。

実務上のルール：このツールエージェントの測定区間では、品質が天井に達したら推論強度を上げるのをやめる。推論強度を上げても増えたのは、より高いスコアではなく、コストとレイテンシだけだった。
