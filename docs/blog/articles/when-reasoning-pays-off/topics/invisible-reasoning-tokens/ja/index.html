見えない推論トークン：回答には現れない請求額の内訳

推論モデルへ移行したあとや、推論強度を一段上げたあとでも、回答は短く平凡なままに見えることがあります。画面に表示されるテキストだけでは、コストが増えたことに気づきにくいでしょう。それでも同じワークロードに対して、財務データやテレメトリには以前より大きな請求額が記録されます。回答が長くなっていないのなら、追加のコストはどこで発生したのでしょうか。

なぜこれを検証したか

リクエストのコストを考えるとき、多くのチームがまず注目するのは回答の長さです。短い回答は安く、長い回答は高いと考えます。推論モデルが登場する前は、この直感でも実務上はおおむね十分でした。

検証すべき問いは明確です。表示される回答の長さが支出を説明しており、請求額の増加は気づかないほどわずかに長くなった回答によるものかもしれません。一方、推論モデルでは、ユーザーが目にしない隠れた推論トークンにコストが移っている可能性もあります。どちらが変化の要因なのかをチャートで確認します。

課金対象となる各リクエストを、入力、キャッシュされた入力、見える出力、隠れた推論に分解し、コスト・品質・レイテンシとあわせて読みました。まず短い事実回答の区間を確認し、次に多段の区間と比較します。両者には明確な違いがありました。短い事実回答では、隠れた推論トークンはほとんど発生しませんでした。見える出力は推論強度の全段階で約 14.0 から 14.8 トークンへ増えただけで、隠れた推論は none で 0、high で最大約 1.35、xhigh で約 0.62 にとどまりました。そのため、リクエストあたりの請求額もほぼ横ばいでした。隠れた推論トークンが増えたのは、タスクに多段の解決が必要な場合だけです。その場合はリクエストあたり約 110 推論トークンまで増えました。以下の1枚要約でこの対比を示し、続く各節で実測の詳細を説明します。

問い

回答テキストが短いままなら、追加のコストはどこから来ているのでしょうか。

根拠

benchmark-01 と benchmark-02 のトークン構成を、コスト・品質・レイテンシと並べて一本の根拠の連なりとして読みます。

わかったこと

短い事実回答では隠れた推論トークンがほぼゼロにとどまり、請求額も横ばいでした。多段の作業では、リクエストあたり 0 から約 110 トークンまで増えました。

判断

回答が短くても、推論トークンをテレメトリで追跡します。隠れたトークンの予算も、回答に現れない請求額の一部として扱います。

セクション別に読む： 隠れた推論トークンが増えない場合と増える場合 チャートの読み方 元チャートで確認できること 押さえておきたい要点 根拠の表

対応する元チャートを開く： benchmark-01 (control) と benchmark-02 (multi-step) のトークン構成。

隠れた推論トークンが増えない場合と増える場合

benchmark-01 で注目すべきなのは、何が起きなかったかです。推論強度を上げても、隠れた推論トークンは増えませんでした。none は、見える出力が平均約 14.0 トークン、推論トークンが 0 でした。high では推論トークンが最大約 1.35、xhigh では見える出力が平均約 14.8 トークン、推論トークンが約 0.62 でした。隠れた推論トークンはほぼゼロで、請求額も横ばいとなり、gpt-5.2 の各セルは gpt-4o ベースライン以下に収まりました。短い事実回答では、モデルが熟考する必要がなかったと考えられます。

多段の区間では、同じ分解から反対の結果が得られました。隠れた推論は none の 0 トークンから xhigh の約 110 トークンへ増え、見える出力も約 6 から 117 トークンへ増加しました。読者が目にするテキストだけでは、実際の計算量を正確に見積もれません。増加した処理のかなりの部分が回答に現れないためです。短い回答が必ずしも安いとは限りません。隠れた予算が使われているかどうかは、トークンの内訳を見て判断します。

チャートの読み方

棒は強度設定ごとの集計セルであり、個々のリクエストのヒストグラムではありません。X 軸は推論強度、Y 軸はリクエストあたりの平均推論トークンです。各棒の下の小さなラベルは、同じセルにおける見える出力トークン数の平均を示します。

チャートは下から上へ読みます。まず、請求額を説明できるほど見える出力が変化したかを確認し、次に隠れた推論の棒と比較します。短い事実回答の control ではどちらも低いため、横ばいの請求額に隠れた要因はありません。多段の区間では、隠れた推論の棒が上昇します。

元チャートから確認できること

トークン構成は仕組みを説明しますが、それだけでは十分ではありません。コストチャートで請求額が変化したか、品質チャートでその支出によって回答が改善したか、レイテンシチャートでユーザーの待ち時間がどう変化したかを確認します。三つをあわせて読むと、隠れた課金構造がわかります。短い事実回答の control では、内部トークン、支出、品質がいずれも横ばいです。多段の作業では、内部トークンが請求額を押し上げます。

押さえておきたい要点

推論トークン自体が悪いわけではありません。推論トークンは、推論モデルの価値を支えるものです。ただし、そのトークンを使う価値のあるタスクが必要です。タスクが短い事実回答しか求めない場合、内部推論は気づきにくい予算の浪費になりえます。一方、多段の解決が必要な場合は、同じトークンが品質向上の鍵になる可能性があります。

そのため概要記事では、コスト・品質・レイテンシ・トークン構成を常にあわせて扱います。請求額のすべてが回答に現れるわけではありません。

出典と根拠の境界

上記の数値はすべて本リポジトリの公開成果物までたどれます。コストに関する記述は、いずれも日付付きの価格スナップショットを基に算定しています。推論トークンの予算をテレメトリで見えるように保つというこの記事の会計上の扱いは、この記事で置いている運用上の解釈です。下の二つの Tier は、文書化された入力がどこで終わり、推論がどこから始まるかを示しています。

  • [1] Tier 1 — 方法論の契約： 本リポジトリ、docs/05-methodology.md（v1.0）です。セルあたり N = 20 のサンプル、R = 3 回の反復で、対象は公開集計の区間のみです。チャート読解の本文はこの固定前提に立っており、誤差バーは信頼区間ではなく標準偏差で、N = 20 では p 値を主張しません。
  • [2] Tier 1 — PAYG 価格スナップショット： リクエストあたりのコストは本リポジトリの pricing/azure-openai-payg-2026-05.yaml で算定しています。2026-05-19 アクセス：Azure OpenAI 価格ページ、アーカイブです。定価が動けば、隠れたトークンの請求も変わります。
  • [3] Tier 2 — benchmark-01 区間の測定（control）： 本リポジトリ、benchmarks/01-short-factual/analysis.json です。平らな隠れトークンの読みの出典です——推論トークンは medium まで 0 にとどまり、ピークも約 1.35、見える出力は 14.0 から 14.8 へ動くだけです——だからこの区間ではリクエストあたりの請求が動きませんでした。
  • [4] Tier 2 — レンダリング済みチャートデータ（control）： 本リポジトリ、docs/blog/data/chart-data/token-composition/benchmark-01/tokens.json がトークン分解の出典です。docs/blog/data/chart-data/cost-curves-effort/benchmark-01/cost-per-request.json、quality.json、latency.json と一緒に読むと、隠れたチャネル、請求、待ち時間がそろって平らだったという対になる根拠になります。
  • [5] Tier 2 — 多段の測定（positive case）： 本リポジトリ、docs/blog/data/chart-data/token-composition/benchmark-02/tokens.json です。ガイドチャートが示す上昇の出典です——隠れた推論は推論強度の階段で 0, 17.433333, 32.0, 43.55, 109.55 と上がり、見える出力は 5.75 から 117.266667 へ上がります。見えない請求が実際に大きくなるのはここです。
  • [6] 根拠ダッシュボード： レンダリングされた benchmark-01 と benchmark-02 のトークン構成チャートは、同じ成果物を監査できる形です。

この根拠が示すことと、示さないことを分けておきます。隠れた推論チャネルはタスク依存です——短い事実回答の control ではほぼゼロで、多段の区間では見える出力にほぼ並ぶまで上がります。ツールエージェントや統合の作業でも同じ形だとは証明していません。各トピックはそれぞれ固有の測定を持っています。大事なのは大きさではなく、この測り方の習慣です。どちらのケースにいるかは、トークン分解だけが教えてくれます。

実務上のルール

  1. 合計トークンだけでなく、リクエストごとの推論トークンを見える出力と並べて記録してください。
  2. 短い回答でも大きな内部コストを含む可能性があるため、隠れたトークンの予算にアラートを設定してください。
  3. このワークロードの品質チャートで改善を確認した場合にだけ、より高い推論強度へ引き上げてください。

見える回答が短くても、推論トークンをテレメトリで測定してください。隠れたトークンの予算は、回答に現れない請求額の一部です。
