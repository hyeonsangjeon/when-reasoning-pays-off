短い事実回答：推論強度を上げても結果が変わらないとき

推論モデルを導入したばかりのチームには、短い事実質問が推論強度を試す最も扱いやすい対象に見えます。答えが短く、誤りもすぐにわかるため、「もう少し考えさせる」ことが安い保険のように思えるからです。しかし、その直感をそのまま方針にするのではなく、まず仮説として検証する必要があります。本記事では、データを使って確かめます。

なぜこれを検証したか

よくある場面です。モデル移行で推論モデルに乗り換えると、設定画面に推論強度の設定が現れます。短い事実質問は、その設定を上げても最も安全そうに見える対象です。出力は短く、誤りも目につきやすい。「もう少し考えさせよう」は安い保険のように聞こえるので、ここで既定値を上げるのはほとんどタダのように感じられます。

そこから、確かめるべき明快な仮説が得られます。短い事実回答に おいて、推論強度を上げると実際に答えはより安全になるのか。そうで あれば、その高い既定値には根拠があります。そうでなければ、チームは 読者に決して届かない思考に対価を払っていることになります。

そこで実測しました。ワークロードの形は同じ短い事実回答の区間に固定し、推論強度の段階を一つずつ上げました。各レベルで、リクエストあたりのコスト、レイテンシ、見える回答テキスト、隠れた推論トークン、評価スコアを比べています。この区間では、推論強度を上げても、コスト、レイテンシ、推論トークン、品質のいずれも実質的に変わりませんでした。下の1枚要約がその結論を一つの図にまとめ、続く各節が実測の詳細を示します。

問い

タスクの大半が短い事実回答を求めるとき、推論強度を上げると、請求を正当化できるほど品質は改善するのでしょうか。

根拠

benchmark-01 のコスト・品質・レイテンシ・トークン構成のチャートを、公開データの表と対にして読みます。

わかったこと

この測定区間では、リクエストあたりのコストは実質的に横ばいでした。none から xhigh まで約 1.02x、すべての gpt-5.2 段階が gpt-4o ベースラインを下回り、平均評価スコアは 1.95 前後に保たれました。

判断

すでに正しく答えられる最も低い推論強度を既定値にします。評価モデルがこのワークロードで実際の品質向上を示した場合にだけ、引き上げます。

対応するチャートファミリーを開く： benchmark-01 コストチャート と対になる品質チャート。

データが示したこと

仮説は、推論強度を上げればより安全な答えが得られると予測していました。 しかしデータはそれを裏づけませんでした。コストの棒は実質的に横ばいです — none で $0.000587、xhigh で $0.000598、約 1.02x の幅で、 すべての gpt-5.2 段階が gpt-4o ベースラインの $0.000665 を下回ります — 品質の棒も同じように横ばいです。平均評価スコアは階段全体で約 1.95、ベースラインの 1.90 以上です。レイテンシにも傾向はありません （上昇なしにおおむね 1.4s から 1.7s）。トークン構成のスループット係数は 0.99 前後を保ちます。

つまり、コストも品質も推論強度に応じて変化しませんでした。推論強度を上げても請求額は下がらず、回答も改善していません。最も低い設定の gpt-5.2 は、すでに gpt-4o ベースラインに並ぶか上回っていました。このワークロードでは、より高い推論強度を既定値にせず、実験として扱うべきです。

仮説が外れうる理由

安全に見える既定値が期待を裏切ることがあるのは、短い事実回答が 長い内部探索をほとんど必要としないからです。答えが単一の事実で あれば、ボトルネックになりやすいのは検索や安定したプロンプト、 あるいはすでに正答に届いている最も低い推論強度設定であって、追加の 熟慮ではありません。その点を越えると、より多く考えても見つかる ものはもう残っていません。今回の区間では、推論強度を上げても 品質、コスト、レイテンシ、推論トークンはいずれもほぼ変わりませんでした。

それがこの測定区間で見られた形です。評価スコアは推論強度とともに 上がらず、1.95 前後に保たれ、コスト、レイテンシ、推論トークン も 実質的に横ばいでした。ここでは支払うべき隠れた思考がほとんどありません — だからこそ、この測定区間で高い既定値にしても、安い設定がすでに 出していないものは何も買えないのです。

チャートの読み方

棒は集計の棒グラフであって、度数のヒストグラムではありません。各棒は benchmark-01 の一つの強度設定を表すため、比較の焦点は「同じ ワークロードの形が推論強度の上昇とともにどう変わるか」にあります。

X 軸

棒は推論強度のレベルを左から右へ並びます——baseline、none、 low、medium、high、xhigh。これは運用者が調整できる設定 です。

Y 軸

コストチャートでは棒の高さがリクエストあたりの平均 USD を、 品質チャートでは棒の高さが平均評価スコアを表します。両者は 別々にではなく、対にして読んでください。

棒と表

各棒は一つの強度設定の集計値です。チャート下の表には、正確な 値、入手できる場合の標準偏差、サンプル数が示されています。誤差 バーは信頼区間ではなく標準偏差です。

各元チャートが受け持つこと

各元チャートは判断の別々の部分を担います。コストチャートはその 設定が何を要するかを示し、品質チャートはその支出でより良い答えが 得られたかを示します。レイテンシとトークン構成は運用上の副作用を 説明し、スループットの見方は同じトークンの形を計画上の圧力へと 置き換えます。

何が起きたか

コスト曲線は横ばいでした。none ではリクエストあたり平均 $0.000587、xhigh ではリクエストあたり平均 $0.000598、 約 1.02x の幅で、すべての gpt-5.2 段階が gpt-4o ベースラインの $0.000665 を下回りました。対になる品質も横ばいでした。平均評価スコアは 1.95 前後に保たれ、ベースラインの 1.90 以上でした。

これは推論全般が悪いという主張ではありません。あくまでこの ワークロードの形についての結果です。この測定区間では、支払うべき 追加の内部計算はほとんどなく、推論強度を上げてもより安い請求も より良い答えも買えませんでした。ダッシュボードはコストと品質を並べて 示すため、それがはっきり見えます。

ここでの落とし穴は逆の直感です。高い推論強度なら必ずより安全だ、 という直感です。レビュー担当者がいくつかの答えを抜き取って確認するだけなら、 xhigh ではモデルがより真剣に考えたように見え、強く感じられる かもしれません。チャートは、その直感がそのまま方針になるのを防ぎます。 品質差は横ばいであり、より安い設定でも同じ回答を保てます。 レイテンシは別のチャートで確認し、この直感だけを方針の根拠にしないでください。

計測しながら学んだこと

「もっと考える」はデフォルトではない

推論強度は一種の処置です。測定区間に適用して効果を計測し、 評価者が実際に動いたときにだけ引き上げてください。グローバルな 既定値として扱うと、本番トラフィックが流れ始めるまで請求の 増加が表に出ません。

コストは品質と対で見る

コストだけのチャートは変化を分かりやすく示しますが、それだけ では不完全です。品質だけのチャートは経済的なコストを見えなく します。役に立つのは両者を対にして見ることです。何にコストを 払い、それが答えを改善したのかを、あわせて確認してください。

短い事実回答には低い推論強度のベースラインが要る

受け入れ可能な最も低い推論強度が、超えるべきベースラインです。 より高いレベルが品質でそれを超えないなら、運用者はより安い 設定を保ち、最適化の時間は別の場所に使うべきです。

判断を見直すとき

この結論を永久に固定してはいけません。タスクが短い想起から統合へ 変わったとき、評価ルーブリックが多段の正当化に報い始めたとき、 プロンプトがツールの出力を運び始めたとき、あるいは新しいモデルが コストと品質の形を変えたとき——そのつど再検証してください。教訓は 「推論を決して使うな」ではありません。「対になる根拠なしに推論 強度を昇格させるな」です。

役に立つ追試は、同じ X 軸を保ちつつワークロードの測定区間を変える ものです。短い事実回答、多段、ツールエージェント、統合のタスクは、 それぞれ独自の推論強度設定を持つべきです。そのルーティングの方針 こそ、推論がふつう報われる場所です。

出典と根拠の境界

上の数値はすべて本リポジトリの公開成果物にたどれ、コストの数値は いずれも日付つきの価格スナップショットをもとに算定しています。 より高い推論強度はこの測定区間では実験的なままにとどめるべきだ、 という運用上の解釈は、この記事自身のものです。下の二つの Tier は、 文書化された入力がどこで終わり、推論がどこから始まるのかを示しています。

  • [1] Tier 1 — 方法論の契約： 本リポジトリ、docs/05-methodology.md（v1.0）。強度設定あたり N = 20 のサンプル、R = 3 回の反復、公開集計の測定区間のみを対象とします。チャート読解の本文はこの固定された前提に立っており、誤差バーは信頼区間ではなく標準偏差で、N = 20 では p 値を主張しません。
  • [2] Tier 1 — PAYG 価格スナップショット： リクエストあたりのコスト（none の $0.000587、xhigh の $0.000598、どちらも $0.000665 ベースラインを下回る）は本リポジトリの pricing/azure-openai-payg-2026-05.yaml をもとに算定しています。2026-05-19 アクセス：Azure OpenAI 価格ページ；アーカイブ。定価が動けば数値も変わります。
  • [3] Tier 2 — 短い事実回答区間の測定： 本リポジトリ、benchmarks/01-short-factual/analysis.json。横ばいのリクエストあたりコスト、約 1.95 の平均評価スコア（gpt-4o ベースライン 1.9）、約 1409 ms から 1713 ms の間で傾向のないレイテンシ、0.99 近くを保つスループット係数の出典です。
  • [4] Tier 2 — レンダリング済みチャートデータ： 本リポジトリ、docs/blog/data/chart-data/cost-curves-effort/benchmark-01/（cost-per-request.json、quality.json、latency.json、throughput-gain.json）と docs/blog/data/chart-data/token-composition/benchmark-01/tokens.json。推論トークンがほぼゼロ（none で 0.0、high で 1.35）にとどまり、見える出力が約 14.0 から 14.8 トークンへしか動かないことの出典です。
  • [5] 根拠ダッシュボード： 根拠ダッシュボードの強度設定ごとの表とレンダリングされた元チャートは、同じ成果物を監査できる形になっています。

この測定区間が示すことと示さないこと：短い事実回答のこのワークロードの 形で、一つのテナント、一つのリージョン、この価格スナップショットのもとでは、 推論強度を上げても、コスト、レイテンシ、推論トークン、品質はいずれも 実質的に横ばいでした。同じ形が統合、多段、ツールを使う作業で、あるいは将来の 価格スナップショットのもとで成り立つことまでは証明していません。

実務上のルール

実務上のルール：短い事実回答は、すでに正しく答えられる最も低い 推論強度に保ち、このワークロードの形で品質ゲートが動いたあとにのみ、より 高い推論強度へ引き上げてください——対になるコスト・レイテンシ・トークン 構成のチャートとあわせて読んでください。

根拠ダッシュボードが、そのルールの裏にある監査証跡です。
