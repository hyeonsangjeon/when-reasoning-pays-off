短い事実回答：追加の推論が品質ではなくコストを買うとき

チームが推論モデルを導入したばかりのころ、短い事実質問は effort を上げて みるのに最も手軽な場所に見える。答えは短く、間違いはすぐ目につき、少し 余分に考えさせることは安価な保険のように感じられる。だから、まずここで 推論 effort を上げたくなる。その直感は、出荷する価値のある方針ではなく、 検証する価値のある仮説だ——そして本記事はそれをデータで検証する。

なぜこれを検証したか

状況はよくあるものだ。移行でチームは推論モデルにたどり着き、設定には 推論 effort のダイヤルが現れ、短い事実質問は、それを上げるのに最も 安全な場所に見える。出力は短く、誤りは明白で、「もう少し考えさせよう」は 安価な保険のように聞こえる——だから既定値をここで上げるのは、ほとんど タダのように感じられる。

そこから、確かめるべききれいな仮説が手に入る。短い事実回答で、より高い 推論 effort は実際に答えをより安全にするのか。もしそうなら、その高い 既定値は居場所を勝ち取る。もしそうでないなら、チームは読者に決して 届かない思考に対して支払っていることになる。

そこで検証した。ワークロードの形は固定し——同じ短い事実回答の断面—— effort のはしごを一段ずつ歩き、各レベルでリクエストあたりのコスト、 レイテンシ、見える回答テキスト、隠れた推論トークン、評価スコアを比べた。 この断面での結果は、既定値を動かすべき種類のものだった。effort は コスト、レイテンシ、隠れたトークンを買ったが、より良い答えは買わなかった。 下の1枚要約はそれを一つの枠で言い切り、続く各節が計測された詳細を示す。

問い

タスクの大半が短い事実回答を求めるとき、より高い推論 effort は請求を正当化できるほど品質を改善するのか。

根拠

benchmark-01 のコスト・品質・レイテンシ・トークン形状のチャートと、公開データの表を対にしたもの。

わかったこと

この断面では、リクエストあたりのコストが約 7.6 倍に上ったが、平均評価スコアは上がらなかった——約 1.88 から約 1.78 へ動いた。

判断

すでに正しく答えられる最も低い effort を既定値にする。評価者がこのワークロードの形で実際の品質の上積みを示したあとにだけ、引き上げる。

対応するチャートファミリーを開く： benchmark-01 コストチャート と対になる品質チャート。

データが示したこと

仮説は、より高い effort でより安全な答えを予言した。データはそれを 届けなかった。コストの棒は minimal effort の $0.000663 から extra-high effort の $0.005043 へ上るが、品質の棒は一緒には上らない。平均評価 スコアは minimal effort で 1.88、extra-high effort で 1.78 だ。レイテンシ も約 1.1s から約 3.1s へ伸びる。容量の面でもタダではない。トークン形状の スループット係数は 0.98 から 0.45 へ落ちる。

それで、コストの棒は上り、品質の棒は上らなかった——それがチャートの 語ろうとする話のすべてだ。高くなったコストの棒は本物で、増えた隠れトークン の予算も本物で、対応する品質の上積みだけが欠けている。このワークロードの 形では、より高い effort は既定値になるのではなく、実験的なままにとどめる べきだ。

仮説が外れうる理由

安全に見える既定値が期待を裏切りうるのは、短い事実回答が長い内部探索を めったに必要としないからだ。答えが単一の事実なら、ボトルネックになりがちな のは検索、安定したプロンプト、あるいは単にすでに正答に届く最も低い effort 設定であって、追加の熟慮ではない。その点を越えると、より多く考えても 見つけるものはもう残っておらず、effort のはしごは精度を足さずに隠れた トークンだけを足し続ける。

それがこの断面の見せる形だ。評価スコアは effort とともに上らない。コスト、 レイテンシ、隠れた推論がすべて増えるなか、1.88 から 1.78 へ漂う。思考は 本物だが、モデルの内側にとどまり、読者には決して届かない——だからこそ、 ここで高い既定値は、答えが決して返さないコストになる。

チャートの読み方

棒は集計の棒グラフであって、度数のヒストグラムではない。各棒は benchmark-01 の一つの effort セルを表すので、比較は「同じワークロードの形が effort の上昇とともにどう変わるか」についてのものだ。

X 軸

棒は推論 effort のレベルを左から右へ動く——baseline、minimal、low、 medium、high、extra-high。これを運用者が変えられる制御つまみとして 扱う。

Y 軸

コストチャートでは棒の高さはリクエストあたりの平均 USD を意味する。 品質チャートでは棒の高さは平均評価スコアを意味する。別々にではなく、 対として読む。

棒と表

各棒は集計セルだ。チャート下の表が正確な値、入手できる場合の標準偏差、 サンプル数を示す。誤差バーは信頼区間ではなく標準偏差だ。

各元チャートが受け持つこと

各元チャートは判断の別々の部分に答える。コストチャートはその設定が何を 要するかを言う。品質チャートはその支出がより良い答えを買ったかを言う。 レイテンシとトークン構成は運用上の副作用を説明する。スループットの見方は、 同じトークンの形を計画上の圧力へと翻訳する。

何が起きたか

コスト曲線は急に上った。minimal effort はリクエストあたり平均 $0.000663、 extra-high effort はリクエストあたり平均 $0.005043、つまり 7.6 倍の請求 だった。対になる品質の動きはその支出を正当化しなかった。平均評価スコアは 1.88 から 1.78 へ動いた。

これは推論が悪いという普遍的な主張ではない。ワークロードの形についての 主張だ。この断面では、追加された内部計算は、見合う回答品質の上積みを 買わなかった。ダッシュボードはコストと品質を並べて保つので、その不一致が 見える。

肝心の罠は、出力がそれでもまともに見えうることだ。レビュー担当者が いくつかの答えしか抽出しないなら、extra-high effort はモデルがより一生懸命 考えたように見えるので、より安全に感じられるかもしれない。チャートは その直感が方針になるのを防ぐ。より高いコスト、より遅いレイテンシ、より 大きな隠れトークンの請求を受け入れる前に、計測された品質の差を求める。

計測しながら学んだこと

「もっと考える」はデフォルトではない

effort は処置だ。断面に適用し、計測し、評価者が動いたときにのみ 昇格させるべきだ。グローバルな既定値として扱うと、本番のトラフィックが 来るまで請求を隠す。

コストは品質と対で見る

コストだけのチャートは変化を明白だが不完全に見せうる。品質だけの チャートは経済的なコストを隠しうる。役に立つ見方は対だ。何を買い、 それは答えを改善したのか。

短い事実回答には低 effort のベースラインが要る

受け入れ可能な最も低い effort レベルが、超えるべきベースラインだ。 より高いレベルが品質でそれを超えないなら、運用者はより安い設定を 保ち、最適化の時間は別の場所に使うべきだ。

判断を見直すとき

この結論を永久に凍結してはいけない。タスクが短い想起から統合へ変わった とき、評価ルーブリックが多段の正当化に報い始めたとき、プロンプトがツールの 出力を運び始めたとき、あるいは新しいモデルがコストと品質の形を変えたとき ——再検証する。教訓は「推論を決して使うな」ではない。「対になる根拠なしに effort を昇格させるな」だ。

役に立つ追試は、同じ X 軸を保ちつつワークロードの断面を変える。短い事実 回答、多段、ツールエージェント、統合のタスクは、それぞれ独自の effort 設定を勝ち取るべきだ。そのルーティングの方針こそ、推論がふつう報われる 場所だ。

出典と根拠の境界

上の数値はすべて本リポジトリの公開アーティファクトにたどれ、コストの数値は いずれも日付つきの価格スナップショットで算定している。より高い effort は この断面では実験的なままにとどめるべきだ、という運用上の解釈は、この記事 自身のものだ。下の二つの Tier は、文書化された入力がどこで終わり、推論が どこから始まるのかを示す。

  • Tier 1 — 方法論の契約： 本リポジトリ、docs/05-methodology.md（v1.0）。セルあたり N = 20 のオーサリング済みサンプル、R = 3 回の反復、公開集計スライスのみ。チャート読解の本文はこの凍結された前提に立っており、誤差バーは信頼区間ではなく標準偏差で、N = 20 で p 値は主張しない。
  • Tier 1 — PAYG 価格スナップショット： リクエストあたりのコスト（minimal effort の $0.000663、extra-high effort の $0.005043、7.6 倍の請求）は本リポジトリの pricing/azure-openai-payg-2026-05.yaml で算定している。出典：Azure OpenAI 価格ページ（2026-05-19 アクセス）· アーカイブ。定価が動けば比も変わる。
  • Tier 2 — 短い事実回答スライスの測定： 本リポジトリ、benchmarks/01-short-factual/analysis.json。コストの上昇、1.87931 から 1.779661 への平均評価スコアの動き、1112.798745 ms から 3088.001225 ms へのレイテンシの伸び、0.984614 から 0.451798 へのスループット係数の出典。
  • Tier 2 — レンダリング済みチャートデータ： 本リポジトリ、docs/blog/data/chart-data/cost-curves-effort/benchmark-01/（cost-per-request.json、quality.json、latency.json、throughput-gain.json）と docs/blog/data/chart-data/token-composition/benchmark-01/tokens.json。3.655172 から 311.474576 への推論トークンの推移と、12.672414 から 17.881356 トークンしか動かない見える出力の出典。
  • エビデンスダッシュボード： エビデンスダッシュボードのセルごとの表とレンダリングされた元チャートは、同じアーティファクトを監査できる形だ。

このスライスが何を証明し、何を証明しないか：短い事実回答のこのワークロードの 形で、一つのテナント、一つのリージョン、この価格スナップショットのもとで、 effort のはしごがコストと隠れたトークンを買い、見合う品質の上積みは買わな かったことを示す。同じ形が統合、多段、ツールを使う作業で、あるいは将来の 価格スナップショットのもとで成り立つことは証明しない。

実務上のルール

実務上のルール：短い事実回答は、すでに正しく答えられる最も低い effort に保ち、このワークロードの形で品質ゲートが動いたあとにのみ、より 高い effort へ引き上げてください——対になるコスト・レイテンシ・トークン 構成のチャートと並べて読むこと。

エビデンスダッシュボードが、そのルールの裏にある監査証跡だ。
