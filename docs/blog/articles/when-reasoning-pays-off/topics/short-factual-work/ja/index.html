短い事実回答：推論強度を上げてもコストだけが増えるとき

推論モデルを導入したばかりのチームにとって、短い事実質問は推論強度を 上げてみる最も手軽な対象に見えます。答えは短く、間違いはすぐ目につく ため、少し余分に考えさせることは安価な保険のように感じられるから です。だから、まずここで推論強度を上げたくなります。しかしその直感は、 そのまま採用してよい方針ではなく、検証すべき仮説です——本記事は それをデータで確かめます。

なぜこれを検証したか

よくある状況です。モデル移行によってチームが推論モデルにたどり 着くと、設定には推論強度の項目が新たに現れ、短い事実質問はそれを 上げるのに最も安全な対象に見えます。出力は短く誤りもすぐ目につく ため、「もう少し考えさせよう」は安価な保険のように聞こえます—— だから既定値をここで上げるのは、ほとんどタダのように感じられます。

そこから、確かめるべき明快な仮説が得られます。短い事実回答に おいて、推論強度を上げると実際に答えはより安全になるのか。そうで あれば、その高い既定値には根拠があります。そうでなければ、チームは 読者に決して届かない思考に対価を払っていることになります。

そこで実際に測定しました。ワークロードの形は固定したまま——同じ 短い事実回答の測定区間で——推論強度の各段階を一つずつ適用し、 レベルごとにリクエストあたりのコスト、レイテンシ、見える回答 テキスト、隠れた推論トークン、評価スコアを比較しました。この測定 区間での結果は、既定値を見直すべき種類のものでした。推論強度を 上げても、コスト・レイテンシ・隠れたトークンが増えるだけで、より 良い答えは得られなかったのです。下の1枚要約がその結論を一つの図に まとめ、続く各節が計測された詳細を示します。

問い

タスクの大半が短い事実回答を求めるとき、推論強度を上げると、請求を正当化できるほど品質は改善するのでしょうか。

根拠

benchmark-01 のコスト・品質・レイテンシ・トークン形状のチャートを、公開データの表と対にして読みます。

わかったこと

この測定区間では、リクエストあたりのコストが約 7.6 倍に上りましたが、平均評価スコアは上がらず——約 1.88 から約 1.78 へ動きました。

判断

すでに正しく答えられる最も低い推論強度を既定値にします。評価者がこのワークロードの形で実際の品質の上積みを示したときにだけ、引き上げます。

対応するチャートファミリーを開く： benchmark-01 コストチャート と対になる品質チャート。

データが示したこと

仮説は、推論強度を上げればより安全な答えが得られると予測していました。 しかしデータはそれを裏づけませんでした。コストの棒は最小強度の $0.000663 から最高強度の $0.005043 へ上りますが、品質の棒は一緒には 上がりません。平均評価スコアは最小強度で 1.88、最高強度で 1.78 です。レイテンシも約 1.1s から約 3.1s へ伸びます。容量の面でも タダではなく、トークン形状のスループット係数は 0.98 から 0.45 へ 落ちます。

コストの棒は上がり、品質の棒は上がらなかった——このチャートが語る 話はそれに尽きます。高くなったコストの棒は本物で、増えた隠れ トークンの予算も本物ですが、それに見合う品質の上積みだけが欠けて います。このワークロードの形では、より高い推論強度を既定値にする のではなく、実験的な扱いにとどめるべきです。

仮説が外れうる理由

安全に見える既定値が期待を裏切ることがあるのは、短い事実回答が 長い内部探索をほとんど必要としないからです。答えが単一の事実で あれば、ボトルネックになりやすいのは検索や安定したプロンプト、 あるいはすでに正答に届いている最も低い推論強度設定であって、追加の 熟慮ではありません。その点を越えると、より多く考えても見つかる ものはもう残っておらず、推論強度を上げても精度は上がらないまま、 隠れたトークンだけが積み上がっていきます。

それがこの測定区間で見られた特性です。評価スコアは推論強度とともに 上がらず、コスト・レイテンシ・隠れた推論がすべて増えるなかで、 1.88 から 1.78 へと沈んでいきます。思考そのものは確かに行われて いますが、モデルの内側にとどまり、読者には決して届きません—— だからこそ、ここでの高い既定値は、答えが決して返さないコストに なるのです。

チャートの読み方

棒は集計の棒グラフであって、度数のヒストグラムではありません。各棒は benchmark-01 の一つの強度設定を表すため、比較の焦点は「同じ ワークロードの形が推論強度の上昇とともにどう変わるか」にあります。

X 軸

棒は推論強度のレベルを左から右へ並びます——baseline、minimal、 low、medium、high、extra-high。これは運用者が調整できる設定 です。

Y 軸

コストチャートでは棒の高さがリクエストあたりの平均 USD を、 品質チャートでは棒の高さが平均評価スコアを表します。両者は 別々にではなく、対にして読んでください。

棒と表

各棒は一つの強度設定の集計値です。チャート下の表には、正確な 値、入手できる場合の標準偏差、サンプル数が示されています。誤差 バーは信頼区間ではなく標準偏差です。

各元チャートが受け持つこと

各元チャートは判断の別々の部分を担います。コストチャートはその 設定が何を要するかを示し、品質チャートはその支出でより良い答えが 得られたかを示します。レイテンシとトークン構成は運用上の副作用を 説明し、スループットの見方は同じトークンの形を計画上の圧力へと 置き換えます。

何が起きたか

コスト曲線は急に上がりました。最小強度ではリクエストあたり平均 $0.000663、最高強度ではリクエストあたり平均 $0.005043、つまり 7.6 倍の請求でした。対になる品質の動きは、その支出を正当化しません でした。平均評価スコアは 1.88 から 1.78 へ動いています。

これは推論全般が悪いという主張ではありません。あくまでこの ワークロードの形についての結果です。この測定区間では、追加された 内部計算に見合う回答品質の上積みが得られませんでした。ダッシュ ボードはコストと品質を並べて示すため、その不一致がはっきり見えます。

ここでの落とし穴は、出力がそれでもそれらしく見えてしまうことです。 レビュー担当者がいくつかの答えを抜き取って確認するだけなら、最高 強度ではモデルがより真剣に考えたように見え、かえって安心してしまう かもしれません。チャートは、その直感がそのまま方針になるのを 防ぎます。より高いコスト、より遅いレイテンシ、より大きな隠れ トークンの請求を受け入れる前に、計測された品質の差を確認して ください。

計測しながら学んだこと

「もっと考える」はデフォルトではない

推論強度は一種の処置です。測定区間に適用して効果を計測し、 評価者が実際に動いたときにだけ引き上げてください。グローバルな 既定値として扱うと、本番トラフィックが流れ始めるまで請求の 増加が表に出ません。

コストは品質と対で見る

コストだけのチャートは変化を分かりやすく示しますが、それだけ では不完全です。品質だけのチャートは経済的なコストを見えなく します。役に立つのは両者を対にして見ることです。何にコストを 払い、それが答えを改善したのかを、あわせて確認してください。

短い事実回答には低い推論強度のベースラインが要る

受け入れ可能な最も低い推論強度が、超えるべきベースラインです。 より高いレベルが品質でそれを超えないなら、運用者はより安い 設定を保ち、最適化の時間は別の場所に使うべきです。

判断を見直すとき

この結論を永久に固定してはいけません。タスクが短い想起から統合へ 変わったとき、評価ルーブリックが多段の正当化に報い始めたとき、 プロンプトがツールの出力を運び始めたとき、あるいは新しいモデルが コストと品質の形を変えたとき——そのつど再検証してください。教訓は 「推論を決して使うな」ではありません。「対になる根拠なしに推論 強度を昇格させるな」です。

役に立つ追試は、同じ X 軸を保ちつつワークロードの測定区間を変える ものです。短い事実回答、多段、ツールエージェント、統合のタスクは、 それぞれ独自の推論強度設定を持つべきです。そのルーティングの方針 こそ、推論がふつう報われる場所です。

出典と根拠の境界

  • [2] Tier 1 — PAYG 価格スナップショット： リクエストあたりのコスト（minimal effort の $0.000663、extra-high effort の $0.005043、7.6 倍の請求）は本リポジトリの pricing/azure-openai-payg-2026-05.yaml をもとに算定しています。出典：Azure OpenAI 価格ページ（2026-05-19 アクセス）· アーカイブ。定価が動けば比も変わります。
  • [3] Tier 2 — 短い事実回答区間の測定： 本リポジトリ、benchmarks/01-short-factual/analysis.json。コストの上昇、1.87931 から 1.779661 への平均評価スコアの動き、1112.798745 ms から 3088.001225 ms へのレイテンシの伸び、0.984614 から 0.451798 へのスループット係数の出典です。
  • [4] Tier 2 — レンダリング済みチャートデータ： 本リポジトリ、docs/blog/data/chart-data/cost-curves-effort/benchmark-01/（cost-per-request.json、quality.json、latency.json、throughput-gain.json）と docs/blog/data/chart-data/token-composition/benchmark-01/tokens.json。3.655172 から 311.474576 への推論トークンの推移と、12.672414 から 17.881356 トークンしか動かない見える出力の出典です。
  • [5] 根拠ダッシュボード： 根拠ダッシュボードの強度設定ごとの表とレンダリングされた元チャートは、同じ成果物を監査できる形になっています。

この測定区間が示すことと示さないこと：短い事実回答のこのワークロードの 形で、一つのテナント、一つのリージョン、この価格スナップショットのもとでは、 推論強度を上げるとコストと隠れたトークンが増え、見合う品質の上積みは 得られなかったことを示しています。同じ形が統合、多段、ツールを使う作業で、 あるいは将来の価格スナップショットのもとで成り立つことまでは証明していません。

実務上のルール

実務上のルール：短い事実回答は、すでに正しく答えられる最も低い 推論強度に保ち、このワークロードの形で品質ゲートが動いたあとにのみ、より 高い推論強度へ引き上げてください——対になるコスト・レイテンシ・トークン 構成のチャートと並べて読むこと。

根拠ダッシュボードが、そのルールの裏にある監査証跡です。
