多段の作業：推論を試す価値が生まれるとき

短い事実回答の測定区間を見たあとでは、推論努力度を「隠れた支出」——答えを変えないまま請求だけを膨らませる設定——と見なしがちです。けれども、複数の制約を同時に保ってはじめて答えにたどり着くタスクも、現場では確かにあります。そこで問いは変わります。より強いモデルやより高い推論努力度は、コストだけでなく答えそのものも変えるのでしょうか。このベンチマークは、その直感が測定でも成り立つかを確かめます。

なぜこれを検証したか

短い事実回答の測定区間からは、一つの教訓が得られました。タスクが想起しか 求めないなら、推論努力度を上げてもコストが増えるだけです。けれども、すべての タスクが想起だけで済むわけではありません。実際の作業では、小さな制約の連なりを 保ったまま進めることをモデルに求める場面があります——いくつかの条件を組み合わせ、 途中結果を持ち運び、そのうえで答える場面です。そうした形では、「もう少し考えさせる」 ことが明らかな無駄とは言い切れず、費用に見合う可能性が出てきます。

ここから、確かめるべき仮説がはっきりします。タスクが本当に複数の制約を まとめて保つことを要するなら、より強いモデルやより高い推論努力度は、 請求額を増やすだけでなく実際の品質向上にもつながるかもしれません。この直感自体は もっともです。実験では、それが抽象的な期待にとどまらず、測定した区間でも成り立つかを見ます。

そこで benchmark-02 では、多段の作業の区間を固定したうえで、同じモデル群と effort の段階——GPT-4o ベースライン、続いて GPT-5.2 のnone、low、medium、high、xhigh——を 順に比べました。各設定では、平均審判スコアをコストとレイテンシの横に並べて読みます。 結果は一様ではなく、そのまま受け止める必要があります。GPT-5.2 は GPT-4o ベースラインより 品質を押し上げましたが、GPT-5.2 の中で最も高い推論努力度が自動的な勝ち筋になったわけではありません。 最高得点を最も安く達成した設定は、推論トークンをまったく使っていませんでした。下の1枚要約で まず結論をつかみ、そのあと各節で計測結果を順に確認します。

問い

推論努力度を上げたとき、請求だけでなく品質の改善も得られるのはどんな場合でしょうか。

根拠

benchmark-02 の品質・コスト・レイテンシ・トークン構成を並べたチャートです。

わかったこと

GPT-5.2 では、最も高い推論努力度を使わなくても、GPT-4o ベースラインに対して目に見える品質の上積みが出ました。

判断

多段の作業は、品質の基準を超える最も低い推論努力度に合わせ、対になる品質チャートが改善するときにだけ強度を上げます。

筋ごとに読む： 品質の動きが解釈を変えた チャートの読み方 このベンチマークが違っていた理由 押さえておきたい要点 根拠の表

対応する元チャートを開く： benchmark-02 品質チャート。

品質の動きが解釈を変えた

benchmark-02 では、ベースラインの GPT-4o セルの平均審判スコアは 1.5 でした。GPT-5.2 はnone、medium、high、xhighで 2.0 に達し、lowでは 1.93 でした。このチャートが示すのは、「常に推論努力度を上げるべきです」という単純な話ではありません。このワークロードには、モデルと effort の選び方を試す価値があるだけの内部構造がある、ということです。

さらに重要なのは、最初に基準を超えた設定の姿です。GPT-5.2 の none強度は、リクエストあたり平均 $0.000618 で 2.0 に達しました。つまり、最も高い推論努力度を既定値にしなくても、試行そのものには十分な意味があります。

チャートの読み方

X 軸はモデルと推論努力度の組み合わせで、Y 軸は平均審判スコアです。各棒の下のラベルは、同じ設定のリクエストあたり平均コストを示しています。この二つを対で見ることが大切なのは、品質の棒だけを追うと過剰な設定を選びやすくなるからです。複数の強度設定がルーブリックの上限に届くなら、より安くて速いほうをまず候補にできます。

これは度数を示すヒストグラムではありません。各棒は、元データの表でサンプル数と標準偏差を持つ、要約済みの実験セルです。

このベンチマークが違っていた理由

短い事実回答のタスクでは、たいてい短い答えが求められました。多段の作業では、複数の小さな推論のつながりを保ったまま進めることがモデルに求められました。そこで「もう少し考えさせる」ことの意味が変わります。モデルと推論努力度の選択は、追加の支出だけでなく、誤りをどれだけ減らせるかという観点でも読む必要が出てきます。

ただし、この根拠は強度を上げ続けることまでは支持しません。推論努力度が上がるほどレイテンシも伸び、xhighでは平均 3.3s でした。品質がいったんルーブリックの上限に達したら、次に問うべきなのは「より遅い設定が本当に新しい上積みを生むか」です。

押さえておきたい要点

推論努力度が報われるのは、答えそのものが変わるときであって、雰囲気だけが変わるときではありません。多段の作業は、推論努力度を試す候補として最初に見るべき領域です。タスクの内部にモデルが恩恵を受けやすい構造があり、評価でもその差を捉えられるからです。

したがって結論は、「どこでも推論努力度を上げる」ではありません。「多段の作業は、品質の基準を超える最も低い推論努力度に合わせ、対になる品質チャートが再び動くときにだけ強度を上げる」です。

この測定区間が示すことと、示さないことを分けます。この多段の作業の区間では、 GPT-5.2 が GPT-4o ベースラインに対して測定できる品質の上積みを出したことを示しています。 一方で、推論努力度を上げれば常に品質が上がることや、追加の請求が常に正当化されることまでは 示していません——ここで最も安い最高得点の設定は、推論トークンをまったく使っていませんでした。 また、同じ上積みが短い事実回答、ツールエージェント、統合作業でも現れることは示していません。 各トピックは、それぞれ別に測定しています。

この根拠から言えること

この測定区間では、多段の作業で GPT-4o ベースラインの 1.5 から GPT-5.2 の 2.0 まで、測定できる品質の上積みが確認できました。その上積みは、推論努力度を上げたことではなく、モデルのアップグレードから生まれています。シリーズ全体にとっては、「推論は答えが実際に変わるときにこそコストに見合います」という基準点を加える結果です。

実務上のルール

  1. 同じ多段の作業の品質チャートをコストチャートと対にして読んでください。品質の棒だけを見ないでください。
  2. 品質の基準を超える最も低い推論努力度を選んでください。より高い設定は、スコアが改善するときだけ候補として扱ってください。
  3. より高い推論努力度へ引き上げる前にレイテンシを確認してください。推論努力度が上がると待ち時間も伸びます。
  4. ワークロードの形が変わったら測定し直してください。この測定区間の上積みは、他のトピックへそのまま持ち込めません。

実務上のルール：多段の作業では、まず品質の基準を超える最も低いモデルと推論努力度を選んでください。このワークロードの形で対になる品質チャートが改善するときにだけ、推論努力度を上げてください。請求を正当化するのは支出そのものではなく、品質の上積みです。
