多段の作業：推論を試す価値が生まれるとき

短い事実回答の実測区間だけを見ると、推論強度は、答えを変えずに請求額だけを増やす「隠れた支出」に見えます。しかし実務には、複数の制約を同時に扱わなければ答えにたどり着けないタスクもあります。では、より強いモデルや高い推論強度は、コストだけでなく答えそのものも変えるのでしょうか。このベンチマークでは、その直感が実測でも成り立つかを検証します。

なぜこれを検証したか

短い事実回答の実測区間から得られた教訓は一つです。タスクが単純な想起しか 求めないなら、推論強度を上げても品質もコストもほぼ変わりませんでした。しかし、すべての タスクが想起だけで済むわけではありません。実際の作業では、複数の条件を組み合わせ、 中間結果を保持しながら答えを導くなど、いくつもの制約を同時に扱う必要があります。 このようなタスクでは、「もう少し考えさせる」ことが費用に見合う可能性があります。

検証すべき仮説は明確です。タスクが複数の制約を同時に扱うことを求めるなら、 より強いモデルや高い推論強度は、請求額を増やすだけでなく、実際の品質向上にも つながるかもしれません。実験では、この直感が実測区間でも成り立つかを確認します。

benchmark-02 では、多段の作業の区間を固定し、GPT-4o ベースラインと、 GPT-5.2 の none、low、medium、high、xhigh を順に比較しました。各設定の 平均評価スコアをコストとレイテンシとあわせて読みます。GPT-5.2 は GPT-4o ベースラインより品質を高めましたが、GPT-5.2 の中では、最も高い推論強度が 最良とは限りませんでした。最高得点を最も低いコストで達成した設定は、推論トークンを まったく使っていません。以下の1枚要約で結論を示し、続く各節で実測結果を説明します。

問い

推論強度を上げたとき、コストの増加だけでなく品質の向上も得られるのは、どのような場合でしょうか。

根拠

benchmark-02 の品質・コスト・レイテンシ・トークン構成を並べたチャートです。

わかったこと

GPT-5.2 は、最も高い推論強度を使わなくても、GPT-4o ベースラインを明確に上回りました。最も低いコストで最高得点を得たのは、推論トークンを使わない none でした。

判断

多段の作業には、品質基準を満たす最も低い推論強度を選び、このワークロードの品質チャートで改善が確認できる場合にだけ強度を上げます。

対応する元チャートを開く： benchmark-02 品質チャート。

品質の動きが解釈を変えた

benchmark-02 では、GPT-4o ベースラインの平均評価スコアは 1.5 でした。GPT-5.2 は none、medium、high、xhigh で 2.0、low で 1.93 でした。強度に沿ってスコアが単調に上がっているわけではなく、low は none を下回っています。このチャートが示すのは、常に推論強度を上げるべきだということではありません。このワークロードには、モデルと推論強度の組み合わせを試す価値のある構造があるということです。

最初に品質基準を満たした設定を見ると、解釈はさらに明確になります。GPT-5.2 の none は、推論トークンを使わず、リクエストあたり平均 $0.000618 で 2.0 に達しました。この区間では、最も高い推論強度ではなく、品質基準を満たした最も安い組み合わせが最良でした。

チャートの読み方

X 軸はモデルと推論強度の組み合わせ、Y 軸は平均評価スコアです。各棒の下のラベルは、同じ設定のリクエストあたり平均コストを示します。品質だけを見ると必要以上に高い強度を選びやすいため、二つを対で読むことが重要です。複数の強度設定がルーブリックの上限に達しているなら、より安く、速い設定を優先できます。

これは度数分布を示すヒストグラムではありません。各棒は、サンプル数と標準偏差を持つ実験セルの集計値です。

このベンチマークが違っていた理由

短い事実回答では、簡潔な回答だけが求められました。一方、多段の作業では、複数の小さな推論をつなげたまま処理する必要があります。ただし、この区間で最高得点を得た none は推論トークンを使っていないため、品質向上は推論予算ではなく、モデルのアップグレードによるものでした。推論を試す価値のある構造はありましたが、スコアを高めたのは推論強度ではなく、より強いモデルです。

この根拠は、強度を上げ続けることを支持していません。推論強度が上がるほどレイテンシも伸び、xhigh では平均 3.3s でした。品質がルーブリックの上限に達したあとは、より遅く高価な設定が本当に追加の価値を生むかを確認する必要があります。

押さえておきたい要点

推論がコストに見合うのは、回答の印象ではなく、答えそのものが変わるときです。多段の作業は、推論を試す候補として優先できます。モデルが利用できる構造がタスクにあり、評価でもその差を捉えられるためです。ただし、この区間で差を生んだのは推論強度ではなく、モデルのアップグレードでした。

したがって、どのタスクでも推論強度を上げるのではなく、多段の作業には品質基準を満たす最も低い強度を選びます。より高い強度は、評価スコアがさらに改善する場合にだけ採用します。

この根拠から言えること

この実測区間では、多段の作業で GPT-4o ベースラインの 1.5 から GPT-5.2 の 2.0 へ品質が向上しました。この向上は、推論強度ではなくモデルのアップグレードによるものです。「推論は答えが実際に変わる場合にだけコストに見合う」というシリーズ全体の基準を補強する結果です。

実務上のルール

  1. 同じ多段の作業の品質チャートをコストチャートと対にして読んでください。品質の棒だけを見ないでください。
  2. 品質の基準を超える最も低い推論強度を選んでください。より高い設定は、スコアが改善するときだけ候補として扱ってください。
  3. より高い推論強度へ引き上げる前にレイテンシを確認してください。推論強度が上がると待ち時間も伸びます。
  4. ワークロードの形が変わったら測定し直してください。この測定区間の上積みは、他のトピックへそのまま持ち込めません。

実務上のルール：多段の作業では、まず品質の基準を超える最も低いモデルと推論強度を選んでください。このワークロードの形で対になる品質チャートが改善するときにだけ、推論強度を上げてください。請求を正当化するのは支出そのものではなく、品質の上積みです。
