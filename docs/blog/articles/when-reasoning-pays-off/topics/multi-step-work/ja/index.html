多段タスク：推論が試す価値を稼ぐとき

短い事実回答の測定区間のあと、推論強度を「隠れた支出」——答えを変えずに請求だけを膨らませる設定——に分類したくなる。だが、いくつもの制約を同時に頭に保つことに答えが懸かるタスクも、チームは走らせる。そこで問いは改めて立てられる。より強いモデルやより高い推論強度は、コストだけでなく実際に答えを変えるのか。このベンチマークは、その直感を測定で検証する。

なぜこれを検証したか

短い事実回答の測定区間は一つの教訓を示した。タスクが想起しか求めないとき、 推論強度を上げてもコストが増えるだけだ。だが、すべてのタスクが想起ではない。 現実の作業の多くは、小さな制約の連鎖を生かし続けることをモデルに求める ——いくつかの条件を組み合わせ、途中結果を運び、そのうえで答える。その形 では、「もっと考えさせる」は明白な無駄には見えなくなり、元を取りうるように 見え始める。

そこから、確かめるべききれいな仮説が手に入る。タスクが本当に複数の制約を まとめて保つことを要するなら、より強いモデルやより高い推論強度は、 より大きな請求だけでなく実際の品質向上をもたらすかもしれない。直感は理にかなって いる——実験は、それが抽象論ではなく実際の測定で成り立つかを検証する。

そこで検証した。benchmark-02 は多段の断面を固定し、同じモデルと effort の 強度の各段階——GPT-4o ベースライン、続いて GPT-5.2 のなし・低・中・高・最高——を 順にたどり、各強度設定でコストとレイテンシの隣に平均評価スコアを読む。 結果はまちまちで、率直に述べる価値がある。GPT-5.2 は GPT-4o ベースラインを 超えて品質を押し上げたが、GPT-5.2 の内部では最も高い推論強度設定が自動的に 勝者ではなく、最も安い最高得点の強度設定は推論トークンをまったく使わなかった。 下の1枚要約はそれを一つの枠で言い切り、続く各節が計測された詳細を示す。

問い

推論強度を上げると、ただ請求額を膨らませるのではなく品質の改善も得られるのは、どんなときか。

根拠

benchmark-02 の品質・コスト・レイテンシ・トークン形状のチャート。

わかったこと

GPT-5.2 の低・なし強度の領域は、最も高い推論強度を使わずとも、GPT-4o のベースラインに対して目に見える品質の上積みを出した。

判断

多段の測定区間は品質の基準を超える最も低い推論強度へ振り向け、対になる品質チャートが改善するときにだけ推論強度を上げる。

筋ごとに読む： 品質の動きが解釈を変えた チャートの読み方 このベンチマークが違っていた理由 押さえておきたい要点 根拠の表

対応する元チャートを開く： benchmark-02 品質チャート。

品質の動きが解釈を変えた

benchmark-02 では、ベースラインの GPT-4o セルが評価スコア平均 1.5 だった。GPT-5.2 はなし・中・高・最高強度で 2.0 に達し、低強度では 1.93 に届いた。チャートは「常に推論強度を上げよ」とは言っていない。このワークロードには、モデルと effort の選択を試す価値があるだけの構造が備わっている、と言っているのだ。

より重要な点は、最初に目標を達成した強度設定の姿にある。GPT-5.2 なし強度はリクエストあたり平均 $0.000618 で 2.0 に達した。これにより、最も高い推論強度をデフォルトに祭り上げることなく、試行そのものが有用になる。

チャートの読み方

X 軸はモデルと推論強度の組み合わせ、Y 軸は平均評価スコア。各棒の下のラベルは、同じ強度設定のリクエストあたり平均コストだ。この対の見方が大事なのは、品質の棒だけを見ると過剰な選択を誘いかねないからだ。複数の強度設定がルーブリックの頂点に達するなら、より安く速いほうが面白くなる。

これは度数のヒストグラムではない。各棒は、元データの表に独自のサンプル数と標準偏差を持つ、要約された実験値だ。

このベンチマークが違っていた理由

短い事実回答のタスクは、おおむね短い回答を求めた。多段タスクは、小さな推論の連鎖を保ち続けることをモデルに求めた。それが「追加の思考」で得られるものを変えた。モデルと推論強度の選択は、もはや追加の支出に対してだけでなく、誤答の少なさに対して読まれることになった。

とはいえ、根拠は最大化主義に報いない。推論強度が上がればレイテンシも上がり、最高強度では平均 3.3s だった。品質がいったんルーブリックの頂点に達したら、次の問いは「より遅い強度設定に新しい発見があるか」になる。

押さえておきたい要点

推論強度が報われるのは、それが実際に回答を変えるときであって、雰囲気を変えるだけのときではない。推論強度を試すにあたり最初に考えるべき場所は多段タスクだ。タスクにはモデルが恩恵を受けるだけの内部構造があり、評価者はその差を見て取れる。

したがって結論は「どこでも推論強度を上げよ」ではない。「多段の測定区間は、品質の基準を超える最も低い推論強度へ振り向けよ」だ。

この測定区間が何を示し、何を示さないか：この多段の測定区間では、GPT-5.2 が GPT-4o のベースラインに対して測定できる品質の上積みを出したことを示す。推論強度を上げると常に品質が上がる、あるいは追加の請求を正当化することは示さない——ここでは最も安い最高得点の強度設定は推論トークンをまったく使わなかった——し、同じ上積みが短い事実回答、ツールエージェント、統合の作業で現れることも示さない。各トピックはそれぞれの測定を持つ。

この根拠から言えること

この測定区間では、多段タスクは GPT-4o ベースラインの 1.5 から GPT-5.2 の 2.0 へと測定できる品質の上積みを見せ、その上積みは推論強度の上昇ではなくモデルのアップグレードから来た。シリーズに「推論は答えが実際に変わるときにこそコストに見合う」という基準点を加える。

概要記事に戻る

実務上のルール

  1. 同じ多段の強度設定の品質チャートをコストチャートと対にして読んでください。品質の棒だけを見ないでください。
  2. 品質の基準を超える最も低い推論強度を選んでください。より高い設定はスコアが改善するときだけ候補として扱ってください。
  3. より高い推論強度へ引き上げる前にレイテンシを確認してください。推論強度が上がると待ち時間も伸びます。
  4. ワークロードの形が変わったら測定し直してください。この測定区間の上積みは他のトピックには引き継がれない。

実務上のルール：多段の作業では、まず品質の基準を超える最も低いモデルと推論強度を選び、このワークロードの形で対になる品質チャートが改善するときにだけ推論強度を上げてください。請求を正当化するのは品質の上積みであって、支出そのものではない。
