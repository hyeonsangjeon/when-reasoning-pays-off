PTU/PAYG クロスオーバー：容量の結果ではなく、プランニングの線

クロスオーバーチャートが有用なのは、まさにそれが限定的だからだ。これは公開されたコストとトークン形状のスナップショットを、一つのプランニングの問いに変える。すなわち、この計測されたワークロード形状において、固定の PTU 支出が PAYG より安く見え始めるのはどのリクエストレートか、という問いだ。稼働中の PTU ターゲットが負荷下でどう振る舞うかを証明するものではない。

問い

モデル化された PTU/PAYG クロスオーバーは何を語れて、何を主張してはならないのか。

根拠

公開のクロスオーバー JSON、価格スナップショット、トークン形状のスループット係数。

わかったこと

クロスオーバーは意思決定のきっかけだ。飽和、429 の発生、稼働中の容量の直接的な根拠ではない。

判断

クロスオーバーは、このワークロード形状で容量実験を走らせる価値がいつ生じるかを告げるプランニングの線として読む。特定のデプロイに PTU が必要だという判定ではない。価格・トークン構成・リージョンが変われば導出し直す。

筋ごとに読む： モデルは狭い問いに答える チャートの読み方 この区別が大事な理由 押さえておきたい要点 根拠の表

対応する元チャートを開く： PTU/PAYG クロスオーバーチャート群。

モデルは狭い問いに答える

クロスオーバーの計算は、リクエストあたり平均コスト、トークン形状のスループット係数、公開の価格スナップショット、そして 50 PTU の下限を組み合わせる。出力されるのは、モデル化された損益分岐 RPM だ。たとえば benchmark-01 extra-high effort はおよそ 149 rpm、benchmark-02 none はおよそ 2,680 rpm、benchmark-03 low はおよそ 564 rpm に着地する。

これらの数字が有用なのは、ワークロード形状がプランニングの会話をどう変えるかを露わにするからだ。これらは稼働負荷の計測ではない。429 がどこで始まるか、飽和近くでキャッシュがどう振る舞うか、特定の構成が p95 レイテンシで何をするか——そうしたことは語らない。

チャートの読み方

X 軸は選ばれた一連のベンチマーク行、Y 軸はモデル化された損益分岐 RPM。棒が高いほど、モデル化された PTU の下限が安く見え始めるまでに PAYG がより高いリクエストレートへ伸びられることを意味する。棒が低いほど、そのワークロードはモデル上のクロスオーバーに早く到達する。

これらの棒は連続的な容量曲線ではない。公開の集計データと価格スナップショットから導かれた、プランニング上の目印だ。

この区別が大事な理由

この区別がなければ、クロスオーバーチャートは約束のように誤読されうる。149 rpm のクロスオーバーを持つ行は「PTU が必要」、2,680 rpm のクロスオーバーを持つ行は「PTU は不要」と言いたくなる。だが根拠はもっと慎重だ。チャートが語るのは、モデル化された前提のもとで経済性がどう見えるか、である。稼働中のシステムには、なおレイテンシ、キャッシュ、リトライ、飽和の根拠が必要だ。

その慎重さは弱さではない。チャートを使えるものにしているのは、まさにそれだ。チャートはチームに、いつ容量実験を走らせるべきかを告げる。その実験が何を見つけるかは告げない。

押さえておきたい要点

PAYG と PTU は別々の問いに答える。PAYG は、完了した各リクエストにいくらかかるかを問う。PTU は、許容できる品質とレイテンシのもとで、固定容量が何を運べるかを問う。クロスオーバーの線はその二つの世界をつなぐが、それらを一つの計測へと畳み込みはしない。

だからこのプロジェクトでは、その線をモデル化された仮説として明示する。線は計測されたチャートの上ではなく、その傍らに属するものだ。

出典と根拠の境界

上記の損益分岐の数値はいずれも測定ではなく計算である。測定されたリクエストあたりのコストとトークン形状を、二つの日付付き価格スナップショットに当てて算出している。下の二つの Tier は、文書化された入力がどこで終わり、モデル化された出力がどこから始まるのかを示す。50 PTU の下限を置いた 149 rpm のクロスオーバーは導出された計算であって、測定されたスループットでも、429 の発生でも、飽和点でもない。

  • Tier 1 — 方法論の契約： 本リポジトリ、docs/05-methodology.md（v1.0）。セルあたり N = 20 のオーサリング済みサンプル、R = 3 回の反復、公開集計スライスのみ。リクエストあたりのコスト入力はこの凍結された前提を引き継ぎ、誤差バーは信頼区間ではなく標準偏差で、N = 20 で p 値は主張しない。
  • Tier 1 — PAYG 価格スナップショット： 本リポジトリ、pricing/azure-openai-payg-2026-05.yaml。出典：Azure OpenAI 価格ページ（2026-05-19 アクセス）· アーカイブ。ここでの 1M トークンあたりの単価（gpt-5.2 input $1.75/1M、cached input $0.175/1M、output と reasoning $14.00/1M、gpt-4o input $2.50/1M、cached $1.25/1M、output $10.00/1M）が、式に入るリクエストあたりの請求を決める。
  • Tier 1 — PTU 価格スナップショット： 本リポジトリ、pricing/azure-openai-ptu-2026-05.yaml。出典：Microsoft Learn ドキュメント（2026-05-19 アクセス、リージョン eastus2）· アーカイブ。式の PTU 側——PTU 時間あたり $2.00、50 PTU の最小値（下限）、スループット係数に使う PTU あたり Input TPM（gpt-4o 2,500、gpt-5.2 3,400）——はこのスナップショットによる。PAYG と PTU の両方の価格が損益分岐に入る。一方にリクエストあたりの PAYG 請求、もう一方に固定の $100/hour の PTU 下限（50 × $2.00）。
  • Tier 2 — 測定されたリクエストあたりの入力： 本リポジトリ、benchmarks/01-short-factual/analysis.json、benchmarks/02-multi-step-reasoning/analysis.json、benchmarks/03-tool-using-agent/analysis.json。これらがリクエストあたりの平均コストと、gpt-4o ベースラインに対するスループット利得係数になるセルごとのトークン分布を供給する。
  • Tier 2 — モデル化されたクロスオーバーの出力（測定ではなく計算）： 本リポジトリ、docs/blog/data/chart-data/ptu-payg-crossover/benchmark-01/crossover.json、benchmark-02/crossover.json、benchmark-03/crossover.json。チャートが描く modeled_break_even_rpm の系列は (min_ptu × ptu_hourly_rate ÷ (60 × mean_usd_per_request)) × throughput_gain_factor で計算する。benchmark-01 extra-high の 149 rpm、50 PTU の下限、PTU 時間あたり $2.00 は、いずれも計算または引用された入力であり、測定されたスループットではなくモデル化された値であると明示する。
  • エビデンスダッシュボード： レンダリングされた PTU/PAYG クロスオーバーチャート群は、同じ JSON アーティファクトを監査できる形である。

このスライスが何を証明し、何を証明しないか：このモデル化された損益分岐が、この価格スナップショットで、benchmark-01・-02・-03 の測定されたトークン分布を持つワークロードについて、どこに位置するかを示す。別の価格スナップショット、別のワークロードの形、キャッシュヒット率、推論の構成、別のデプロイリージョンでクロスオーバーが成り立つことは証明しない。これはプランニングの補助であって、SLA でも、稼働中の容量についての言明でもない。

この根拠から言えること

クロスオーバーが価値を持つのは、それが謙虚にとどまるときだ。根拠をプランニングの問いに変え、稼働中の容量は稼働中の計測に委ねる。

実務上のルール

  1. 損益分岐の RPM は、日付付きの PAYG と PTU のスナップショットから導いた価格だけの計算として扱い、どちらかのスナップショットが動いたら導出し直してください。
  2. 汎用のワークロードではなく、計画しているスライスの測定されたトークン形状に合わせてください。
  3. 低いクロスオーバーは、デプロイに PTU が必要だという証明ではなく、容量実験を走らせるきっかけとして使ってください。
  4. PTU を確定する前に、チャートには見えない非価格要因——レイテンシ目標、アドミッションの同時実行数、バースト耐性——を検討してください。

実務上のルール：クロスオーバーが示すのは、このスナップショットとトークン形状における価格だけの損益分岐にすぎない。PTU か PAYG かは、それがモデル化できない非価格要因——レイテンシ、アドミッション、バースト——と対にして判断してください。
