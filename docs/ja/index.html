同じトークン単価、異なる請求額

あるチームがワークロードを推論モデルへ移すと、トークン単価は以前と 変わらないのに、見慣れない調整値が一つ増えていることに気づく。推論強度だ。 これを上げるのはほぼ無料に見える。ならば全体で最大にして、より良い答えを 取りにいけばよさそうに思える。しかし、見える出力はほとんど変わらないまま 請求額だけが上がる。原因は隠れた「思考」トークンである。推論モデルはこの トークンを生成して課金するが、応答には決して出さない。本プロジェクトでは、 代表的な小規模タスク群を対象に、その追加トークンがいつ費用に見合い、いつ 請求額だけを膨らませるのかを測定する。

チームが気にする理由

モデル移行のあと、エンジニアに届く問いは率直だ。なぜコストが動いたのか。 なぜレイテンシが変わったのか。なぜスロットリングが増えたのか。推論強度は この 3 つすべての下にある。既定値を高くしておくと、読者には決して届かない 内部計算にトークンを静かに使う。従量課金では実費になり、プロビジョニング 容量では貴重な余力を削る。強度が実際に回答を変える地点を知っているかどうかが、 自信を持ったロールアウトと、請求書を見てから慌てる展開を分ける。

何を測定したか

プロンプトとワークロードの区分は固定したまま、短い事実回答、構造化 データの自然言語変換、多段階推論、ツールを使うエージェントという各 区分に、同じ推論強度の段階を順に適用しました。そしてすべての呼び出し で、入力・キャッシュ・推論・出力トークンに加え、品質シグナルと レイテンシまで含めて使用量の内訳を記録した。この実測した トークン構成をもとに、同じワークロードが従量課金（PAYG）とプロビジョ ニングされたスループット（PTU）でそれぞれどう課金されるかをモデル化 して比較しました。

根拠から見えたこと

結果は、良い根拠らしく割れた。ある区分では強度が費用に見合い、別の区分では 隠れた計算費用だけが積み上がった。4 つの教訓は、区分全体に共通する。

推論トークンは必ず測定する

課金されるのに応答には返されません。すべての呼び出しで、入力・ キャッシュ・推論・出力に分けた使用量の内訳を記録する。

すべてのタスクに推論が必要なわけではない

短い事実回答、構造化データから自然言語への変換、単純な分類では、 品質が伴って上がらないままコストだけが増える場合が多くありました。

推論強度が主要なコストレバー

推論強度のつまみはまず最も低いレベルを既定とし、品質評価で支出を 正当化できる場合にだけ引き上げる。

課金モデルによって効果が変わる

従量課金（PAYG）では、推論トークンを削減すると請求額が下がる。 プロビジョニングされたスループット（PTU）では、同じ削減が固定請求額 のままスループット向上として現れる。

対象読者

Azure OpenAI デプロイを運用し、推論を有効にするかどうか（そしてどの 程度）を判断したり、容量を見積もったり、モデル移行後のコスト・レイテンシ・ スロットリングの変化をデバッグしたりするエンジニアとアーキテクト向けである。

製品ではなく研究成果物である。 ホスティングされた サービスも SLA もありません。本リポジトリは、再現可能なベンチマーク、 方法論、意思決定ツール、サニタイズ済みの結果の抜粋のみを公開する。

PTU
プロビジョニングされたスループット単位：トークン単位ではなく スループットに対して支払う予約済み固定容量の課金。
PAYG
従量課金：入力・キャッシュ・推論・出力の各トークンごとに 課金される消費ベースの課金。
推論トークン
推論モデルが生成し課金されるが、応答には返されない内部の 「思考」トークン。
キャッシュ
プロンプトキャッシュ：以前に処理されたプロンプトの接頭部を 再利用し、低いキャッシュ入力単価で課金される。
429
