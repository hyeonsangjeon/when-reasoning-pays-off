वही token price, अलग bill

कोई टीम workload को reasoning model पर ले जाती है। per-token price पहले जैसा ही दिखता है, लेकिन एक नई setting सामने आती है: reasoning effort। उसे बढ़ाना लगभग मुफ़्त-सा लगता है। फिर हर जगह इसे ऊपर कर बेहतर जवाब क्यों न लिया जाए? पर visible output लगभग वैसा ही रहता है और bill फिर भी चढ़ जाता है। वजह छिपे हुए "सोच" tokens हैं: reasoning model इन्हें बनाता है और इन पर charge करता है, पर response में कभी नहीं दिखाता। यह project representative tasks के छोटे set पर मापता है कि ये extra tokens कब लागत वसूल करते हैं और कब सिर्फ़ bill बढ़ाते हैं।

यहाँ से शुरू करें लेख-केंद्र अवलोकन निबंध साक्ष्य डैशबोर्ड GitHub

टीमें इसकी परवाह क्यों करती हैं

मॉडल माइग्रेशन के बाद इंजीनियर से सवाल सीधे पूछे जाते हैं: लागत क्यों बदली, लेटेंसी क्यों बदली, थ्रॉटलिंग क्यों बढ़ी? reasoning effort इन तीनों के नीचे बैठा है। default ऊँचा छोड़ दें तो tokens चुपचाप उस internal computation पर खर्च होते हैं जो reader तक कभी नहीं पहुँचती: PAYG में असली पैसा, और PTU में कीमती capacity headroom। effort कहाँ सच में जवाब बदलता है, यह जानना भरोसेमंद rollout और अचानक आए bill के बीच का फर्क है।

हमने क्या परखा

हमने prompts और workload slices स्थिर रखे, फिर हर slice पर reasoning-effort के स्तरों का वही क्रम चलाया: छोटे factual answers, structured data से natural language synthesis, multi-step reasoning, और tools इस्तेमाल करने वाले agents। हर call पर पूरा usage breakdown दर्ज किया: input, cached, reasoning और output tokens, साथ में quality signal और latency। इस measured token shape के ऊपर हमने modeled view जोड़ा कि वही workload pay-as-you-go (PAYG) बनाम provisioned throughput (PTU) में कैसे priced होगा।

साक्ष्य ने क्या दिखाया

नतीजे वैसे ही बँटे जैसे भरोसेमंद evidence बँटता है: कुछ जगह effort ने अपनी लागत वसूल की, और कुछ जगह उसने सिर्फ़ hidden computation की लागत बढ़ाई। चार बातें हर slice पर लागू होती हैं।

reasoning tokens हमेशा मापें

इन पर शुल्क लगता है पर ये लौटाए नहीं जाते। हर call पर पूरा usage breakdown दर्ज करें: input, cache, reasoning और output।

हर task को reasoning की ज़रूरत नहीं

छोटे तथ्यात्मक उत्तर, संरचित डेटा से प्राकृतिक भाषा में रूपांतरण, और सरल वर्गीकरण में अक्सर लागत बढ़ी पर उसके साथ गुणवत्ता नहीं बढ़ी।

एफर्ट प्रमुख लागत-नियंत्रक है

reasoning-effort knob को default रूप से सबसे निचले स्तर पर रखें और तभी बढ़ाएँ जब गुणवत्ता मूल्यांकन इस खर्च को उचित ठहराए।

बिलिंग मॉडल फ़ायदे को बदल देता है

पे-ऐज़-यू-गो (PAYG) पर, reasoning tokens घटाने से bill कम होता है। प्रोविज़ंड थ्रूपुट (PTU) पर, वही कटौती निश्चित बिल पर थ्रूपुट लाभ बन जाती है।

यह किसके लिए है

उन इंजीनियरों और आर्किटेक्ट्स के लिए जो Azure OpenAI deployment चलाते हैं और यह तय कर रहे हैं कि reasoning enable करें या नहीं (और कितनी), क्षमता का आकलन कर रहे हैं, या मॉडल माइग्रेशन के बाद लागत, लेटेंसी या थ्रॉटलिंग में बदलाव डीबग कर रहे हैं।

यह कोई उत्पाद नहीं, शोध सामग्री है। कोई होस्टेड सेवा नहीं है और कोई SLA नहीं। यह repository केवल reproducible benchmarks, methodology, decision tools और sanitized result slices प्रकाशित करती है।

शब्दावली

Foundry
Azure AI Foundry: इस project में मापे गए model को deploy और सर्व करने वाला प्रबंधित प्लेटफ़ॉर्म।
PTU
Provisioned Throughput Units: tokens के बजाय throughput के लिए payment वाली आरक्षित, निश्चित-क्षमता बिलिंग।
PAYG
Pay-as-you-go: input, cache, reasoning और output tokens के अनुसार लिया जाने वाला उपयोग-आधारित बिलिंग।
reasoning tokens
internal "सोच" tokens जिन्हें reasoning model बनाता और bill करता है पर प्रतिक्रिया में कभी नहीं लौटाता।
कैश
Prompt cache: पहले process किए गए prompt prefixes का reuse, कम कैश-इनपुट दर पर बिल किया जाता है।
429
HTTP 429 Too Many Requests: जब कोई deployment अपनी rate या क्षमता सीमा पार करता है तब लौटाई जाने वाली थ्रॉटलिंग प्रतिक्रिया।
